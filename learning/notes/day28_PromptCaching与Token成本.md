# day28 Prompt Caching 与 Token 成本

> 承接 day27 的"值不值得换决策模型"，实际测算 Agent 每轮对话的 token 成本。
> 核心结论：**"生成文字指令"只花几十 token，真正的大头是 system + 工具清单（约 5,650 token），这靠 Prompt Caching 省，不靠换模型。**

## 一、实测：我的 Agent 每轮 token 账（iaa-analytics-agent/src/agent.py）

| 部分 | 字符数 | 折算 token |
|---|---|---|
| SYSTEM_PROMPT | 1,379 字符 | ~1,650 |
| TOOLS_DEFINITION（9 个工具） | 8,007 字符 | ~4,000 |
| 快照 snapshot | ~3,000 字符 | ~2,000 |
| **首轮输入合计** | — | **~7,500 token** |

**关键发现**：system + 工具清单 = 5,650 token，占首轮输入 **~75%**。真正吃 token 的是"工具说明书"，不是"生成文字指令"（那才几十 token）。

多轮循环会滚雪球：每查一次工具，历史全部重发，`max_rounds=8` 时累计 1.5 万 ~ 3 万 token。

## 二、两种"缓存"，别混

| | 多轮对话记忆 | Prompt Caching |
|---|---|---|
| 缓存什么 | 多轮历史记录 | 单次请求的固定前缀 |
| 触发条件 | 手动 append 历史 | 前缀一字不差 |
| 谁在管 | 你（代码） | 平台服务端 |

**误区澄清**：跟我聊天"前面聊过的不会重算"是错的——每轮都把全部历史重新发送、重新计算。这是"历史重发"，不是缓存。

## 三、Prompt Caching 是什么

**平台把"重复出现的那段提示"算过一次就存起来，下次同样的开头直接复用，省钱提速。**

原理：LLM 从左往右算 token，算后面依赖前面的中间结果（KV cache）。两段开头一样 → 开头结果可共享。

### 命中条件（三条）
1. 位置在最前（缓存的是"前缀"）
2. 内容一字不差（差一个空格都作废）
3. 能重复出现

### 命中/未命中示例
```
请求1：[A][B][问题1]
请求2：[A][B][问题2]      ✅ 命中 A+B
请求3：[A][B打错一字][..]  ❌ 从打错字起全作废
请求4：[问题][A][B]       ❌ A、B 不在最前面
```

### 各平台机制
| 平台 | 机制 |
|---|---|
| DeepSeek | 自动缓存，前缀稳定即命中，约 1/10 价 |
| OpenAI | 自动缓存（1k token 以上），部分模型 5 折 |
| Anthropic | 手动 `cache_control` 标记，写贵 25% 读便宜 90% |

## 四、"固定在前"到底是什么意思

messages 是列表，LLM 从第 1 条往下读。"最前面"= 列表开头第 1、2 条。

```python
messages = [
    {"role": "system", "content": SYSTEM_PROMPT},  # 第1条 固定
    {"role": "system", "content": tools_str},      # 第2条 固定（缓存命中点）
    {"role": "user", "content": snapshot},         # 会变，放后面
    {"role": "user", "content": user_query},       # 会变
]
```

**红线**：system prompt 和工具清单必须是"写死的常量"，不能拼动态变量（日期、top_n 数字、快照），否则前缀每天变、缓存失效。

## 五、用户问题可以固定吗？

可以。定时自动化场景，分析目标每天一样，可写死：
```python
FIXED_QUERY = "请分析今天各渠道 D7 ROI，找出低于 0.7 的广告组并给优化建议"
```
但**固定问题不是为了省 token**（一句才 20 token），而是为了实现无人值守自动化。且快照挡在问题前面，问题本身缓存不了。

## 六、省 token 的正确姿势（不是换模型）

按性价比排序：
1. **固定前缀放最前** → 触发 DeepSeek 自动缓存那 5,650 token（零成本，最重要）
2. **精简工具描述** → 9 个工具砍 1,500~2,000 token（约束交给 enum/required）
3. **快照做 mtime 指纹缓存** → 数据没变不重复序列化
4. **真到高并发**才抽"意图路由"给小分类器

## 一句话总结

"生成文字指令"只花几十 token，不值得为它换决策模型。真正大头是 5,650 token 的 system+工具清单，靠"固定前缀放最前触发 Prompt Caching"省，这是工程优化，不是换模型。
