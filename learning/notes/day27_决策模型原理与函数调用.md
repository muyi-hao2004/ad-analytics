# day27 决策模型原理与函数调用

> 承接 day24/25（神经网络、训练），讲 LLM 的两种用法：生成 vs 决策。
> 核心结论：**"选函数"是决策问题，不是生成问题**；决策模型省的是"逐字生成"，但候选集才是决策质量的上限。

## 一、两种用法：生成 vs 决策

同一个预训练 Transformer 底座，区别只在最后一层怎么用：

| | 生成模型（Generative） | 决策模型（打分/分类） |
|---|---|---|
| 干什么 | 逐 token 生成文字 | 给候选打分/排序/选一个 |
| 输出 | 一段话 | 概率分布 / 分数 |
| 本质 | 自回归采样 | 分类 / 排序 |
| 特点 | 慢、贵、可能幻觉 | 快、省、更可控 |

## 二、三个关键数学机制

1. **自回归概率链（生成侧）**
   ```
   P(w1,...,wT) = Π P(wt | w1...wt-1)
   ```
   生成 = 一步步从条件概率采样。

2. **分类打分（决策侧）**
   ```
   P(选项_i) = e^{z_i} / Σ e^{z_j}   （softmax）
   然后 argmax 选最大的 → 做决策
   ```

3. **偏好对齐训练（让它"选得对"）**
   - 光预训练只会"补全"，不会"选对"。
   - **RLHF**：人类给回答排序 → 训练奖励模型 r(x) → 主模型最大化奖励。
   - **DPO**：跳过奖励模型，直接拿"好/坏"对比样本调模型。

## 三、与已有知识的连接

- 我论文里的 **XGBoost 二分类**（破产预测）本质就是"决策模型"：输入特征 → 输出概率 → 选阈值。
- 区别：XGBoost 输入是结构化财务比率；LLM 决策模型输入是文本隐向量。
- **softmax 回归**是决策侧最基础形态；**logistic 回归**是二分类特例。
- "损失函数（量错的尺子）"在 RLHF 里 = 交叉熵 / pairwise ranking loss。

## 四、决策模型 + 函数调用（核心洞察）

**函数调用本质是"决策"问题，不是"生成"问题。**

| | 生成模型直接调函数 | 决策模型选函数 |
|---|---|---|
| 怎么决定调哪个 | 生成函数名+参数 JSON，可能拼错 | 从注册列表里打分选 |
| 可靠性 | 参数幻觉、函数名拼错 | 候选=白名单，不会选到不存在的 |
| 可控性 | 弱，靠 prompt 约束 | 强，候选集=白名单 |

### 完整闭环
```
用户意图
  → [决策①] 意图分类（查数据/闲聊/操作）
  → [决策②] 工具选择（N 个函数里打分选 Top-1）
  → 执行函数（真实查库/调 API/写文件）
  → 返回结构化结果 → [可选] 生成模型润色成人话
```

**分工**：决策（选工具、填参数）→ 决策模型；表达（结果说成人话）→ 生成模型。

## 五、值不值得换成"独立小决策模型"

先纠正前提：**现在没有"独立决策模型"让你随便换**。同一个 GPT 就是通过 Function Calling 决策，不是二选一。

真实成本对比：

| 方案 | 实际是什么 |
|---|---|
| 文字下指令（无工具） | LLM 生成废话，你人工解析 |
| Function Calling | 同一个 LLM，只输出短 JSON |
| 真·独立决策模型 | 小专用分类器（BERT/小模型），一次前向 |

**判断标准：候选集能不能预先枚举**

> 候选集有限、固定 → 用小决策模型（延迟降 10 倍、成本降 100 倍），值得。
> 候选集开放、多变 → 用大模型 + Function Calling，别省这个 token。

比喻：大模型=全科医生，小决策模型=分诊台护士。

## 六、不接 RAG，决策模型能对吗？

**不接 RAG，只是省了生成文字，没变聪明。** 决策依据只有：
1. 预训练权重里的通用知识（可能错/过期）
2. 你喂的 prompt + 候选选项

**模型上限由输入信息决定，不由模型结构决定**（同 XGBoost：垃圾特征 → AUC 上不去）。

完整形态必须是：
```
行业知识（RAG/规则/DB）→ 生成候选集 → 决策模型打分 → 选 Top-1
```

## 一句话总结

决策模型 = 预训练 Transformer + 分类头 + 偏好对齐训练，把"逐字生成"换成"一次前向算分数"，所以更快更省；但要外部先给候选，候选集才是决策质量的上限。"选函数"天然是决策问题，所以函数调用用决策模型最合适。
