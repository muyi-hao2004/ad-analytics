### A. Hadoop 生态全景 + HDFS 目录/分区机制

**出处**：10-16 17:53 ~ 18:14（约 20 分钟，一整段连续讲解）

原始提问：

- 18:06 / 18:07 `跟datanode有什么关系吗`（问了两次）
- 18:09 `看不懂`
- 18:11 `那不是还是datanode的目录存的方式更好，后面查的也更好吗`
- 18:14 `这个分区是在一个电脑里分吗`

**笔记缺口**（`12_分布式存储HDFS与Parquet.md` 只写到"切块 128MB + 3 副本 + NameNode/DataNode"就停了）：

| 缺失知识点 | 为什么重要 |
|---|---|
| **Hive 到底是什么** | 它不是数据库，是「把 SQL 翻译成 MapReduce/Spark 任务的翻译官」；元数据存 MySQL，数据存 HDFS。这是面试区分"用过 Hive"和"懂 Hive"的分水岭 |
| **YARN** | 资源调度器，管"哪台机器有空跑任务"。Hadoop 三件套之一，笔记完全没有 |
| **MapReduce** | 批处理计算模型（Map → Shuffle → Reduce），YARN 上跑的东西。笔记完全没有 |
| **四者的关系** | HDFS 存 / YARN 调度 / MapReduce 算 / Hive 提供 SQL 层 —— 一张图能讲清，但笔记没有这张图 |
| **HDFS 目录结构** | `/user/hive/warehouse/库名.db/表名/分区名/` —— 这是"为什么分区能加速查询"的物理原因 |
| **分区 = 目录（物理层）** | 你当时问的"分区是在一个电脑里分吗"，答案正是：**分区是逻辑上的目录切分，物理上仍散落在多个 DataNode**。这一层抽象没写进笔记 |
| **分区 vs 分桶** | 分区是目录级切分（粗粒度），分桶是文件内哈希切分（细粒度）。笔记里连"分桶"两个字都没有 |
| **谓词下推** | 笔记里提到过（在数仓建模笔记里），但没和"分区目录"串起来 |

> 建议单独成篇：`day30_Hadoop生态与Hive原理.md`

### C. Agent 代码审查结论（10-19 11:47）

对 `iaa-analytics-agent/src/agent.py`（994 行）的完整审查，结论是 P0/P1/P2 三级：

- **P0-1**：未用原生 Function Calling，而是把工具定义塞进 prompt 再自己解析 JSON；工具结果用 `role=user` 回传（应为 `role=tool`）
- **P0-2**：`df["_rev"] = df["spend"] * df["d7_roi"]` —— 加权 ROI 用"当天花费 × D7 回报率"，口径错配，应改 `sum(drev)/sum(spend)`
- **P1**：日志用子串匹配会误配（`ch_003` 命中 `ch_0031`）；写操作执行前无二次核对；工具调用无去重缓存
- **P2**：`max_rounds` 耗尽无降级总结；知识库检索无相似度阈值

> 这份内容**不一定要进笔记**，但它决定了你项目"能不能讲清楚"。建议放到 `iaa-analytics-agent/CODE_REVIEW.md`。
