# Day7：pandas与SQL的选择 + Python面向对象

## 一、pandas vs SQL：什么时候用哪个？

### 核心区别
- **pandas**：在**内存**里操作 DataFrame，像计算器+草稿纸，算得快但纸有限
- **SQL**：在**数据库（硬盘）**里操作表，像图书馆查询系统，书再多也能快速找到

### pandas 擅长（5个场景）
1. **数据清洗**（最擅长）：缺失值填充、异常值处理、类型转换、去重、字段名标准化
2. **复杂数据转换**：透视表(pivot)、长宽表转换(melt)、apply自定义函数、多列计算衍生指标
3. **小数据量灵活探索**：几万几十万行，改来改去很方便
4. **和Python生态集成**：可视化(matplotlib)、机器学习(sklearn)、大模型(LangChain)
5. **读写各种格式文件**：CSV、Excel、JSON、Parquet、数据库

### pandas 不擅长（4个场景）
1. **大数据量**（致命弱点）：全部读进内存，几百万行可能内存溢出
2. **多表关联(JOIN)**：merge慢、占内存、多表JOIN写起来麻烦
3. **复杂窗口函数/子查询**：写起来绕，多层子查询要拆很多步
4. **持久化存储/多人共享/并发访问**：数据在内存里，程序一关就没了

### SQL 擅长（5个场景）
1. **大数据量查询**（最擅长）：有索引优化，几亿条也能秒查
2. **多表关联(JOIN)**：数据库看家本领，3-10张表关联都轻松
3. **复杂查询**：窗口函数、子查询、CTE(WITH语句)，写起来清晰
4. **持久化存储**：数据存在硬盘，关机不丢
5. **多人共享/并发访问/权限管理**：多个同事同时查，互不影响

### SQL 不擅长（3个场景）
1. **复杂数据清洗**：自定义清洗逻辑写起来麻烦，调试不方便
2. **灵活探索性分析**：频繁改查询不如pandas方便
3. **可视化/机器学习**：得导出来用其他工具

### 决策流程
```
第1步：数据量多大？
  ├─ 小（<100万行）→ 可以考虑 pandas
  └─ 大（>100万行）→ 优先用 SQL

第2步：做什么操作？
  ├─ 清洗/复杂转换/探索/可视化/机器学习 → 用 pandas
  ├─ 多表关联/复杂窗口函数/大数据查询/持久化 → 用 SQL
  └─ 建库建表/权限管理 → 必须用 SQL
```

### 实际工作标准流程（99%场景混合用）
```
1. 原始数据存在数据库（大数据量）
2. 用SQL初步筛选聚合（几千万行→几万行）
3. 结果读进pandas，做精细清洗/转换/探索
4. pandas+matplotlib可视化，或+sklearn建模
5. 分析结果存回数据库或导出报表
```

> **一句话：SQL负责搬数据/筛数据/聚合（重活），pandas负责精细加工/分析/可视化（细活）。**

## 二、Python面向对象

### 基础概念
- **面向过程**：一步一步做事情，关注"怎么做"（函数+顺序执行）
- **面向对象**：把数据和功能打包成对象，关注"谁来做"（类+对象）
- **类（Class）**：模板/设计图，定义一类事物共同的属性和方法
- **对象/实例（Object/Instance）**：根据类造出来的具体东西，一个类可以造很多个对象
- **属性**：对象的数据（变量），`self.属性名`，调用时不加括号
- **方法**：对象的功能（函数），`def 方法名(self):`，调用时加括号
- **`__init__`**：构造方法，创建对象时自动调用，设置初始属性
- **`self`**：对象自己，调用方法时Python自动传，第一个参数必须是self

### 进阶概念
- **继承**：子类继承父类的所有属性和方法，代码复用。`class 子类(父类):`
  - `super()`：调用父类的方法，`super().__init__(参数)`
  - **重写**：子类方法名和父类一样，覆盖父类方法
  - ORM核心：`AdData(Base)` 继承SQLAlchemy的Base父类，自动拥有对象↔数据库映射能力
- **封装**：隐藏内部细节，只对外提供接口
  - 私有属性：`__属性名`（双下划线开头），外部不能直接访问
  - 私有方法：`__方法名`，外部不能直接调用
  - 好处：保护数据、加校验、隐藏实现、方便修改
- **类属性 vs 实例属性**
  - 类属性：定义在类下面，所有对象共享，`属性名 = 值`
  - 实例属性：定义在`__init__`里，每个对象独有，`self.属性名 = 值`
- **三种方法**
  - 实例方法：最常用，第一个参数`self`，能访问实例属性和类属性
  - 类方法：`@classmethod`装饰，第一个参数`cls`，只能访问类属性，通过类名调用
  - 静态方法：`@staticmethod`装饰，没有self/cls，像普通函数放在类里
- **魔术方法**：前后双下划线，特定情况自动调用
  - `__init__`：创建对象时调用
  - `__str__`：print对象时显示
  - `__repr__`：调试时显示

## 三、接口（Interface）

### 什么是接口
- 接口就是"外部和内部交互的入口"，外部不用管内部怎么实现，通过接口就能操作
- 面向对象里的接口 = 类对外提供的公开方法（public methods）
- 生活例子：手机的按钮、自动售货机的投币口/按钮、餐厅的菜单

### 具体怎么做
1. 把数据设为私有（`__balance`），外部不能直接访问
2. 提供公开方法作为接口（`deposit()`、`withdraw()`、`get_balance()`）
3. 外部只能通过接口操作，不能直接碰私有属性

### 为什么要提供接口
- **保护数据**：不能随意修改（比如余额不能改成负数）
- **加校验**：在接口内部加校验逻辑（存款必须大于0、余额不足不能取）
- **隐藏实现细节**：外部不用管内部怎么算的（总余额=活期+定期+理财）
- **方便修改**：内部实现变了，接口不变，外部代码不用改

### 项目例子
- `Settings`类的`database_url`就是接口（@property装饰）
- 外部用`settings.database_url`就能得到连接字符串，不用管内部怎么拼接的
- 以后拼接逻辑变了（加SSL参数），外部代码不用改

## 四、装饰器（Decorator）

### 什么是装饰器
- 在不改变原函数代码的前提下，给函数包一层，增加额外功能
- 本质：一个函数，接收另一个函数作为参数，返回包装后的新函数
- 生活例子：手机壳（不改变手机功能，增加防摔/美观）、快递包装

### `@`语法糖
- `@装饰器名` 等价于 `函数名 = 装饰器名(函数名)`
- 先定义函数，然后把函数传给装饰器，返回的新函数重新赋值给原函数名

### 常见用途
- 记录日志、计时、权限校验、缓存、重试、类型检查

### 类里常用的三个装饰器
1. **`@property`**：把方法变成属性，调用时不用加括号
   - 用于不需要传参数、返回计算值的方法
   - 可配合`@属性名.setter`在修改时加校验（封装的优雅实现）
   - 项目例子：`Settings.database_url`，每次访问动态拼接连接字符串
2. **`@classmethod`**：类方法，第一个参数`cls`（代表类），通过类名调用，用于工厂方法/修改类属性
3. **`@staticmethod`**：静态方法，没有self/cls，像普通函数放在类里，用于工具函数

### 自定义装饰器原理
```python
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"执行了{end-start}秒")
        return result
    return wrapper

@timer
def slow_function():
    time.sleep(1)
```
- `timer`接收原函数`func`，返回`wrapper`新函数
- `wrapper`内部：额外功能（计时）+ 调用原函数 + 返回结果
- `*args, **kwargs`接收任意参数，保证装饰器通用
