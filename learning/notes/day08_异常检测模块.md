# Day8：异常检测模块（anomaly\_detection.py）

## 一、什么是异常检测？

从数据中找出 "不正常" 的记录 —— 和大多数数据不一样、偏离正常范围的点。

### 为什么广告投放需要异常检测？

广告投放每天花很多钱，出问题不能及时发现损失会很大：



* 花费突然暴涨 → 预算设置错误、被恶意点击 → 钱白花了

* 点击率突然下降 → 广告素材失效、竞争对手加价 → 流量减少

* 转化率突然下降 → 落地页打不开、支付系统故障 → ROI 暴跌

* CPA 突然升高 → 流量质量下降 → 获客成本超预期

* 零曝光 / 零点击 → 账户被封、计划审核不通过 → 完全没流量

## 二、两种异常检测方法

### 方法 1：统计规则（我们项目先用这个）

根据业务经验设定阈值规则，超过阈值就判定为异常。



* 优点：简单、容易理解、可解释、不需要训练数据

* 缺点：阈值需要人工设定，复杂异常检测不出来

### 方法 2：机器学习（后面再学）

用算法自动学习 "正常模式"，偏离正常模式的就是异常。



* 常用算法：Isolation Forest（孤立森林）、One-Class SVM、Autoencoder

* 优点：自动学习，能检测复杂异常

* 缺点：不容易解释，需要足够数据，调参复杂

## 三、我们检测的 5 种异常



| 异常类型   | 检测规则                   | 严重程度 |
| ------ | ---------------------- | ---- |
| 花费暴涨   | 当天花费 > 前 7 天平均花费 × 1.5 | 高    |
| 点击率过低  | CTR <1%（曝光> 100 才检测）   | 中    |
| 转化率过低  | CVR <1%（点击> 50 才检测）    | 中    |
| CPA 过高 | CPA > 所有记录平均 CPA × 2   | 高    |
| 零曝光    | 曝光量 = 0                | 高    |

每条异常记录包含：日期、渠道、计划名、异常类型、实际值、阈值、严重程度、描述

## 四、anomaly\_detection.py 模块（6 个函数）

### 1. detect\_spend\_surge (df, threshold=1.5) — 花费暴涨检测



* 按渠道和日期分组，计算每天花费

* 对每个渠道单独检测（前 7 天平均是同一个渠道自己的）

* 前 7 天数据不足跳过，历史平均为 0 跳过

* 关键：`groupby(['channel','date'])['cost'].sum().reset_index()`

### 2. detect\_low\_ctr (df, threshold=0.01) — 点击率过低检测



* 按日期 + 渠道 + 计划分组，计算总曝光和总点击

* CTR = clicks /impressions（np.where 除零保护）

* 小样本过滤：曝光 > 100 才检测，避免误报

* 关键：`groupby().agg({'impressions':'sum','clicks':'sum'})` 命名聚合

### 3. detect\_low\_cvr (df, threshold=0.01) — 转化率过低检测



* 和 detect\_low\_ctr 几乎一样，指标换成 CVR = conversions /clicks

* 小样本过滤：点击 > 50 才检测

### 4. detect\_high\_cpa (df, threshold\_multiplier=2.0) — CPA 过高检测



* 按日期 + 渠道 + 计划分组，计算总花费和总转化

* CPA = cost /conversions（无转化时设为 np.inf 无穷大）

* 只统计有转化的记录算平均 CPA（无转化的 CPA 是无穷大，会拉高平均）

* 阈值 = 平均 CPA × 2

### 5. detect\_zero\_impressions (df) — 零曝光检测



* 最简单：直接筛选 impressions == 0 的记录

* 注意：清洗模块已删除零曝光记录，此函数应在清洗前的原始数据上用

### 6. detect\_all\_anomalies (df, config=None) — 执行所有检测，合并结果



* 依次调用 5 个检测函数，结果放进列表

* `pd.concat(列表, ignore_index=True)` 合并所有异常

* 按严重程度排序（高 > 中 > 低）：用.map () 把文字转成数字排序，排序后删掉临时列

* 支持自定义阈值：config.get ('key', 默认值)

## 五、关键语法知识点

### 1. np.where (条件，真值，假值) — 条件计算 + 除零保护



```
grouped\['ctr'] = np.where(grouped\['impressions'] > 0,

&#x20;                          grouped\['clicks'] / grouped\['impressions'],

&#x20;                          0)
```



* 条件为真用第一个值，为假用第二个值

* 避免除零错误（曝光为 0 时 CTR 设为 0 而不是报错）

### 2. groupby ().agg ({列名：聚合函数}) — 命名聚合



```
grouped = df.groupby(\['date','channel','campaign']).agg({

&#x20;   'impressions': 'sum',

&#x20;   'clicks': 'sum'

}).reset\_index()
```



* 字典的 key 是列名，value 是聚合函数

* 可以同时对多列做不同的聚合

### 3. pd.concat (列表，ignore\_index=True) — 合并多个 DataFrame



```
all\_anomalies = pd.concat(anomaly\_list, ignore\_index=True)
```



* 按行合并（上下拼接）

* ignore\_index=True：合并后重新生成索引，避免索引重复

### 4. .map (字典) — 按字典映射值



```
severity\_order = {'高': 0, '中': 1, '低': 2}

all\_anomalies\['severity\_order'] = all\_anomalies\['severity'].map(severity\_order)
```



* 把列的每个值按字典映射成新值

* 常用于把文字分类转成数字排序

### 5. 小样本过滤 — 避免误报



* CTR 检测要求曝光 > 100（曝光太少 CTR 波动大，可能是偶然）

* CVR 检测要求点击 > 50

* 这是数据分析的常见做法：样本量足够才有统计意义

### 6. pandas 多条件筛选



```
low\_ctr = grouped\[(grouped\['ctr'] < threshold) & (grouped\['impressions'] > 100)]
```



* `&` 是 "且"（pandas 里用 & 不是 and）

* 每个条件必须加括号

* `|` 是 "或"

## 七、从 "看懂代码" 到 "写出代码" 的练习方法

### 为什么看懂了但写不出来？

"看懂" 和 "写出" 是两个完全不同的能力，差了 100 倍练习量：



* 看懂代码 ⭐⭐

* 修改代码 ⭐⭐⭐

* 调试代码 ⭐⭐⭐⭐

* 从零写出 ⭐⭐⭐⭐⭐

### 4 个阶段的练习方法

#### 阶段 1：仿写（看着写）



1. 看着代码手打抄一遍（不要复制粘贴）

2. 每一行想 "这一行在干什么"

3. 运行确认能跑通

4. 删掉，不看代码自己再写一遍

5. 写不出来就看一眼，继续写

#### 阶段 2：改写（改着玩）

拿能跑通的函数改逻辑：



* 改阈值、改参数

* 加新的异常类型

* 改分组维度

* 加新功能

#### 阶段 3：拆解（把大函数拆成小函数）

面对复杂需求，拆成小步骤：



1. 第一步：分组计算 → 写一步，打印确认

2. 第二步：排序 → 加一步，打印确认

3. 第三步：计算历史平均 → 加一步

4. 第四步：比较阈值 → 加一步

5. 第五步：组装结果 → 加一步

   每写完一步就运行验证，不要一口气写完再调试。

#### 阶段 4：默写（不看写）



1. 看需求和思路（不看具体代码）

2. 合上资料自己从零写

3. 写不出来就想 "怎么拆的？第一步是什么？"

4. 写完和原代码对比

### 练习计划（4 周）



* 第 1 周：仿写 6 个函数，从最简单的开始，每天 1 个

* 第 2 周：改写 + 加功能，给每个函数加新参数 / 新异常类型

* 第 3 周：拆解 + 从零写，给新需求自己拆步骤写

* 第 4 周：综合练习，自己设计小模块

### 重要心态

实际工作中 90% 的代码不是从零写的，而是：



* 参考已有代码，复制过来改一改

* 参考官方文档 / 示例，改参数

* 问 AI 助手，生成代码后检查修改调试

* Google/Stack Overflow 找解决方案

真正需要 "从零写" 的很少，能看懂 + 会改 + 会调试就够用了。"从零写出" 随经验增长自然会的，不用急。
