# 渠道质量与假量识别

## 为什么这件事对 IAA 格外重要

IAA 的 LTV 只有几毛钱，**一个渠道的假量就能吃掉整个 campaign 的利润**。
而且低 CPI 的诱惑天然存在：便宜的量往往不干净。所以「CPI 异常低」本身就该触发排查，
而不是当成好消息。

**判断原则：CPI 低于行业均价 50% 以上，大概率不是捡漏，是踩坑。**

## 六个可查的信号（任意三个同时亮红灯，基本可判定有问题）

| # | 信号 | 具体表现 |
|---|---|---|
| 1 | 留存曲线异常 | 陡升陡降、出现断层；真实用户应是平滑指数衰减 |
| 2 | D1 留存 > 注册转化率 | 正常应相反。留存高于转化说明注入了虚假用户 |
| 3 | 人均启动次数不衰减 | 真实用户日启动次数自然递减；只启动 1–2 次或反常上升都异常 |
| 4 | 设备指纹重复 | 同一设备 ID 短期反复下载不同应用 → 设备农场 |
| 5 | CTIT 分布错位 | 见下节，这是最有力的技术信号之一 |
| 6 | 自然量异常波动 | 某天自然下载暴涨但次日归零 → 疑似归因劫持洗白 |

### 用口语问法再说一遍前三条

表格是压缩表述，检索时容易漏。这里用实际工作里的说法重述，并补上同义术语：

- **「次留比注册转化率还高，正常吗？」**
  不正常。正常情况下**次日留存（D1 留存、次留）应该低于注册转化率**——
  用户连注册都不愿意，第二天再回来的概率只会更低。如果残存反而高于转化率，
  说明有虚假用户被直接注入到留存口径里。
- **「用户只在安装当天打开一两次就再也不来了，是不是有问题？」**
  看人均启动次数。真实用户的日启动次数随时间自然递减，但不会一开始就只有 1–2 次。
  某渠道用户普遍只启动一两次、且不继续衰减，质量可疑。
- **「留存曲线中间突然跳了一下」**
  真实留存是平滑的指数衰减。出现陡升、断层、或者某一天突然回到高位，
  基本可判定数据被干预过（机刷、积分墙任务）。

## CTIT：最值得学的技术信号

**CTIT = Click-To-Install Time**（点击到安装的时间间隔）。

正常分布：主峰在 **10–30 秒**（Xinstall 数据）。

| 异常模式 | 特征 | 指向 |
|---|---|---|
| 极短 CTIT 高占比 | 大量安装集中在 **0–2 秒** | 点击注入 / 脚本模拟。真实用户 1 秒内完成下载安装几乎不可能批量发生 |
| 极长 CTIT + 极差质量 | 安装拖很久才完成，后续留存差 | 使用旧点击或低质流量，在某个时点集中触发以消耗预算 |
| 分布整体错位 | 主峰在几秒内或几分钟后，与大盘完全不同 | 流量来源异常 |

**风险区间建议（Xinstall）**：0–2 秒 = 高风险，2–5 秒 = 偏高，5–120 秒 = 正常，
超长 = 特殊关注。

**正确的用法不是一刀切拒绝，而是打标签算风险分：**

```
给每次安装打 CTIT_very_short / CTIT_long 等标签
  → 结合留存、付费、行为路径
  → 算综合风险分
  → 高风险的单列统计（对账时作证据），中风险的降低 ROI 计算权重
```

这一点很重要：**假量识别是概率判断，不是二元判断**。
直接按「CTIT < 2 秒就全部剔除」会误杀一部分真实用户（网络快、包体小的情况）。

## 留存曲线的具体判据

| 判据 | 说明 |
|---|---|
| 形态 | 真实留存是平滑指数衰减，不该有剧烈波动或断层 |
| 节点集中 | 部分渠道在 D1 / D7 / D30 等关键节点集中导入虚假用户，表现为曲线在这些点异常 |
| 48 小时归零 | 安装后两天内集体消失，是欺诈流量的典型特征 |
| 长期验证 | 月留存很难造假。新渠道先小规模测，验证后再放量 |

**业内通用「优秀」线（中文投放语境）**：D1 ≥ 40%、D7 ≥ 20%、D30 ≥ 10%。
注意这个标准比英文来源的超休闲基准（D1 27%、D7 8%）高很多——
因为它针对的是工具类/泛应用，不是超休闲游戏。**套用前先确认品类。**

## 反作弊的对抗性（不要指望一劳永逸）

作弊手段在升级，识别手段也在升级：

- 早期：明文 JSON 伪造新增/活跃/留存 → 主流平台已改二进制协议 + 加密
- 现在：分布式人肉刷量（积分墙任务）、脚本改真机参数驱动真实设备（如 iOS 的 igrimace 类工具）
- 这类行为接近真实用户，**技术层面极难识别**，只能靠行为深度与长期数据

**因此**：反作弊是持续博弈，不是一次性配置。手段是「小规模测试 → 验证 → 再放量」，
而不是「上了反作弊 SDK 就放心投」。

## 处理原则（发现异常之后做什么）

1. **不要立刻全量停投**。先降权、缩小预算、单列统计
2. **留证据**：异常安装单独打标，对账时是与媒体交涉的依据
3. **区分「作弊」和「低质」**：低质流量（真实用户但不留存）需要优化定向，
   作弊流量需要停止合作。两者的处置不同
4. **不是所有 bot 流量都是浪费**：品牌曝光类投放对 bot 敏感度低；
   效果类（下载/付费）才需要严格审计

## 判断清单（看到某个子渠道数据时按序检查）

| 顺序 | 检查项 | 若异常 |
|---|---|---|
| 1 | 数据天数够不够（<3 天不下结论） | 等数据 |
| 2 | 安装量够不够（<100 次，ROI 无统计意义） | 等样本 |
| 3 | 留存曲线形态是否平滑 | 断层 → 高度怀疑 |
| 4 | D1 留存 vs 注册转化率 | 留存 > 转化 → 怀疑注入 |
| 5 | CTIT 分布是否与大盘一致 | 0–2 秒占比高 → 怀疑点击注入 |
| 6 | 人均启动次数是否自然递减 | 不衰减 → 质量可疑 |
| 7 | 与同期其他渠道横向对比 | 偏离过大 → 深入查 |

**第 1、2 条最容易犯**：30 次安装、单日数据就判「这个渠道不行」，
结论在统计上不成立。**样本不足时正确动作是「观察」，不是「删除」。**
