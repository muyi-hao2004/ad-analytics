# 待核实项与口径冲突（不要当结论用）

## 为什么单独写一篇

行业数据天生有三个问题：**口径不一致、样本不透明、商业动机**。
同一个指标不同来源能差一倍，如果不加区分地引用，会得出相反的行动结论。

这一篇专门记录「我看到过但不敢当结论」的数字，以及冲突在哪里。
**遇到这里的数字，正确动作是去自己的后台数据核对，而不是直接引用。**

## 冲突一：D7 ROAS 目标到底该多少

| 来源 | 说法 | 问题 |
|---|---|---|
| 本项目原知识库 | D7 ROAS 目标通常 70% | 没写口径、没写品类 |
| Leapwave 2025 | 广告变现 app「D7 40–60%」，同一页后面又写「Day 7: 150–200%」 | **同一篇文章前后矛盾**，不可引用 |
| Adapty 2026 | 超休闲 D7 ROAS 1.0–1.5x（即 100–150%） | 与上一条差一倍 |
| Unity 案例 | 用 **70% D1** ROAS 作目标（Android） | 是 **D1 不是 D7**，且是「优化器设定值」不是「回本线」 |

**冲突的根源是三个概念被混用了：**

```
① 优化器目标值（target ROAS）     ← 给算法设的靶子，可以低于回本线
② 盈亏平衡点（break-even ROAS）   ← 取决于 margin
③ 实际达成值（actual ROAS）       ← 报表上看到的
```

Unity 案例里的 70% 是 ①（给 ironSource ROAS optimizer 设的 D1 目标），
不是「70% 就赚钱」。它之所以设 70%，是因为超休闲要用低目标换规模（官方第一条实践：
「最大化总利润而非单用户利润率」）。

**正确理解**：

- 目标 ROAS 是**投放策略参数**，可以低于 1
- 是否赚钱看 **LTV / CPI**，不是看 ROAS 目标
- **D1 / D7 / D30 必须写清是哪个窗口**，差一个词含义全变

**行动建议**：自己算 break-even。对纯 IAA：
`break-even ROAS = 1 / (1 - 其他成本占比)`，其他成本包括服务器、MMP、素材、人力。
如果其他成本占 40%，break-even 就要 1.67（167%）。

## 冲突二：超休闲 D7 留存

| 来源 | 数值 |
|---|---|
| Adjust《2026 移动应用趋势》 | **8%** |
| SolarEngine（转引） | <8% |
| Hubapps 2026（UA 规划用） | **10–14%** |
| Game Industry Library | D7 常掉到个位数，头部约 15% |

**差异可能来自**：样本市场构成（Adjust 含更多新兴市场）、是否含自然量、
是否按安装日 cohort 还是滚动 DAU。

**行动建议**：判断渠道质量时用**同品类同期大盘**做基准，不要用跨来源的绝对值。
绝对基准只用来判断「是否数量级偏离」。

## 冲突三：美国激励视频 eCPM

| 来源 | 数值 |
|---|---|
| RevolGames 2025 | $8–15 |
| AdReact 2025–26（Tier1 超休闲） | $8–15 |
| TopOn H1 2025（EU+NA 休闲 Android） | $8.90 |
| Yango Ads（美国游戏 Android / iOS） | $16.49 / $19.63 |

**iOS 高于 Android 是共识**，但「$9 还是 $16」差近一倍。
可能原因：是否含高端 iOS 流量、是否统计头部产品、是否含 Q4。

**行动建议**：eCPM 一律取自己后台值。基准只回答一个问题：
「我的 $6 是不是明显偏低」（是 → 查聚合配置/地区结构）。

## 未验证：网赚类（提现/看广告赚钱）游戏的公开基准

本项目场景是「海外 IAA 休闲，纯广告无内购」。搜索**没有找到**针对中文语境
「网赚类」（看广告赚金币/提现）的可靠公开基准数据。

**只能确认的相邻事实**：

- 激励视频是该类产品的收入主体（完成率 70–90%，收入占比 60–80%）
- P2E（play-to-earn）类产品有报告称月收入 $10k–30k 主要来自激励广告（Adexium，2025 末，
  来源为「多个广告网络报告汇总」，**非第一方数据，可信度中**）
- Tier 2/3 市场做纯 IAA 的案例存在（LinkedIn 从业者分享，见下条），但都是个案

**不要做的事**：把「超休闲」的留存基准直接套到「网赚类」上。
网赚类的用户动机是收益而非娱乐，留存曲线形态可能完全不同（受提现周期驱动）。
**这类产品必须用自己 cohort 的数据，没有任何外部基准可替代。**

## 存疑个案：印度 CPI $0.01

LinkedIn 上一个公开案例（2025）声称：

> 街机品类 / 100% 广告 / Android / 月预算 $1 万 / 印度 / CPI $0.01 /
> 100 万安装 / D7 LTV $0.02 / 月利润 $1 万

同帖评论里，印度本地从业者直接反驳：

> 「$0.01 在印度几乎不可能。我试过所有主要渠道，简单游戏的 CPI 都在 $0.03 以上，
> 主流变现伙伴的插屏 eCPM 不超过 $0.4–0.7，激励视频约 $0.8–1.2。」

另一条评论补充了被忽略的成本：这个规模下 Firebase 就要 $1–2k/月，
加起来 MMP、广告网络、分析工具，很容易到 $4–6k/月，**利润减半**。

**判断**：这个案例的「月利润 $1 万」很可能没扣全成本。
**但它有一个可用的结论**：低 CPI 市场 + 纯 IAA + 多国并行，在特定条件下能跑通现金流。
把它当「方向参考」，不要当「参数参考」。

## 引用这些数据的三条规则

1. **每个数字必须能说出：来源 + 时间 + 口径（哪个窗口、什么品类、什么地区）**
   说不全的，当「量级参考」用，不当「判断依据」用
2. **交叉验证**：一个数字只有一个来源支持时，标注「单一来源」
3. **优先相信自己的后台**：外部基准用来发现「显著偏离」，
   不能用来证明「我的数据是对的」

## 一个反例：为什么这条规则有用

如果按 Leapwave 那篇文章的「广告变现 app D7 应达 150–200%」去设目标，
纯 IAA 休闲游戏会永远不达标——因为它的 D30 ROAS 通常只有 15%–47%（Liftoff 实测）。
按那个标准，所有正常产品都会被判为失败，进而做出「砍掉所有渠道」的错误决策。

**错误的数据比没有数据更危险**，因为它会导向确定的错误动作。
