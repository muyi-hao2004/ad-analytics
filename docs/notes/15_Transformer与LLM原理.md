# Transformer 与 LLM 原理

本篇覆盖：Transformer 要解决的 RNN 瓶颈；Attention 的直觉与 Q/K/V 的数学形式、缩放点积与 `sqrt(d_k)` 的作用；Multi-Head、位置编码、残差与 LayerNorm、FFN；Embedding 与语义空间；BERT 与 GPT 两条技术路线；从 tokenize 到采样输出的完整推理流程（含 temperature / top-k / top-p）；预训练 → SFT → RLHF/DPO 三阶段训练；参数到底是什么、训练与推理的区别；上下文窗口、KV Cache、MoE、蒸馏；以及 Transformer 与 Agent / RAG 的分工。

主线是一句话：**Transformer 用注意力把"任意两个词直接连起来"，把串行变并行；LLM 则是在这个结构上，用"预测下一个 token"把海量语料压进参数，再用对齐训练把它变成一个会按指令说话的接口。**

## 一、为什么需要 Transformer

### 1.1 Transformer 是什么

一句话：**Transformer 是一个"理解和生成人类语言"的机器结构。** 主流大模型（DeepSeek、GPT、Claude、豆包等）底层都是 Transformer 或其变体。

严格说，Transformer 是 2017 年论文《Attention Is All You Need》提出的**序列建模架构**，最初用于机器翻译，后来成为 LLM 的基础。

### 1.2 RNN / LSTM 的三个问题

在 Transformer 之前，序列任务主要用 RNN / LSTM，存在三个硬伤：

| 问题 | 具体表现 |
|---|---|
| **慢** | 必须按顺序读，第 t 个词要等第 t-1 个词算完，无法并行 |
| **忘** | 信息要沿时间步一步步传递，序列一长，前面的信息被稀释或覆盖，长距离依赖学不到 |
| **抓不住重点** | 对所有词一视同仁，没有机制判断"当前这个词该重点看谁" |

第三点尤其关键：RNN 把整句压成一个固定长度的隐状态，信息瓶颈明显。

### 1.3 Transformer 的解法

- **并行**：所有位置同时计算，靠矩阵乘法一次算完，训练效率提升几个数量级。
- **直接连接**：任意两个位置之间只隔一层注意力，路径长度 O(1)，长距离依赖不再衰减。
- **动态权重**：每个词自己决定关注哪些词，权重由内容算出来，不是固定的。

代价是**计算量随序列长度平方增长**（见 2.6），这也是长上下文昂贵的根源。

## 二、Attention：让模型自己决定看哪里

### 2.1 直觉

**让模型自己判断：当前这个词，应该重点关注前面哪些词。**

例子："Facebook 的 CPA 涨了，因为它的 CPC 上升了。"

读到"它"的时候：

- 和"Facebook"相关性：0.95（很高，就是它）
- 和"CPA"相关性：0.03
- 和"CPC"相关性：0.02

模型据此知道"它"指代 Facebook。注意力权重就是这么一组"相关性分数"，由数据学出来，不是人写的规则。

### 2.2 Q / K / V 是什么

用图书馆借书类比：

| 符号 | 含义 | 类比 |
|---|---|---|
| **Q（Query）** | 当前词要"查询什么" | 我在找什么书？ |
| **K（Key）** | 每个词"能被怎样匹配"的标签 | 每本书的书名 |
| **V（Value）** | 每个词"实际携带的内容" | 每本书的内容 |

流程：

1. 用 Q 和每个 K 做相似度计算（点积）。
2. 相似度经过 Softmax 变成权重（和为 1）。
3. 用权重对所有 V 加权求和，得到当前词的输出。

一句话：**用 Q 去匹配所有 K，按匹配度把对应的 V 混合起来。**

### 2.3 数学形式

```
Q = X · W_Q
K = X · W_K
V = X · W_V

Attention(Q, K, V) = softmax( Q·Kᵀ / sqrt(d_k) ) · V
```

- `X` 是输入序列（`seq_len × d_model`）。
- `W_Q / W_K / W_V` 是可学习参数矩阵，把输入投影到查询 / 键 / 值空间。
- `Q·Kᵀ` 得到 `seq_len × seq_len` 的分数矩阵，第 `i` 行第 `j` 列表示"第 i 个词对第 j 个词的关注分数"。
- Softmax 按行归一化，每行和为 1。
- 最后乘 V，得到每个位置的新表示。

**为什么 Q 和 K 要分开、不能用同一个向量？** 因为"我想找什么"和"我能提供什么"是两种不同的角色。同一个词在不同语境下既可能是查询方，也可能是被查询方，分开投影让模型有更大的表达空间。

### 2.4 为什么要除以 sqrt(d_k)（高频追问）

假设 Q、K 的每个分量独立、均值 0、方差 1，那么点积：

```
q · k = Σ(i=1..d_k) q_i * k_i
```

有 `d_k` 个独立项相加，方差是 `d_k`，标准差是 `sqrt(d_k)`。

所以维度越大，点积的绝对值越大。后果：

1. Softmax 的输入差异被放大 → 输出接近 one-hot（一个位置接近 1，其余接近 0）。
2. Softmax 在饱和区导数接近 0 → **梯度消失，训练不动**。

除以 `sqrt(d_k)` 把点积的方差拉回 1 左右，让 Softmax 工作在梯度良好的区间。

一句话答案：**点积的方差随维度线性增长，除以 `sqrt(d_k)` 是为了防止 Softmax 饱和、梯度消失。**

### 2.5 为什么要 Mask

- **Padding mask**：一个 batch 里句子长度不同，短句补齐的位置不能参与注意力，否则会看到无意义的填充。
- **Causal mask（因果掩码）**：GPT 这类自回归模型只能看左边，不能看右边——训练时把未来位置的分数设成 `-inf`，Softmax 后权重为 0。

没有 causal mask，模型在训练时就能"偷看答案"，推理时没有未来词可用，效果直接崩。

### 2.6 计算复杂度

- 自注意力：`O(n² · d)`，n 是序列长度。分数矩阵是 `n × n`，这是长上下文贵的根本原因。
- 前馈网络：`O(n · d²)`。
-  short n 时 FFN 是瓶颈；n 很大时注意力是瓶颈。

优化方向：稀疏注意力、滑动窗口、线性注意力、FlashAttention（不改变数学结果，只优化显存访问）。

## 三、Multi-Head Attention

### 3.1 是什么

**同时算好几组 Attention，每组用不同的投影矩阵，关注不同的关系。**

| 第几组 | 关注什么 |
|---|---|
| 第 1 组 | 指代关系（"他"指的是谁） |
| 第 2 组 | 主谓关系（谁做了什么） |
| 第 3 组 | 因果关系（为什么涨了） |

"看多了几个角度，理解更全面。"

### 3.2 怎么算

```
head_i = Attention(X·W_Q^i, X·W_K^i, X·W_V^i)
MultiHead = Concat(head_1, ..., head_h) · W_O
```

- 每个头的维度 `d_k = d_model / h`，保证总计算量与单头大维度相当。
- 各头的结果拼接后再过一个输出投影 `W_O`，融合成 `d_model` 维。
- 头与头之间参数不共享。

### 3.3 常见误解

- **多头不是简单重复**：不同头学到不同的关注模式，可视化时常能看到有的头盯相邻词、有的头盯句法依存、有的头盯标点。
- **头数不是越多越好**：总维度固定时，头太多会导致每个头维度太小，表达不足。常见 `h = 8 / 12 / 16 / 32`。
- **不是所有头都有用**：研究发现部分头可以剪掉而几乎不掉点。

## 四、位置编码

### 4.1 为什么需要

**Attention 本身是顺序无关的。** 打乱输入顺序，注意力算出来的结果只是跟着换位置，模型无法区分"狗咬人"和"人咬狗"。

如果不加位置信息，整个模型等价于一个"词袋"。

### 4.2 正弦位置编码（原论文）

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

- `pos` 是位置，`i` 是维度索引。
- 不同维度对应不同频率的正弦波，形成每个位置唯一的"指纹"。
- 优点：不需要训练、可以外推到比训练时更长的序列（有限）、任意两个位置的相对关系可由线性变换表达。

### 4.3 其他方案

| 方案 | 思路 | 用在哪 |
|---|---|---|
| 可学习绝对位置 | 每个位置一个可训练向量 | BERT、早期 GPT |
| 相对位置偏置 | 直接建模"相距 k 个位置" | T5、部分 Transformer 变体 |
| **RoPE（旋转位置编码）** | 把 Q/K 按位置旋转一个角度，点积天然携带相对距离 | LLaMA、Qwen、DeepSeek 等主流 LLM |
| ALiBi | 按距离给注意力分数加线性惩罚 | 部分长文本模型 |

RoPE 之所以成为主流：它让"相对位置"直接体现在注意力分数里，且便于通过调整旋转基数做上下文扩展。

## 五、残差、LayerNorm 与 FFN

### 5.1 残差连接

```
y = x + F(x)
```

- `F(x)` 是注意力或前馈子层的输出。
- 梯度可以通过恒等路径 `x` 直接回传，缓解深层网络的梯度消失。
- 让"加一层至少不会变差"成为可能——最差情况学成 `F(x)=0`。
- GPT-3 有 96 层，没有残差根本训不动。

### 5.2 LayerNorm

```
LayerNorm(x) = γ * (x - μ) / sqrt(σ² + ε) + β
```

- 对**单个 token 的所有特征维度**做归一化，不跨 batch。
- 因此不依赖 batch size，推理时行为与训练一致，适合变长序列。
- `γ`、`β` 是可学习的缩放和平移。

与 BatchNorm 的区别：BatchNorm 跨样本统计（对 batch 敏感、变长序列难处理），LayerNorm 单样本内统计（稳定、Transformer 标配）。

### 5.3 Post-LN vs Pre-LN

| 结构 | 公式 | 特点 |
|---|---|---|
| Post-LN（原论文） | `LN(x + F(x))` | 表达能力强，但深层难训，需要 warmup |
| Pre-LN（现代主流） | `x + F(LN(x))` | 梯度更稳，可训很深的网络，收敛稍慢但更可靠 |

现在几乎都用 Pre-LN 或它的变体（RMSNorm）。

### 5.4 FFN（前馈网络）

```
FFN(x) = W2 · 激活(W1 · x + b1) + b2
```

- 对每个位置**独立**做同样的两层变换，不跨位置交互。
- 中间维度通常放大 4 倍（`d_model → 4·d_model → d_model`），激活常用 GELU / ReLU / SwiGLU。
- 作用：在注意力"混合信息"之后，对每个位置做非线性加工，提升表达能力。
- **参数量大头**：FFN 通常占每层参数的 2/3 左右。

### 5.5 一个 Transformer Block

```
x = x + MultiHeadAttention(LN(x))
x = x + FFN(LN(x))
```

堆 N 层，就是"深度"。每一层都在做同一件事：**先让词与词交换信息（Attention），再让每个词自己消化（FFN）。**

## 六、Embedding：文字怎么变成数字

### 6.1 基本过程

计算机只认识数字，所以必须先把字变成数字。

```
"Facebook" → token id 12345 → 查表 → [0.12, -0.34, ..., 0.88]   （d_model 维）
```

- 词表是有限的（几万到十几万），每个 token 对应一个 `d_model` 维向量。
- 这张表就是参数的一部分，训练时一起更新。
- 数学上等价于 one-hot 向量乘一个矩阵，但实现上直接查表，不做矩阵乘法。

### 6.2 词向量的性质

**语义相近的词，向量也相近。**

- "Facebook"和"Google"都是广告渠道 → 向量很像。
- "Facebook"和"苹果" → 向量差得很远。

常见的相似度度量是余弦相似度：

```
cos(a, b) = (a·b) / (|a| * |b|)
```

只看方向，不看长度，取值 -1 到 1。

经典例子：`king - man + woman ≈ queen`——方向承载语义关系。这类线性关系在早期静态词向量（Word2Vec / GloVe）上最明显，上下文模型里被分散到多层表示中。

### 6.3 静态向量 vs 上下文向量

| | 静态词向量 | 上下文向量 |
|---|---|---|
| 代表 | Word2Vec、GloVe | BERT、GPT 的隐层输出 |
| "苹果"的向量 | 永远同一个 | 在"吃苹果"和"苹果发布会"里不同 |
| 能力 | 只能表达平均语义 | 能区分一词多义 |

Transformer 输出的 embedding 是**上下文相关**的，这也是它比静态词向量强的地方。

### 6.4 和 RAG 里的 Embedding 的关系

本质一样：都是把文字变成向量，让计算机能处理。区别在粒度：

| | Transformer 内部 | RAG |
|---|---|---|
| 输入 | 单个 token | 整段文档 / 一句话 |
| 输出 | 每个 token 一个向量 | 整段一个向量 |
| 用途 | 供后续层计算 | 存进向量数据库，做相似度检索 |
| 模型 | LLM 自己的 embedding 层 | 专门的 embedding 模型（bge-m3、MiniLM 等） |

RAG 用的 embedding 模型通常是 BERT 家族的双塔编码器，输出经过池化（CLS 或均值）得到句向量，再归一化后用余弦相似度或 ANN 索引检索。

## 七、BERT vs GPT：两条技术路线

### 7.1 一张表说清

| | GPT（生成派） | BERT（理解派） |
|---|---|---|
| 结构 | Decoder-only | Encoder-only |
| 注意力方向 | 只看左边（Masked / Causal，右边还没生成） | 前后都看（双向） |
| 训练任务 | 预测下一个词（自回归） | 完形填空（Masked LM，猜被盖住的词） |
| 训练范式 | 自回归（Autoregressive） | 自编码（Autoencoding） |
| 产出 | 下一个 token 的概率 → 生成文字 | 每个词"读懂上下文"的向量 |
| 任务类型 | 生成式 | 判别式（分类、序列标注、检索） |
| 典型用途 | 对话、写作、Agent、代码 | embedding、检索、分类、NER |
| 项目里的对应 | DeepSeek（Agent 生成回答） | MiniLM / bge-m3（RAG 算 embedding） |

一句话：**BERT 是"读"的 Transformer（理解引擎），GPT 是"写"的 Transformer（生成引擎）。**

### 7.2 自编码 vs 自回归

- **自编码（BERT）**：把输入的一部分遮住，让模型还原。因为要还原被遮的词，必须同时看左右上下文 → 双向。学到的是"这个词在语境里是什么"。
- **自回归（GPT）**：给定前文，预测下一个词。因为只能看前文 → 单向。学到的是"接下来最可能是什么"。

这两种目标函数决定了能力边界：BERT 擅长"理解并打标签"，不擅长"自由生成"；GPT 擅长"续写"，理解能力是副产品。

### 7.3 各自适合什么任务

| 任务 | 首选 | 理由 |
|---|---|---|
| 文本分类、情感分析 | BERT 类 | 双向上下文 + 分类头，小模型就能到高精度 |
| 命名实体识别 | BERT 类 | 每个 token 都要标注，需要双向信息 |
| 语义检索 / RAG embedding | BERT 类双塔 | 输出句向量，可预先建索引 |
| 对话、写作、代码生成 | GPT 类 | 自回归天生适合生成 |
| Agent 决策、工具调用 | GPT 类 | 需要指令遵循和自由格式输出 |
| 抽取式问答 | BERT 类 | 预测答案在原文的起止位置 |

补充：GPT 也能做分类（把类别当 token 生成），但成本和延迟远高于微调一个小 BERT；BERT 也能"生成"，但只能做填空式生成，不能自由续写。

### 7.4 第三条路线

T5 / BART 这类 **Encoder-Decoder** 结构：编码器双向读输入，解码器自回归生成输出，适合翻译、摘要这类"输入到输出"的任务。它不是主流 LLM 的选择，但概念上要能区分。

### 7.5 四条红线

1. 别说"模型记住了文字 / 知识存在某个地方"——知识是向量关系，不是原文存储。
2. 别说"Transformer 能回答问题"——Transformer 只负责读懂上下文并算概率，"回答"是输出层 + 自回归采样完成的。
3. 别把 GPT 和 BERT 混为一谈——一个只看左边（生成），一个前后都看（理解）。
4. 别说"知识是导入的"——是"预测下一个词磨出来的"。

## 八、完整推理流程

### 8.1 七步

```
输入："本季度 Facebook 的 CPA 是多少？"
  ↓
① Tokenization：把句子切成 token，变成数字编号
  ↓
② Embedding：每个 token 查表变成 d_model 维向量
  ↓
③ 加位置编码：告诉模型词的顺序
  ↓
④ 经过 N 层 Transformer（几十层）
     每层做两件事：
     - Multi-Head Self-Attention：每个词看其他所有词
     - FFN：每个词再加工一下
  ↓
⑤ 输出层：最后一个位置的向量 → 词表大小的 logits
  ↓
⑥ Softmax：变成"下一个 token"的概率分布
  ↓
⑦ 采样一个 token，拼回输入，重复 ④~⑦，直到结束符或达到 max_tokens
```

关键结论：**全程没有"理解 → 想答案 → 输出"的人类思维，只有"算概率 → 采样下一个字 → 循环"。**

### 8.2 Tokenization 细节

- 主流算法：BPE（GPT 系）、WordPiece（BERT）、SentencePiece（多语种、LLaMA 系）。
- 粒度是**子词**：常见词一个 token，生僻词拆成几个片段。
- 中文通常 1 个汉字约 1~2 个 token（取决于词表）；英文一个 token 约 4 个字符。
- 词表大小常见 3 万 ~ 15 万。
- token 数直接决定成本和上下文占用：计费按 token，不是按字数。

### 8.3 输出层

- 最后一个位置的隐向量（`d_model`）经过一个线性层投影到词表维度，得到 logits。
- 很多模型让这个投影矩阵与 embedding 矩阵共享（weight tying），省参数。
- Softmax 后得到每个 token 的概率。

### 8.4 采样策略

模型给的是概率分布，怎么从分布里挑字，是可调的。

| 策略 | 做法 | 特点 |
|---|---|---|
| 贪心（Greedy） | 每次取概率最高的 | 确定、可复现；容易重复、死板 |
| 束搜索（Beam Search） | 保留 top-b 条候选序列 | 翻译等任务常用；开放对话里显得平庸 |
| Temperature | logits 除以 T 后再 Softmax | 控制整体随机性 |
| Top-k | 只保留概率最高的 k 个，重新归一化 | 截掉长尾，避免采到离谱词 |
| Top-p（nucleus） | 保留累积概率达到 p 的最小集合，重新归一化 | 自适应候选数量，比 top-k 更灵活 |

**Temperature 的作用**：

```
p_i = softmax(z_i / T)
```

- `T < 1`：分布变尖，高概率词更占优 → 更确定、更保守。
- `T = 1`：原始分布。
- `T > 1`：分布变平 → 更随机、更有创造性，也更容易胡说。
- `T → 0`：退化为贪心。

**Top-k 与 Top-p 的区别**：

- top-k 固定候选数量，不管分布形状；分布很尖时 k 太大，分布很平时 k 太小。
- top-p 按累积概率动态决定候选数，分布尖时候选少、分布平时候选多。
- 常见组合：`temperature=0.7, top_p=0.9`。两者都调得很激进会叠加放大随机性。

**事实型任务**（查数、写 SQL）→ 低温度；**创意型任务**（写文案、起标题）→ 高温度。同一句 prompt 结果不稳定，先检查 temperature。

### 8.5 自回归循环

每生成一个 token，就把它拼到输入末尾，重新跑一次前向，预测下一个。这就是"自回归"（autoregressive）。

朴素的实现每步都要重算全部历史，代价是 O(n²)。工程上用 KV Cache 优化（见第十一节）。

## 九、训练三阶段

### 9.1 总览

| 阶段 | 任务 | 数据 | 产出 | 特点 |
|---|---|---|---|---|
| ① 预训练（Pre-training） | 预测下一个 token | 海量文本（自监督，无需标注） | Base 模型（有知识，不会聊天） | 占约 99% 算力 |
| ② 监督微调（SFT） | 看问答对学"回答" | 几万到几十万条人工标注对话 | 会聊天的助手 | Function Calling 也在此教 |
| ③ 对齐（RLHF / DPO） | 人打分排序 | 人类偏好数据 | 会"好好说话"的成品 | 学会有用、无害、讨喜 |

关键：预训练用"文本自己当题目、自己也当答案"（自监督），所以能零成本量产。

### 9.2 预训练：next token prediction

- 输入：互联网量级的文本（万亿 token 级）。
- 过程：取一段文本，用前 n 个 token 预测第 n+1 个，算交叉熵损失，反向传播调参数。
- 一次前向可以对每个位置同时算损失（teacher forcing + causal mask），训练效率极高。
- 学到：语法、事实知识、世界常识、推理模式的雏形。

**为什么"猜下一个词"能学到知识？** 因为要把下一个词预测准，模型必须隐式掌握大量因果关系和事实关联。这是整件事最反直觉、也最关键的一点。

### 9.3 知识是怎么"进"模型的

不是"导进去"，是"磨进去"。

- 错误想象：把百科文字复制进模型存起来。
- 真实过程：喂海量文本，逼它预测下一个字，为了预测准，**被迫把知识压进参数**。

机制：反复"拉近 / 推远"词向量。

```
语料："珠穆朗玛峰是世界最高峰"
训练：输入「珠穆朗玛峰是世界」→ 预测下一个字
      猜错 → loss 大 → 反向传播 → 调整参数
      → "珠穆朗玛峰"和"世界最高峰"的向量，被拉近一点点
```

几万亿字反复磨，"一起出现的词拉近、不该一起的推远"，最终向量空间编码了整张知识关系网。

三句金句：

1. **知识不是存储的，是训练的副产品。**
2. **知识以向量形式存在**——"珠穆朗玛峰"的知识 = 它和"最高峰""8848 米"向量挨得近。
3. **训练 = 反复拉近 / 推远词向量**，几万亿次后长成"世界知识"。

### 9.4 SFT：监督指令微调

- 数据：人工编写的（指令，回答）对，质量远比数量重要。
- 目标：仍然是 next token prediction，但只在**回答部分**算损失（prompt 部分 mask 掉），让模型学"给定指令该怎么续写"。
- 学到：听懂指令、按格式回答、拒绝不当请求的雏形、Function Calling 的调用格式。
- 规模：通常几万到几十万条，远小于预训练。

SFT 不注入新知识，它改变的是**行为方式**——把 Base 模型的"续写能力"引导成"对话能力"。

### 9.5 RLHF：基于人类反馈的强化学习

三步：

1. **收集偏好数据**：同一个问题让模型生成多个回答，人工标注哪个更好（排序，不是打分）。
2. **训练奖励模型（Reward Model）**：学习人类的偏好，给任意回答打一个分数。常用 Bradley-Terry  pairwise 损失。
3. **强化学习优化策略**：用 PPO 等算法调 LLM，让它生成奖励更高的回答；同时加一个 KL 惩罚，防止模型偏离 SFT 模型太远（否则会学会"讨好奖励模型"的怪话）。

作用：让回答更有用、更简洁、更符合人类表达习惯，减少有害输出。

代价：流程复杂（四个模型同时在显存里：策略、参考、奖励、价值），训练不稳定，调参困难。

### 9.6 DPO：直接偏好优化

DPO（Direct Preference Optimization）把 RLHF 的目标改写成一种**类似分类的损失**，直接用偏好对（chosen / rejected）训练，**不需要单独训练奖励模型，也不需要 PPO 采样**。

- 输入：同一个 prompt 下的好回答和差回答。
- 目标：提高好回答的似然、降低差回答的似然，同时用参考模型约束偏移。
- 优点：实现简单、训练稳定、显存占用低，效果在许多任务上接近 RLHF。
- 缺点：是离线方法，依赖偏好数据质量；探索能力不如在线 RL。

一句话：**RLHF 是"先学一个裁判，再用强化学习取悦裁判"；DPO 是"直接告诉模型哪个答案更好，让它照着调"。**

### 9.7 对齐目标

业界通用三原则：**有用（helpful）、诚实（honest）、无害（harmless）**。三者会冲突——过度追求无害会让模型变得过度拒答，这也是对齐训练要权衡的地方。

## 十、参数是什么，训练和推理的区别

### 10.1 参数就是一堆数字

几百亿个。训练就是调整这些数字，让预测越来越准。

类比音响的旋钮：音量、高音、低音……调到合适的位置，声音最好听。Transformer 有几百亿个这样的旋钮，训练就是把它们调到最合适的位置。

### 10.2 参数都在哪

以 `d_model = d`、层数 `L`、词表 `V` 为例：

| 位置 | 参数量 | 说明 |
|---|---|---|
| Token embedding | `V × d` | 词表查表矩阵 |
| 每层 Attention | `4d²` | W_Q、W_K、W_V、W_O 各 `d×d` |
| 每层 FFN | `8d²` | 中间层 `4d`，两个矩阵 `d×4d` 和 `4d×d` |
| 每层 LayerNorm | `4d` 左右 | γ、β，可忽略 |
| 输出层 | `V × d` | 常与 embedding 共享 |

每层约 `12d²`，总参数约 `12·L·d² + 2·V·d`。

例：`d = 4096`、`L = 32`、`V = 32000`

```
12 * 4096² * 32 ≈ 6.4B
2 * 32000 * 4096 ≈ 0.26B
合计约 6.7B
```

这也解释了两个现象：

- **加深比加宽省参数**：参数量与 `d²` 成正比，宽度翻倍参数变 4 倍。
- **embedding 在小模型里占比高**：词表大时 `V×d` 不可忽视。

### 10.3 训练过程

1. 先随机给参数赋值（用初始化策略，不是全 0）。
2. 拿数据预测，算误差。
3. 每个参数都往减小误差的方向调一点点（梯度下降）。
4. 重复几万亿次。

### 10.4 训练 vs 推理

| | 推理（使用时） | 训练（做模型时） |
|---|---|---|
| 用 Attention 吗 | 用 | 用 |
| 干嘛用 | 理解问题，生成回答 | 理解文本，猜下一个字 |
| 参数变吗 | 不变 | 一直在调 |
| 目的 | 输出回答 | 把参数调准 |
| 计算特点 | 自回归、逐 token、受显存带宽限制 | 一次前向算所有位置、可并行、受算力限制 |
| 成本 | 按 token 计费，推理为主 | 一次几百万美元级，预训练为主 |

一个重要区别：**推理时参数冻结，但模型内部状态在变**（KV Cache 不断增长）；训练时参数在变，但不需要缓存历史（一次前向看全序列）。

### 10.5 微调是什么

- **全参微调**：更新所有参数，成本高，容易灾难性遗忘。
- **参数高效微调（PEFT）**：只训练一小部分参数。最常见的是 **LoRA**——冻结原权重，在旁边加两个低秩矩阵 `A·B`，只训练它们，推理时可合并回原权重。
- 微调改变的是行为与领域适配，不是从零注入知识。

## 十一、上下文窗口、KV Cache、MoE、蒸馏

> 本节为补写内容：源笔记中未展开，属于面试常问的工程侧概念。

### 11.1 上下文窗口

**模型一次能处理的 token 总数上限（输入 + 输出）。**

- 超出会报错或被截断，早期内容直接丢失。
- 注意力是 `O(n²)`，窗口翻倍，计算量和显存约翻四倍。
- "lost in the middle"：长上下文中，开头和结尾的信息更容易被利用，中间部分容易被忽略。
- 扩展手段：RoPE 调整基数（NTK / YaRN）、滑动窗口注意力、稀疏注意力、检索增强（把长文档切块，只喂相关片段）。

工程含义：**长上下文不等于无限记忆**。把整份文档塞进去，既贵又可能漏，RAG 仍然是更经济的做法。

### 11.2 KV Cache

自回归生成时，每生成一个新 token，都要让它关注前面所有 token。如果每一步都重算前面所有 token 的 K、V，代价是 `O(n²)`。

**KV Cache 的做法**：把每一层历史 token 的 K、V 存下来，新 token 只算自己的 Q、K、V，然后直接和缓存拼接做注意力。

- **时间复杂度**：从每步 `O(n²)` 降到每步 `O(n)`（累计仍是 `O(n²)`，但常数小得多）。
- **显存代价**：`2 × L × h × d_head × seq_len × batch × 字节数`，随上下文线性增长。
- 常见优化：PagedAttention（vLLM）把 cache 分页管理，减少碎片；MQA / GQA 让多个 query 头共享一组 K/V，直接砍掉数倍显存。
- **Prefill vs Decode**：预填充阶段并行处理整个 prompt，是算力瓶颈；解码阶段逐 token 生成，是显存带宽瓶颈。这也是为什么"首 token 延迟"和"每秒 token 数"是两个不同指标。

一句话：**KV Cache 用显存换时间，是推理加速最基础的一招。**

### 11.3 MoE（混合专家）

把 Transformer 里的 FFN 换成 N 个"专家"FFN，再加一个路由器（router），每个 token 只激活其中 top-k 个专家（常见 2 个）。

- **总参数量很大，单次计算量很小**：模型容量上去了，算力没同比例上涨。
- 代价：所有专家都要占显存（即使没被激活）、需要负载均衡避免"专家饿死"、多卡通信复杂。
- 典型：Mixtral 8x7B、DeepSeek-V3 等。

一句话：**MoE 是"参数很多但每次只用一小部分"，用显存换容量。**

### 11.4 蒸馏

用一个大的**教师模型**教一个小的**学生模型**。

- 教师输出的是**软标签**（soft label）：完整概率分布，比如"猫 0.7、狗 0.2、汽车 0.01"。
- 学生同时学硬标签（真实类别）和软标签（教师的分布），损失通常是两者的加权 + KL 散度。
- 软标签携带"暗知识"：它告诉学生"猫更像狗，而不像汽车"，这种类间相似性是硬标签给不了的。
- 温度 `T` 用来平滑教师分布，让学生看到更多细节；训练后学生推理时用 `T=1`。

变体：响应蒸馏（学输出）、特征蒸馏（学中间层表示）、思维链蒸馏（学推理过程）。

用途：把大模型压缩成能在端侧 / 低延迟场景部署的小模型。

## 十二、Transformer 与 Agent / RAG 的关系

### 12.1 Agent = 大脑 + 手脚

| 角色 | 谁干的 |
|---|---|
| 理解用户问题 | Transformer |
| 判断该调用哪个工具 | Transformer |
| 填工具参数 | Transformer |
| 整理结果成回答 | Transformer |
| 真正查数据库、算指标 | 工具（代码） |

**Transformer 是 Agent 的大脑，工具是 Agent 的手脚。**

模型再强也算不准精确指标、也拿不到内部数据，所以必须把"算"和"取数"交给工具。

### 12.2 RAG = 开卷考试

| | RAG | 大模型本身 |
|---|---|---|
| 知识在哪 | 外部知识库 | 参数里 |
| 怎么回答 | 先查知识库，再整理 | 直接根据参数里的知识生成 |
| 像什么 | 开卷考试 | 闭卷考试 |
| 更新成本 | 改文档即可 | 要重新训练 |
| 可溯源 | 能给出处 | 不能 |

RAG 解决三个问题：知识过时、领域知识缺失、幻觉无法追溯。它不改变模型参数，只在 prompt 里补上下文。

### 12.3 三层能力分工

```
参数化知识（预训练）  → 通用语言能力、世界常识
外部知识（RAG）        → 私域文档、最新资料
实时数据（Function Calling / API） → 数仓指标、订单状态、计算结果
```

三者互补，不能互相替代：

- 只有参数 → 不知道内部数据，会编。
- 只有 RAG → 拿不到实时数值，也不会算。
- 只有工具 → 不会理解模糊的自然语言指令。

### 12.4 为什么这个组合能工作

LLM 的输出是"下一个 token 的概率"，它擅长**理解意图、组织语言、决定下一步**，不擅长**精确记忆和精确计算**。

所以工程上的通用范式是：**LLM 负责决策与表达，工具负责取数与计算，RAG 负责补知识。** 这也是 Agent 系统的基本分工。

## 十三、面试速查

**Q：为什么需要 Transformer？**
A：RNN 串行慢、长距离易遗忘、无法区分重点；Transformer 用注意力实现并行计算和任意位置直接连接。

**Q：Attention 在做什么？**
A：让每个词根据内容计算对其他词的关注权重，再按权重加权汇总信息。

**Q：Q、K、V 分别是什么？**
A：Q 是当前词的查询，K 是每个词被匹配的标签，V 是每个词携带的内容；用 Q 匹配 K 得到权重，再对 V 加权求和。

**Q：为什么要除以 sqrt(d_k)？**
A：点积方差随维度线性增长，数值过大会让 Softmax 饱和、梯度消失；缩放后方差回到 1 左右。

**Q：为什么要 Mask？**
A：Padding mask 屏蔽补齐位；Causal mask 屏蔽未来 token，防止自回归训练时偷看答案。

**Q：Self-Attention 的复杂度？**
A：`O(n²·d)`，n 是序列长度；这是长上下文昂贵的根本原因。

**Q：Multi-Head 有什么用？**
A：多组独立投影从不同角度建模关系（指代、句法、因果），拼接后融合，表达更丰富。

**Q：为什么需要位置编码？**
A：注意力本身顺序无关，不加位置信息模型等价于词袋，无法区分语序。

**Q：位置编码有哪些方案？**
A：正弦编码、可学习绝对位置、相对位置偏置、RoPE（主流）、ALiBi。

**Q：残差连接的作用？**
A：提供恒等梯度通路，缓解深层网络梯度消失，让"加深至少不变差"。

**Q：LayerNorm 和 BatchNorm 的区别？**
A：LayerNorm 在单个样本的特征维度上归一化，不依赖 batch，适合变长序列；BatchNorm 跨样本统计。

**Q：FFN 的作用？**
A：对每个位置独立做两层非线性变换（中间扩 4 倍），增强表达能力，通常占每层参数的三分之二。

**Q：一个 Transformer Block 由什么组成？**
A：Multi-Head Self-Attention + 残差 + LayerNorm，再接 FFN + 残差 + LayerNorm。

**Q：Embedding 是什么？**
A：把 token 映射成稠密向量的查表操作；语义相近的词向量相近。

**Q：静态词向量和上下文向量的区别？**
A：静态词向量一个词只有一个向量；上下文向量随句子变化，能区分一词多义。

**Q：BERT 和 GPT 的核心区别？**
A：BERT 是 Encoder-only、双向、完形填空、产出表示，适合理解类任务；GPT 是 Decoder-only、单向、预测下一个词、产出概率，适合生成。

**Q：什么是自编码和自回归？**
A：自编码是遮住部分输入再还原（BERT）；自回归是根据前文预测下一个 token（GPT）。

**Q：BERT 适合什么任务？**
A：分类、NER、抽取式问答、语义检索 / embedding。

**Q：GPT 适合什么任务？**
A：对话、写作、代码生成、Agent 工具调用。

**Q：完整推理流程？**
A：tokenize → embedding → 加位置编码 → N 层 Transformer → 输出层 → Softmax 概率 → 采样一个 token → 拼回输入循环，直到结束符。

**Q：temperature 的作用？**
A：logits 除以 T 再 Softmax；T<1 更确定，T>1 更随机，T→0 退化为贪心。

**Q：top-k 和 top-p 的区别？**
A：top-k 固定保留 k 个候选；top-p 按累积概率动态确定候选集合，更能适应分布形状。

**Q：为什么模型输出不稳定？**
A：采样有随机性。事实型任务应降低 temperature，必要时固定 seed。

**Q：训练分哪三个阶段？**
A：预训练（next token prediction，学知识与语言）、SFT（指令微调，学听指令和工具调用）、RLHF / DPO（对齐人类偏好）。

**Q：预训练为什么能学到知识？**
A：为了预测准下一个词，模型被迫把事实关联压进参数；知识是训练的副产品，不是导入的。

**Q：SFT 和预训练的区别？**
A：预训练学"语言和知识"，SFT 学"按指令回答的行为"，数据量小几个数量级。

**Q：RLHF 的流程？**
A：收集人类偏好排序 → 训练奖励模型 → 用 PPO 优化策略，同时用 KL 惩罚约束不要偏离太远。

**Q：DPO 和 RLHF 的区别？**
A：DPO 直接用偏好对优化，不需要奖励模型和强化学习采样，更简单稳定；RLHF 更灵活但工程复杂。

**Q：参数是什么？**
A：几百亿个可学习的数字，分布在 embedding、注意力投影、FFN 和输出层里；训练就是调它们。

**Q：训练和推理的区别？**
A：推理时参数冻结、逐 token 生成、可用 KV Cache；训练时参数持续更新、一次前向可并行算所有位置的损失。

**Q：上下文窗口是什么？**
A：一次能处理的 token 上限（输入 + 输出）；受 `O(n²)` 注意力限制，且存在"中间信息易丢失"问题。

**Q：KV Cache 是什么？**
A：缓存历史 token 的 K、V，避免每步重算，用显存换时间；显存随上下文线性增长。

**Q：MoE 是什么？**
A：把 FFN 换成多个专家，每个 token 只激活 top-k 个，参数量大但单次计算量小。

**Q：蒸馏是什么？**
A：用教师模型的软标签（概率分布）教学生小模型，软标签携带类间相似性的暗知识，用于压缩部署。

**Q：Transformer 和 Agent 的关系？**
A：Transformer 是大脑，负责理解、决策、填参数、组织回答；工具是手脚，负责查库和精确计算。

**Q：RAG 和大模型的关系？**
A：RAG 是开卷考试，从外部知识库检索后塞进上下文；模型本身是闭卷考试，知识在参数里。

**Q：为什么有了大模型还需要 RAG 和工具？**
A：模型缺实时数据、缺私域知识、不擅长精确计算且会幻觉；RAG 补知识，工具补数据与计算。
