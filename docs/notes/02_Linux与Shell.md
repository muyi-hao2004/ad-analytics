## 一、Linux 在数据工程中的位置

### 1.1 一条认知主线

```
Linux（服务器系统）→ Python（指挥语言）→ 服务器程序 vs 普通电脑 → Docker（打包部署）
```

核心结论：**代码是「逻辑」，操作系统是「跑代码的地方」，两者解耦。** 同一份 Python / SQL / Spark 代码，换 Windows 或 Linux 照样能用。

### 1.2 Linux 是生存环境，不是加分项

所有大数据组件（Spark、Kafka、Hadoop、Airflow、Flink、MySQL），**生产环境 99% 跑在 Linux 服务器上**。不会 Linux 意味着连服务器都登不上、服务都部署不了，工作无法开展。

### 1.3 六个具体作用

| 作用 | 例子 |
|---|---|
| 服务器就是 Linux | `ssh mia@IP` 登录远程服务器 |
| 部署运行组件 | `spark-submit`、`airflow scheduler`、`kafka-server-start.sh` |
| 数据处理文件操作 | `cat` / `head` / `tail` / `grep` / `awk` / `wc` / `find` |
| 看日志排查 | `tail -f app.log`、`grep "ERROR"` |
| Shell 脚本自动化 | 写 `.sh` 一键跑一串命令 |
| 进程资源监控 | `ps` / `top` / `kill` / `lsof` / `df` / `free` |

### 1.4 够用的底线

不需要学成运维，**必须会五件事：登录、看日志、查进程、传文件、装软件。**

对应的重点命令：`cat/head/tail/grep/awk/wc/find`、`chmod/chown`、`ps/top/kill/lsof`、`df/du`、`scp`、写 `.sh`、`apt/yum/pip`。

整体流程可以概括为：**登录 → 看 → 找 → 改 → 排障**。

### 1.5 Windows 学习环境 vs Linux 生产环境

| | 自己电脑（学习） | 生产服务器（工作） |
|---|---|---|
| 操作系统 | Windows | **Linux**（Ubuntu / CentOS） |
| 位置 | 桌上 | 阿里云 / 腾讯云机房 |
| 操作方式 | 鼠标 + PyCharm 图形界面 | **命令行（ssh 登录）** |
| 使用者 | 自己 | 全公司 / 全世界用户 |
| 数据量 | 小（千行 CSV） | 大（TB 级） |

两条核心区别：**① 系统不同（Windows vs Linux）；② 操作方式不同（图形界面 vs 纯命令行）。**

### 1.6 换到 Linux 后 PySpark 还能用吗

**完全能用，代码一行不用改。** 代码是逻辑，系统是环境，Python / PySpark / MySQL 都是跨平台的。

唯一要改的两处：

- **文件路径**：`C:/...` → `/home/...`
- **操作方式**：从「PyCharm 点运行」变成命令行 `spark-submit`

## 二、终端与 WSL：命令行的操作基础

### 2.1 WSL 是什么

WSL（Windows Subsystem for Linux）让 Windows 上直接跑一个真实的 Linux 发行版（如 Ubuntu），不需要装虚拟机、开双系统。练习环境就是 WSL Ubuntu，打开终端就是一个没有图形界面的 Linux 命令行。

三件需要知道的事：

| 现象 | 含义 |
|---|---|
| Linux 里只有一个根 `/` | Windows 的盘被挂载在 `/mnt/c`、`/mnt/d` |
| 家目录是 `/home/<用户名>` | `~` 展开到这里 |
| Windows 访问 WSL 文件 | 资源管理器地址栏输入 `\\wsl.localhost` |

`\\wsl.localhost` 的实际用途：在 Windows 侧（编辑器里）写好脚本，再放进 WSL 运行，避免在终端里手敲长脚本。

### 2.2 终端快捷键

| 操作 | 快捷键 |
|---|---|
| 复制 / 粘贴 | `Ctrl+Shift+C` / `Ctrl+Shift+V`（**不是** `Ctrl+C/V`） |
| 中断当前命令 | `Ctrl+C` |
| 清屏 | `Ctrl+L` |
| 跳到行首 / 行尾 | `Ctrl+A` / `Ctrl+E` |
| 上一条 / 下一条历史 | `↑` / `↓` |
| 反向搜索历史命令 | `Ctrl+R` |

为什么不是 `Ctrl+C/V`：在终端里 `Ctrl+C` 是「发送中断信号」，`Ctrl+V` 是「按字面插入下一个字符」，这两个键位早已被终端占用。

### 2.3 从网页 / 聊天工具复制命令的坑

引号 `"`、单引号 `'`、破折号 `--` 会被替换成中文全角标点，bash 不识别。

典型症状：提示符从 `$` 变成 `>`，表示 shell 认为「上一条命令没写完，还在等补全」（通常是引号没闭合）。

处理：`Ctrl+C` 退出当前输入，回到 `$`，然后把引号自己手敲一遍。

### 2.4 Git Bash

Windows 上另一种常用终端是 Git Bash（随 Git 安装），提供 bash 环境与常用 Unix 命令。（源笔记未展开）

### 2.5 读报错的核心技能

Linux 报错**最后一两行**往往直接告诉「缺什么、怎么补」，例如提示 `apt install python3.14-venv`。

原则：**先读完报错，再动手**。多数「环境搭不起来」的问题，答案就在报错最后一行。

## 三、文件系统与路径

### 3.1 Linux 是一棵树

- Windows：多个盘符 `C:` `D:` `E:`，每个盘是独立的根。
- Linux：**只有一个根 `/`**，所有东西都挂在这棵树下。Windows 的 C 盘在 Linux 里是 `/mnt/c`。

```
/           根（一切从这里开始）
├── /bin     基本命令（ls、cat、grep…）
├── /usr/bin 更多用户程序（which ls 通常指到这里）
├── /etc     系统配置文件
├── /home    每个普通用户的家目录（/home/haohao）
├── /root    root 用户的家目录（普通用户进不去）
├── /tmp     临时文件
└── /mnt     挂载点（/mnt/c 就是 Windows 的 C 盘）
```

记住 `/etc`（配置）、`/home`（家目录）、`/tmp`（临时文件）三处即可覆盖大部分日常场景：改配置去 `/etc`，自己的东西放 `/home`，临时产物丢 `/tmp`。

### 3.2 路径的写法

| 符号 | 含义 |
|---|---|
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `~` | 家目录，如 `/home/haohao` |
| 相对路径 | 从当前目录出发，如 `sub/a.txt` |
| 绝对路径 | 从根 `/` 出发，如 `/home/haohao/a.txt` |

**末尾加不加 `/`**：几乎没区别（`sub` = `sub/`）。真正的判断标准是目标写的是「目录」还是「完整文件名」：

- 写目录 → 放进去，保持原名：`cp a.txt sub/` → `sub/a.txt`
- 写完整文件名 → 复制 / 移动并改名：`cp a.txt sub/b.txt`

### 3.3 隐藏文件

文件名以 `.` 开头即为隐藏，如 `.venv`、`.git`、`.bashrc`。

```bash
ls -a        # 显示全部（含隐藏）
ls -la       # 最常用组合：长格式 + 隐藏文件
```

`ls -la` 一次性给出权限、属主、大小、时间和全部文件，是进目录后第一个该敲的命令。

## 四、文件操作

### 4.1 最常用命令

| 命令 | 作用 | 例子 |
|---|---|---|
| `pwd` | 显示当前目录 | `pwd` |
| `whoami` | 显示当前用户 | `whoami` |
| `ls` / `ls -l` | 列出文件 / 详细信息 | `ls -l hello.txt` |
| `cd` | 切换目录 | `cd /`、`cd ~` |
| `mkdir` / `touch` | 建目录 / 建空文件 | `touch hello.txt` |
| `echo` | 输出文字（常配重定向写文件） | `echo "hi" > f.txt` |
| `cat` | 查看文件全部内容 | `cat hello.txt` |
| `grep` | 按关键词搜索 | `grep "ERROR" hello.txt` |
| `which` | 查命令的实际路径 | `which ls` |
| `sudo` | 临时借管理员权限 | `sudo ls /root` |

`which` 的用处：确认「现在敲的 `python3` 到底是哪一个」，排查环境问题时必用（详见虚拟环境一节）。

### 4.2 进阶：软链接、压缩、复制、移动

| 命令 | 作用 | 例子 |
|---|---|---|
| `ln -s 目标 链接名` | 建软链接（快捷方式） | `ln -s hello.txt hello_link` |
| `tar -czf x.tar.gz 文件` | 打包 + gzip 压缩 | `c`=创建 `z`=gzip `f`=文件名 |
| `tar -xzf x.tar.gz` | 解压到当前目录 | `x`=解压 |
| `tar -xzf x.tar.gz -C 目录` | 解压到指定目录 | `-C` 指定目标目录 |
| `tar -tzf x.tar.gz` | 只看包里有什么，不解压 | `t`=list |
| `cp 源 目标` | 复制（保留原件） | `cp a.txt sub/` |
| `mv 源 目标` | 移动 / 重命名（不留原件） | `mv a.txt sub/`、`mv a.txt b.txt` |

### 4.3 软链接

- `ls -l` 输出第一位是 `l`，表示 link。
- 软链接文件本身体积极小，内容只是「目标路径」这一行字符串。
- 目标被删除后，软链接变成「断链」，访问会报 `No such file or directory`。

数据工程中的典型用法是**版本切换**：脚本固定读 `/data/latest`，而 `latest` 是一个软链接，指向当前最新日期目录（如 `/data/2026-01-01`）。换版本时只改链接指向，所有下游脚本不用动。

### 4.4 tar 的坑

解压同名文件会**静默覆盖**，没有任何提示。

所以解压前先 `tar -tzf x.tar.gz` 看一眼包里有什么、会覆盖哪些文件——这是很多「配置被莫名改掉」事故的来源。

### 4.5 危险红线

`rm -rf` 只允许对「你明确知道内容的目录」使用（比如刚建失败、准备重建的 `.venv`）。

**永远不要对 `/` 或家目录这类大目录敲 `rm -rf`**：它不回收站、不二次确认、不区分「你以为的路径」和「tab 补全出来的路径」。

## 五、文件权限

### 5.1 权限串怎么读

`ls -l` 输出的权限串共 10 个字符，分 4 段：

```
-          rw-           r--          r--
文件类型    主人(u)权限    组(g)权限     其他人(o)权限
```

- 第 1 位：`-` 普通文件、`d` 目录、`l` 链接
- 后面每 3 位一组，固定顺序 `r w x`：读 / 写 / 执行，`-` 表示没有该权限

### 5.2 数字法

`r=4`、`w=2`、`x=1`，每组三个二进制位相加。

| 权限串 | 数字 | 含义 |
|---|---|---|
| `-rw-r--r--` | 644 | 主人可读写，其他人只读（普通文件最常见） |
| `-rw-------` | 600 | 只有主人可读写（密钥文件标配） |
| `-rwxr-xr-x` | 755 | 主人全权，其他人可读可执行（脚本 / 目录常见） |

```bash
chmod u+x hello.txt   # 符号法：给主人加执行权限
chmod 600 hello.txt   # 数字法：只有主人可读写
```

数字法一次设定全部权限（会覆盖原权限），符号法适合「只增减某一项」。

### 5.3 目录权限含义不同（高频考点）

| 权限 | 对文件 | 对目录 |
|---|---|---|
| `r` | 读文件内容 | `ls` 能列出目录内容 |
| `w` | 修改文件内容 | 能在目录内新建 / 删除文件 |
| `x` | 执行（脚本 / 程序） | `cd` 能进入目录 |

**结论**：`cd` 依赖 `x`，`ls` 依赖 `r`，是两个独立权限。目录没有 `x` 就进不去，没有 `r` 就列不出内容——「能 cd 进去但 ls 报 Permission denied」正是缺 `r` 的典型症状。

### 5.4 sudo：临时借管理员权限

- Linux 的安全设计核心：**平时用普通用户，必要时 sudo 提权**，避免误操作毁掉系统。
- `sudo ls /root`：输入**自己**的密码即可临时获得 root 权限。
- `sudo` = "superuser do"。

`chown` 用于改文件属主（`chown user:group file`），同样需要 sudo——它只出现在「重点命令」清单里，源笔记未展开细节。

## 六、标准流、重定向与管道

### 6.1 每个进程自带三条流

| 流 | 编号 | 装什么 | 默认去向 |
|---|---|---|---|
| stdin | 0 | 输入 | 键盘 |
| stdout | 1 | 正常输出 | 屏幕 |
| stderr | 2 | 报错信息 | 屏幕 |

这就是「数据流思维」的底层：命令不是在「打印」，而是在往流里写；重定向和管道只是改变流的去向。

### 6.2 重定向与管道

| 写法 | 作用 |
|---|---|
| `> file` | 把 stdout **覆盖**写入文件（stderr 仍上屏幕） |
| `>> file` | 把 stdout **追加**到文件末尾 |
| `2> file` | 只把 stderr 写入文件 |
| `> file 2>&1` | stdout 和 stderr 都进同一个文件 |
| `\|` | 管道：左边命令的 stdout 变成右边命令的 stdin |

```bash
echo "hello" > hello.txt          # 覆盖（文件不存在则创建）
echo "world" >> hello.txt         # 追加
grep "ERROR" hello.txt | wc -l    # 过滤后统计行数
```

### 6.3 核心认知：`>` 只搬一根水管

`>` 只重定向 stdout，报错走 stderr，完全不受影响。

这解释了那个经典困惑：**「我已经重定向到文件了，为什么文件是空的、屏幕上还有报错？」**——因为出错信息从来没走 stdout。要一起收，必须写 `> log 2>&1`。

### 6.4 常见坑

从微信 / 网页 / Word 复制的命令，引号或 `--` 会变成中文全角标点，bash 直接不识别；提示符从 `$` 变 `>` 说明引号没闭合。`Ctrl+C` 退出重来，符号手敲。

## 七、进程与日志

### 7.1 进程是什么

- **程序** = 硬盘上的文件（死的）。
- **进程** = 程序在内存里跑起来的样子（活的）。
- 每个进程有 **PID**（唯一编号）和父进程；一台服务器同时跑几百个进程。

排障要回答的三个问题：现在什么在跑？谁把 CPU 吃满了？任务报错去哪看？

### 7.2 进程管理三板斧

| 命令 | 作用 | 要点 |
|---|---|---|
| `ps` | 看当前终端相关进程 | 只列出 bash 和 ps 自己 |
| `ps aux` | 看系统所有进程 | `a`=所有用户 `u`=详细信息 `x`=无终端的 |
| `ps aux \| grep xxx` | 过滤找某个进程 | 「进程在不在」的标准动作 |
| `top` | 实时刷新看负载 | 约 3 秒刷一次，按 `q` 退出 |
| `kill PID` | 发信号让进程退出 | 默认 SIGTERM（「请你退出」，进程可清理后退出） |
| `kill -9 PID` | 强制杀死 | SIGKILL，进程无法拦截，装死进程的最后手段 |
| `lsof` | 列出打开的文件 / 端口占用 | 排查「端口被谁占了」「文件被谁占着」 |

`ps aux` 关键列：`USER`（谁跑的）、`PID`（编号）、`%CPU`、`%MEM`、`COMMAND`（启动命令）。

`kill -9` 的代价：进程没机会保存状态、没机会释放资源，可能留下脏数据或占着不放的句柄，所以先 `kill` 再 `kill -9`。

### 7.3 看日志（排障主力）

日志是一个**不断增长的文件**，用 `cat` 会刷屏，改用这几个：

| 命令 | 作用 |
|---|---|
| `tail file` | 看末尾 10 行 |
| `tail -n 3 file` | 看末尾 3 行 |
| `head file` | 看开头 10 行 |
| `tail -f file` | **实时跟随**，新内容写入即刷出 |

`head` 的用处常被低估：看日志开头的启动信息（版本、配置、初始化是否成功），比末尾更能定位「为什么起不来」。

### 7.4 黄金组合拳

```bash
# 场景1：几万行日志里，只要最近的 10 条 ERROR
grep "ERROR" hello.txt | tail -n 10

# 场景2：盯着正在写的日志，只看 ERROR
tail -f hello.txt | grep "ERROR"
```

注意顺序差异：`grep ... | tail` 是「先全量过滤，再取最后 10 条」；`tail -f ... | grep` 是「持续跟随，边来边过滤」，用于实时监控。

### 7.5 标准排障姿势

**一个终端 `tail -f` 盯着日志，另一个终端跑任务 / 触发操作，实时看报错。** `Ctrl+C` 退出 `tail -f`。

这样能把「操作」和「报错」在时间上对齐，比事后翻日志快得多。

## 八、磁盘

磁盘满是最常见的线上故障之一，表现为：写文件失败、数据库拒绝写入、日志突然中断、进程莫名退出。

### 8.1 三个命令

| 命令 | 作用 | 要点 |
|---|---|---|
| `df -h` | 看整个磁盘分区用量 | `-h` 人类可读；盯 `Use%` 是否 100% |
| `du -sh 目录` | 看某目录总占用 | `-s` 只汇总不展开 `-h` 可读 |
| `find 路径 -size +10M` | 按大小找文件 | `+` 表示大于，用来抓「吃磁盘的元凶」 |

### 8.2 排障套路

```
df -h 看满没满 → du -sh 逐层下钻找谁占的 → 没权限就 sudo
```

`du` 要一层层往下钻（先 `/`，再 `/var`，再 `/var/log`…），因为 `-s` 只给总量。

### 8.3 识别磁盘

`df -h` 里挂载在 `/` 的 `/dev/sdX` 才是 Linux 真磁盘；`/mnt/c`、`/mnt/d` 是从 Windows 挂进来的盘，不是 Linux 自己的空间。

### 8.4 一个高频深题

**`df` 显示磁盘满了，但 `du` 扫不出任何大文件，为什么？**

因为文件被删除了，但仍有进程打开着它（例如 `tail -f` 正盯着这个日志）。Linux 的规则是「还有进程持有文件句柄就不真正释放空间」，所以 `du` 看不到它（目录项已删），`df` 仍算它占着。处理：找到并结束那个进程（或让它重新打开文件），空间才释放。

`free` 用于看内存使用（`free -h`），与磁盘排查常一起做——「机器卡」既可能是磁盘满，也可能是内存耗尽触发 swap。

## 九、后台运行与 nohup

| 写法 | 效果 |
|---|---|
| `cmd &` | 后台跑，但关终端会被杀（收到 SIGHUP） |
| `nohup cmd &` | 忽略 SIGHUP，关终端 / 断 SSH 也不停 |
| `cmd > log 2>&1 &` | 后台跑，输出全部进日志 |
| `nohup cmd > log 2>&1 &` | 服务器跑任务的标准姿势 |

### 9.1 原理

- 进程跑在内核里，**终端只是「遥控器」**。
- 关终端时，系统给该终端的所有子进程发 `SIGHUP`（hang up）信号，让它们退出。
- `nohup` = no hang up，让进程忽略这个信号。
- 终端退出后，这些进程变成孤儿进程，被 `init`（PID 1）收养，继续运行。

### 9.2 为什么必须配重定向

后台进程没有终端可写，stdout / stderr 要么被丢弃，要么写进 `nohup.out`。显式写 `> log 2>&1` 才能保证「出事有据可查」。

面试句：**任务用 `nohup` + `&` 后台运行，stdout/stderr 重定向到日志，再用 `tail -f` 监控。**

## 十、装软件与 Python 虚拟环境

### 10.1 包管理器 apt

```bash
sudo apt update          # 刷新软件清单（不等于安装/升级）
sudo apt install htop    # 安装某个包
```

心智模型：apt 从软件仓库拉包 → 自动解决依赖 → 装进 `/usr/bin` → 因为该路径在 `PATH` 里，直接敲命令名就能跑。

发行版差异：Ubuntu / Debian 用 `apt`，CentOS / RHEL 用 `yum`；Python 包统一用 `pip`。

### 10.2 为什么必须用虚拟环境

| 问题 | 说明 |
|---|---|
| 版本冲突 | 项目 A 要 pandas 1.5，项目 B 要 pandas 2.0 |
| 搞坏系统 Python | Ubuntu 自身依赖系统 Python，乱装包可能弄坏系统工具 |
| 权限 | 装到系统目录需要 root，普通用户装不了 |

### 10.3 venv 的原理（面试考点）

venv **不是复制一整个 Python**，而是：

- **软链接**到系统解释器：`.venv/bin/python3` → 系统 `python3`
- **独立的包目录**：`.venv/lib/...`

`source .venv/bin/activate` 的本质是**改 `PATH`**，让终端优先命中 `.venv/bin` 里的 `python` / `pip`；`deactivate` 就是改回去。

所以「虚拟环境」虚拟的是**包目录和 PATH**，不是解释器本体——这就是它几秒钟就能建好的原因。

### 10.4 完整流程

```bash
python3 -m venv .venv       # 建（Ubuntu 可能需先 sudo apt install python3.xx-venv）
source .venv/bin/activate   # 激活，提示符出现 (.venv)
which python3               # 确认指向 .venv/bin/python3
python3 -c "import sys; print(sys.prefix)"   # 更彻底：让 Python 自报家门
pip install xxx             # 装包 → 进 .venv/lib
deactivate                  # 退出
```

### 10.5 排障：确认「现在用的是哪个 Python」

三条互相印证：

1. 提示符有没有 `(.venv)`
2. `which python3` 指到哪
3. `sys.prefix` 是不是 `.venv` 路径

「明明激活了却还是报找不到包」，多半是用了 `sudo pip`（提权后 PATH 变了）或另一个终端没激活。

## 十一、vim 最小生存包

### 11.1 三种模式

```
普通模式（默认，按键即命令）
   --i-->  插入模式（打字）
   <--Esc--
   --:-->  命令行模式（保存、退出、查找替换）
```

### 11.2 必会按键

| 键 | 作用 |
|---|---|
| `i` / `Esc` | 进入编辑 / 回到普通模式 |
| `:wq` / `:q!` | 保存退出 / 不保存退出 |
| `dd` / `yy` / `p` / `u` | 删行 / 复制行 / 粘贴 / 撤销 |
| `gg` / `G` | 跳到文件开头 / 末尾 |
| `/关键词` + `n` | 查找 / 跳到下一个匹配 |

**逃生连招**：疯狂按 `Esc` → 输入 `:q!` → 回车。任何「卡住了」的情况都先回到普通模式再谈其他。

**改配置文件的标准动作**：`vim file` → `/` 定位到要改的行 → `i` 编辑 → `Esc` → `:wq`。

### 11.3 echo vs vim

| 场景 | 用什么 | 原因 |
|---|---|---|
| 追加一行 | `echo "..." >> file` | 可写进脚本、可自动化 |
| 精确修改某处 | vim | 能定位、能改、能看上下文 |

**配置文件**是纯文本的设置文件，程序启动时读取；改配置 ≠ 改代码，不需要重新编译，但通常需要重启服务或 `source` 才生效。

### 11.4 两个实战坑

**E325 swap 文件冲突**：上次 vim 异常退出（或还开着），目录里留下 `.xxx.swp`，再次编辑会提示 `E325: ATTENTION`。

处理：确认没有其他 vim 在编辑 → `kill <PID>` 杀掉残留进程 → `rm .xxx.swp`。

**nano 作为替代**：无模式，直接打字；保存 `Ctrl+O` 回车，退出 `Ctrl+X`。临时改一行配置时比 vim 更快。

## 十二、ssh 远程登录

### 12.1 三条命令

```bash
ssh user@host            # 密码登录
ssh-keygen -t ed25519    # 生成密钥对（私钥留本地！公钥可公开）
ssh-copy-id user@host    # 把公钥装到服务器 → 之后免密登录
```

`scp` 用于传文件，是最常用的「传文件」手段：`scp local.txt user@host:/home/user/`（上传）、`scp user@host:/path/file .`（下载）。

### 12.2 免密登录原理

1. 本地生成一对密钥：私钥（钥匙，**永远留在本机**）、公钥（锁，可以公开）。
2. 公钥被装到服务器的 `~/.ssh/authorized_keys`。
3. 登录时服务器用公钥「加密出一道题」，只有持有私钥的一方能解开，解开即证明身份。

多台设备 = `authorized_keys` 里多行公钥；一人离职删掉对应那一行即可，无需改密码。

### 12.3 换默认编辑器

```bash
echo 'export EDITOR=vim' >> ~/.bashrc && source ~/.bashrc
```

`~/.bashrc` 是 bash 每次启动都会读的配置文件，所以改完要 `source` 让当前终端立即生效。

## 十三、crontab 定时任务

### 13.1 时间格式

```
分 时 日 月 周   命令
```

五个字段，空格分隔，`*` 表示「每一个」。

```bash
*/2 * * * *     echo "hi" >> /tmp/x.log     # 每 2 分钟
0 2 * * *       /usr/bin/python3 job.py     # 每天凌晨 2 点
```

`*/2` 表示「每隔 2 个单位」，`0 2 * * *` 是「2 点 0 分」。

### 13.2 管理命令

| 命令 | 作用 |
|---|---|
| `crontab -e` | 编辑当前用户的定时任务 |
| `crontab -l` | 列出已有的定时任务 |
| `crontab -r` | 删除全部任务（**慎用，无确认**） |

### 13.3 最大的坑

**cron 的执行环境是「干净环境」，不会加载你的终端配置**（`.bashrc`、`PATH`、venv 激活状态都没有）。

因此：

- 命令一律写**绝对路径**：`/usr/bin/python3` 而不是 `python3`
- 脚本里的解释器、数据文件、日志路径都写绝对路径
- 需要虚拟环境时，用 `.venv/bin/python` 的绝对路径，而不是先 `activate`

「手动跑成功、定时跑失败」，90% 是环境变量和相对路径的问题。

## 十四、Shell 脚本

### 14.1 是什么

把多条 Linux 命令写进一个 `.sh` 文件，`./xxx.sh` 一次跑完。数据任务的「十步操作」（进目录 → 查数据 → 跑任务 → 查错 → 发邮件）全靠它串起来。

**数据工程师的本质工作就是自动化**，而 shell 是最底层、最通用的自动化手段。

### 14.2 最小结构

```bash
#!/bin/bash                 # 第一行固定：声明用 bash 解释
echo "任务开始"
date
echo "当前用户: $(whoami)"   # $(命令) = 执行该命令并取输出
```

```bash
chmod +x hello.sh    # 加执行权限
./hello.sh           # ./ 表示当前目录（当前目录不在 PATH 里）
```

两个细节：

- 不加 `chmod +x` 会报 `Permission denied`。
- 直接敲 `hello.sh` 会报 `command not found`，因为当前目录不在 `PATH` 中，必须写 `./`。

### 14.3 变量

```bash
NAME="ad_data"    # 定义：等号两边不能有空格
echo $NAME        # 使用：$ 取值
echo ${NAME}      # 加花括号可明确边界，如 ${NAME}_2026
```

**坑**：`NAME = "x"`（等号两边有空格）会报错——shell 会把 `NAME` 当成要执行的命令。

### 14.4 条件判断 if

```bash
if [ -f "data.csv" ]; then    # [ ] 内侧必须有空格
    echo "存在"
else
    echo "不存在"
    exit 1                    # 0=成功，1=失败
fi                            # if 倒过来写就是结束
```

**常用条件**：

| 条件 | 含义 |
|---|---|
| `-f 路径` | 是文件且存在 |
| `-d 路径` | 是目录且存在 |
| `-z "字符串"` | 字符串为空 |
| `!` | 取反，如 `[ ! -f "$1" ]` |

`[` 本质是一个命令，所以 `[` 后面、`]` 前面必须有空格；写 `[-f x]` 会报 `command not found`。

### 14.5 循环 for

```bash
for channel in Google TikTok YouTube; do
    echo "处理 $channel"
done
```

`do ... done` 是循环体边界，变量 `channel` 依次取列表里的每个值。

### 14.6 传参数

系统自动把「脚本名 + 参数」存进特殊变量，不用声明。

假设执行 `./run.sh google.csv 2026-01-01 extra`：

| 符号 | 值 | 含义 |
|---|---|---|
| `$0` | `./run.sh` | 脚本自己的名字（含路径） |
| `$1` | `google.csv` | 第 1 个参数 |
| `$2` | `2026-01-01` | 第 2 个参数 |
| `$3` | `extra` | 第 3 个参数 |
| `$#` | `3` | 参数**个数**（`#` 像数字） |
| `$@` | 三个参数，各自独立 | **标准答案**，日常都用它 |
| `$*` | 三个参数，合成一个字符串 | 了解即可 |
| `$?` | 上一条命令的退出码 | 0=成功，非 0=失败 |

记忆：`$0` 是脚本自己，`$1` 起才是参数；`$#` 带 `#` 是「个数」；`$@` 带 `@` 是「全部」。

**`$@` vs `$*`**：加引号时才见区别——`"$@"` 展开成多个独立参数，`"$*"` 合成一个大字符串。日常用 `$@`。

**传参的意义**：脚本复用。`wc -l "$1"` 一个脚本通吃所有文件，不用改脚本内容。

**坑**：参数变量几乎永远加双引号 `"$1"`，否则参数里含空格会被拆成多个。

### 14.7 真实脚本骨架：先校验再执行

```bash
#!/bin/bash
if [ -z "$1" ]; then
    echo "用法: $0 <文件路径>"
    exit 1
fi

DATA_FILE="$1"
if [ ! -f "$DATA_FILE" ]; then
    echo "错误: $DATA_FILE 不存在"
    exit 1
fi

echo "[$(date)] 开始处理 $DATA_FILE"
# 真实场景这里跑 python/spark
wc -l "$DATA_FILE"
echo "[$(date)] 完成"
```

骨架 = **校验参数 → 校验文件 → 执行 → 留日志**，这就是数据任务脚本的标准形态。`[$(date)]` 的时间戳让日志可追溯。

### 14.8 退出码 `$?`

`$?` 保存**上一条命令**的退出码：`0` 成功，非 `0` 失败。

```bash
python job.py
if [ $? -ne 0 ]; then
    echo "任务失败"
    exit 1
fi
```

注意：`$?` 只反映紧邻的上一条命令，中间插了 `echo` 就会被覆盖。

### 14.9 实操踩坑

| 现象 | 处理 |
|---|---|
| vim 卡住没退出，再次 vim 报 E325 swap 文件冲突 | `kill <PID>` 杀残留进程 + `rm .xxx.swp` |
| 需要快速改文件又不想学 vim | nano：`Ctrl+O` 回车保存、`Ctrl+X` 退出 |
| 复制粘贴脚本带入中文引号 | 在 Windows 侧写好，通过 `\\wsl.localhost` 放进 WSL（覆盖同名文件可能被权限拒绝，换新文件名） |

### 14.10 为什么数据工程离不开 Shell

数据管道 = Python + Spark + 数据库 + 各种工具，shell 脚本是最底层的「胶水」。Airflow 调度里，每个 Task 底层也常是一条 shell 命令。

进阶方向（按需补）：函数、数组、`&&` / `||` 逻辑、`case` 分支、错误处理 `set -e`。这些在源笔记中仅列出名称，未展开（源笔记未展开）。

## 十五、服务器、Web 服务与网络部署链

### 15.1 「服务器」有两个意思

| 意思 | 是什么 |
|---|---|
| 意思 1 | **一台电脑**（物理机器，有 IP） |
| 意思 2 | **一个提供服务的程序**（uvicorn、MySQL） |

混乱就来自这两个意思混用。「买一台服务器」说的是意思 1，「服务器挂了」往往说的是意思 2。

### 15.2 你跑 uvicorn，是「意思 2」

```
你的 Windows 电脑（一栋房子）
   └─ uvicorn 程序（房子里开的一家餐厅，挂 8000 号门牌）
   └─ MySQL     （同一栋房子另一家餐厅，挂 3306 号门牌）
```

**并没有虚拟出新房子，只是在自家房子里多开了几家餐厅（跑了几个服务器程序）。**

「虚拟一台电脑」是另一回事，那才是虚拟机 / Docker：

| | 你跑的 uvicorn | 虚拟机 / Docker |
|---|---|---|
| 是什么 | 一个**程序** | 真正虚拟出**隔离环境** |

区分方法：程序只是占了一个端口；虚拟机 / 容器有自己的文件系统、自己的进程空间、自己的「操作系统视角」。

### 15.3 Web 服务器是什么

**专门「接收 HTTP 请求、返回响应」的软件**（uvicorn 就是）。它像前台 / 收发员，管请求收发、端口、连接，**不负责业务逻辑**。

- Web 服务器（uvicorn / Nginx）管「收发」，FastAPI 代码管「业务」。
- 一个 Web 服务器可以承载多个 API。

### 15.4 Nginx：站在最前面的大门

标准部署链：

```
用户 → Nginx（大门：分发、加密、静态文件）→ uvicorn（业务）→ MySQL（数据）
```

四个核心作用：

| 作用 | 说明 |
|---|---|
| 反向代理 | 用户只认识 Nginx，后面的服务被隐藏 |
| 负载均衡 | 把请求分发给多台 uvicorn（分布式在 Web 层的落地） |
| 静态文件 | 图片 / CSS / JS 直接发，不经过 Python |
| HTTPS 加密 | 在 Nginx 层做加解密 |

Nginx vs uvicorn：Nginx 管「流量怎么进来、怎么分发」，uvicorn 管「业务逻辑」。

### 15.5 HTTPS：加密的 HTTP

**HTTPS = HTTP + SSL/TLS 加密。**

HTTP 是明文，链路上谁都能看、能改。HTTPS 把数据加密成乱码再传，解决两件事：**防偷看（机密性）+ 防篡改（完整性）**。

原理（大白话）：浏览器和服务器先商量出一把只有双方知道的「钥匙」，之后所有数据都用它加锁 / 开锁。

**HTTPS 通常在 Nginx 这层做**：Nginx 是大门、最靠近用户，业务代码就不用管加密了，这是职责分离。

### 15.6 VPN：加密隧道

VPN（虚拟专用网络）在你电脑和远程服务器之间建一条**加密隧道**：数据先加密，再经服务器**中转转发**。

路上的人既看不懂内容（加密），也看不到真实目标（中转）。它本来是企业的「安全远程访问」技术，底层思想 = HTTPS（加密）+ Nginx（反向代理 / 中转）的组合。

## 面试速查

- **Linux 和数据工程什么关系？** → 生存环境，所有大数据组件跑在 Linux 上；底线是登录 / 看日志 / 查进程 / 传文件 / 装软件五件事。
- **换 Linux 后 PySpark 还能用吗？** → 能，代码不变，只改文件路径和启动方式（代码跨平台）。
- **Linux 文件系统和 Windows 最大区别？** → 只有一个根 `/`，一切挂在这棵树下；Windows 的盘挂在 `/mnt/c`。
- **`/etc`、`/home`、`/tmp` 各放什么？** → 配置、用户家目录、临时文件。
- **`cd` 和 `ls` 分别依赖目录的哪个权限？** → `cd` 要 `x`，`ls` 要 `r`，两者独立。
- **`755` 和 `644` 分别是什么权限？** → 755：主人读写执行、其他人读执行；644：主人读写、其他人只读。
- **`600` 用在哪？** → 私钥等敏感文件，只有主人可读写。
- **`sudo` 是什么？** → superuser do，临时借管理员权限，输入自己的密码。
- **`>` 和 `>>` 的区别？** → 覆盖写入 / 追加到末尾。
- **重定向后文件为空但屏幕有报错，为什么？** → `>` 只搬 stdout，报错走 stderr；要一起收需 `> log 2>&1`。
- **管道 `|` 做了什么？** → 把左边命令的 stdout 接到右边命令的 stdin。
- **怎么在几万行日志里找最近的 ERROR？** → `grep "ERROR" app.log | tail -n 10`。
- **怎么实时盯日志？** → `tail -f app.log`，可再接 `| grep "ERROR"`。
- **进程和程序的区别？** → 程序是硬盘上的文件，进程是它在内存里运行的状态，有 PID。
- **`ps aux` 里 a/u/x 各什么意思？** → 所有用户的、详细信息的、无终端的进程。
- **`kill` 和 `kill -9` 的区别？** → 前者发 SIGTERM 请进程自行退出，后者发 SIGKILL 强杀、进程无法拦截。
- **磁盘满了怎么查？** → `df -h` 看分区，再 `du -sh` 逐层下钻定位目录。
- **`df` 满了但 `du` 找不到大文件，为什么？** → 文件已删但仍有进程持有句柄，空间未释放，需结束该进程。
- **`&` 和 `nohup` 的区别？** → `&` 只是后台，关终端仍会被 SIGHUP 杀掉；`nohup` 忽略 SIGHUP，断开也不停。
- **服务器上跑长任务的标准写法？** → `nohup cmd > log 2>&1 &`，再 `tail -f log` 监控。
- **venv 是复制了一整个 Python 吗？** → 不是，软链接系统解释器 + 独立包目录，`activate` 本质是改 PATH。
- **怎么确认当前用的是虚拟环境的 Python？** → 看提示符 `(.venv)`、`which python3`、`sys.prefix`。
- **vim 卡住了怎么退出？** → 连按 `Esc` 回普通模式，再 `:q!` 不保存退出。
- **E325 swap 冲突怎么处理？** → 确认无其他 vim 在编辑，`kill` 残留进程后删掉 `.xxx.swp`。
- **ssh 免密登录的原理？** → 公钥放服务器 `authorized_keys`，登录时服务器用公钥出题，私钥解题证明身份。
- **`crontab` 五个字段是什么？** → 分、时、日、月、周。
- **为什么 cron 里的命令要写绝对路径？** → cron 环境不加载 `.bashrc` 和 PATH，写相对命令会找不到。
- **脚本为什么要 `chmod +x` 和 `./`？** → 需要执行权限；当前目录不在 PATH 中，必须显式指定路径。
- **Shell 里 `$0` `$1` `$#` `$@` 分别是什么？** → 脚本名、第 1 个参数、参数个数、全部参数。
- **`$@` 和 `$*` 的区别？** → 加引号时 `"$@"` 每个参数独立，`"$*"` 合成一个字符串。
- **`$?` 是什么？** → 上一条命令的退出码，0 成功、非 0 失败。
- **脚本变量赋值为什么不能有空格？** → `NAME = "x"` 会被当成执行 `NAME` 命令，必须 `NAME="x"`。
- **`[ -f x ]` 里的空格为什么不能省？** → `[` 是命令，缺空格会被当成命令名的一部分。
- **服务器是「虚拟电脑」吗？** → 不是，跑 uvicorn 只是在本机开了个占端口的程序；虚拟环境要 Docker / 虚拟机。
- **Nginx 的四个作用？** → 反向代理、负载均衡、静态文件、HTTPS 加密。
- **HTTPS 解决了什么？** → HTTP + SSL/TLS，防偷看、防篡改。
- **VPN 的原理？** → 加密隧道 + 中转转发，隐藏内容和真实目标。
