# 神经网络原理

本篇覆盖：神经网络作为"带参数的函数"的本质、训练四步循环与 batch / epoch 概念、万能逼近定理与非线性激活的必要性、损失函数的选择、反向传播与梯度、优化器与学习率、过拟合与正则化（L1/L2/Dropout/早停/数据增强）与偏差-方差权衡、梯度消失与爆炸、权重初始化与 BatchNorm、如何决定层数与单元数的方法论、超参搜索的自动化，以及"什么任务该训模型、什么任务规则就够了"的选型判断。

主线是一句话：**模型是一个形状固定、参数未定的函数；训练是在损失函数的指引下，用梯度把参数一点点挪到让预测最准的位置；而能不能训、该不该训，取决于任务形态与数据量，而不是技术时髦度。**

## 一、模型是什么：一堆参数组成的函数

### 1.1 本质定义

**神经网络 = 一个带参数的函数 `f(x, W)`。**

- `x` 是输入（一组数字）。
- `W` 是一堆参数（也是数字，可能几百万到几千亿个）。
- `f` 是固定的计算规则：矩阵乘法 + 激活函数，层层堆叠。

它不"回答文字"，它**算一个数字**。回答文字的是 LLM，但 LLM 底层也是这堆东西堆出来的。

**训练 = 调 `W`，让 `f` 的预测越来越接近标准答案。**

### 1.2 怎么判断"学会了"

模型不像 LLM 那样能看答案对不对，判断标准只有一个：**看 loss 下降**。

- loss 一路往下掉、最后稳定在接近 0 → 参数调对了。
- loss 不降、震荡、变 `nan` → 训练有问题（学习率、量纲、初始化、数据）。

这也是训练时必须打印 loss 曲线的原因——它是唯一的过程信号。

### 1.3 人只控制三样东西

很多人以为要"设计每个神经元的函数"，完全不是。人只指定：

| 控制项 | 怎么设 |
|---|---|
| ① 输入长什么样 | 几个数字、什么含义（如曝光量、出价） |
| ② 输出长什么样 | 几个数字、什么含义（如 1 个转化量） |
| ③ 损失函数 | 回归用 MSE，分类用交叉熵——是"选"不是"写" |

**每个单元内部的函数是固定的**，全网络统一：

```
out = 激活( w1*x1 + w2*x2 + ... + wn*xn + b )
```

- 中间层统一用 **ReLU**（`max(0, x)`），选一下即可。
- 输出层按任务选：预测数值不用激活（或线性），二分类用 Sigmoid，多分类用 Softmax。

### 1.4 关键认知：不是告诉规则，是给例子

模型不是"人把规则写进去"，而是"人只给输入 → 输出的成对例子，它自己猜出规则，记进 W 里"。

这也是它和规则系统的根本区别：规则系统是人总结规律，模型是从样本里拟合规律。

### 1.5 PyTorch 是什么

**PyTorch = 带"自动求梯度 + 自动调参 + GPU 加速"的超级 numpy。**

手写版最痛苦的是手推梯度（例如线性回归的 `grad_w = 2 * (y_pred - y_true) * x`），PyTorch 里只要两行：

```python
loss.backward()     # 自动算出所有参数的梯度
optimizer.step()    # 自动按学习率更新参数
```

- **地位**：AI 技术栈的中间层。上层是具体模型（GPT / BERT / bge-m3），底层是硬件 + numpy，PyTorch 夹在中间负责训练。
- Meta 于 2016 年发布，目前是学界和工业界的主流框架。
- 常见误区：**PyTorch 是框架，不是模型**。模型是 GPT / BERT 那些具体网络结构。

最小训练片段：

```python
import torch
from torch import nn

model = nn.Sequential(nn.Linear(2, 16), nn.ReLU(), nn.Linear(16, 1))
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.MSELoss()

for xb, yb in dataloader:
    pred = model(xb)
    loss = loss_fn(pred, yb)
    opt.zero_grad()      # 清空上一轮梯度，否则会累加
    loss.backward()      # 反向传播求梯度
    opt.step()           # 更新参数
```

`opt.zero_grad()` 是必写的一行：PyTorch 的梯度默认累加，不清零会让这一步用上历史梯度。

## 二、训练四步循环与数据喂法

### 2.1 四步循环

```
① 前向传播  喂数据，算出预测值 y_pred = f(x, W)
② 算损失    loss = 预测 与 标准答案 差多少
③ 反向传播  算出"每个参数该往哪调、调多少"（梯度）
④ 更新参数  W = W - 学习率 × 梯度
        ↓ 回到 ①，重复几万次
```

这四个步骤循环成千上万次，就是训练。

### 2.2 三个数据单位

| 术语 | 含义 |
|---|---|
| batch size | 一次喂几条（常见 32 / 64 / 128） |
| iteration | 喂一批、调一次参数 |
| epoch | 把全部数据**完整喂一遍** |

例：1 万条数据、batch = 32 → 一个 epoch = 313 次迭代；训练 100 个 epoch = 反复喂 100 遍。

### 2.3 为什么按批喂，不一条条喂

1. **GPU 并行算得快**：一条数据喂进去，GPU 大部分核心闲着。
2. **梯度更稳**：一批的平均梯度比单条样本的梯度噪声小。
3. **内存放得下**：全量一次性喂会 OOM，batch 是精度与显存的折中。

batch size 的影响：太小 → 梯度噪声大、训练抖；太大 → 泛化可能变差、显存吃紧。它是超参数之一。

## 三、万能逼近定理：为什么神经网络能近似任意函数

### 3.1 定理说什么

**只要神经元够多 + 每个神经元后加一个"能拐弯"的非线性激活函数，这堆东西拼起来，就能以任意精度逼近任何连续函数。**

面试版表述：**至少一层隐藏层 + 足够多神经元 + 非多项式激活函数 → 能以任意精度逼近任意连续函数。** 记"非线性 + 足够多 = 万能"即可。

### 3.2 直觉

像用积木拼任意形状：每个神经元是一个开关，无数个开关各管一小段，拼起来能拼出任何弯弯绕绕的形状。像素点足够多能拼出任何图，神经元足够多能拼出任何函数曲线。

更具体一点：一个神经元配合 ReLU 可以造出一个"折角"（两段直线），足够多的折角首尾相接，就能用折线逼近任意曲线——折点越密，误差越小。

### 3.3 为什么必须要有非线性激活（少一个都不行）

推理链（面试可以一口气讲）：

1. 神经元先做加权求和（线性变换）。
2. **线性套线性还是线性**：`W2(W1x + b1) + b2 = (W2W1)x + (W2b1 + b2)`，仍然是 `Ax + b`。
3. 所以如果全是线性层，100 层等价于 1 层，深度毫无意义，只能表达直线 / 平面。
4. 必须加非线性激活"掰弯"，层数越多能表达的形状越复杂 → 这才是"深度"的意义。

结论：**没有非线性，再深也只是一个大线性回归。**

### 3.4 常用激活函数

| 激活 | 公式 | 特点 | 用在哪 |
|---|---|---|---|
| ReLU | `max(0, x)` | 计算简单；正区间导数恒 1，不衰减梯度；负区间输出 0 | 隐藏层默认首选 |
| Sigmoid | `1 / (1 + e^-x)` | 压到 0~1；两端饱和、导数最大只有 0.25 | 二分类输出层 |
| Tanh | `(e^x - e^-x)/(e^x + e^-x)` | 压到 -1~1，零中心；同样会饱和 | 早期隐藏层 |
| Softmax | `e^zi / Σe^zj` | 转成概率分布，和为 1 | 多分类输出层 |
| Leaky ReLU / GELU | — | 负区间保留小梯度 / 平滑版 ReLU | 现代网络、Transformer |

### 3.5 定理的边界（重要，容易被追问）

万能逼近定理只保证**存在**一组参数能逼近目标函数，它**不保证**：

- 用梯度下降一定能找到这组参数（优化问题可能很难）。
- 找到的参数在新数据上一定好（泛化问题）。
- 需要多少神经元是可计算的（定理是存在性证明，不给数量）。

所以"万能"是理论下限保证，实际效果仍取决于数据、初始化、正则化和训练技巧。

## 四、损失函数：训练到底在优化什么

### 4.1 一句话

损失函数是一把"尺子"，量"模型现在错得有多离谱"；**训练的唯一目标就是不断调参，让尺子读数越来越小**。

### 4.2 两类任务对应两种损失

| 任务 | 损失函数 | 理解 |
|---|---|---|
| 回归（预测收入 / 价格 / 转化量） | MSE 均方误差 | 预测值与真实值差多少，平方后平均 |
| 分类（判流失 / 破产 / 点击与否） | 交叉熵（Cross-Entropy） | 模型"猜错的置信度"有多大 |

公式：

```
MSE      = (1/n) * Σ (y_pred - y_true)^2
交叉熵   = -Σ y_true * log(y_pred)          # 配合 Softmax
```

### 4.3 分类为什么不用 MSE（常考）

- MSE 配合 Sigmoid / Softmax 时，梯度里会带上激活函数的导数，而饱和区导数接近 0 → **梯度消失、收敛极慢**。
- 交叉熵的梯度形式是 `y_pred - y_true`，**错得越离谱，梯度越大，改得越狠**，收敛快。
- MSE 隐含假设误差是高斯分布，适合回归；分类的输出是概率分布，用交叉熵（等价于最小化两个分布的 KL 散度）更匹配。

### 4.4 和数据工作的关系

造特征、清洗、样本平衡（如 SMOTE）最终都是为了让损失函数更顺畅地降下去：

- 特征量纲差太大 → 损失曲面狭长 → 难优化（见第八节实战踩坑）。
- 类别极度不平衡 → 模型全预测多数类，loss 很低但没学到东西 → 需要重采样或改损失权重。
- 标签噪声 → loss 降不下去，或者模型去拟合错误标签。

## 五、反向传播：参数怎么被"教会"

### 5.1 一句话

先算总损失（算账），再从输出层往回走，算出每个参数"贡献了多少责任"，按责任大小去调它。

### 5.2 直觉

像项目失败后的责任追溯：输出层负责 60%、隐层某几个神经元 30%、其他 10%……**责任大的多改，责任小的少改**。

数学上就是**链式法则**：复合函数求导时，外层导数乘以内层导数，一层层往回传。

### 5.3 梯度是什么

梯度是损失对某个参数的偏导 `∂loss/∂w`，含义是：**w 增大一点点，loss 会变化多少**。

- 梯度为正 → 增大 w 会让 loss 变大 → 应该减小 w。
- 梯度为负 → 增大 w 会让 loss 变小 → 应该增大 w。

所以更新公式是减号：

```
W_new = W_old - learning_rate * gradient
```

### 5.4 手写版长什么样

以一个最简单的线性单元 `y_pred = w*x + b`、损失 `MSE = (y_pred - y_true)^2` 为例：

```python
grad_w = 2 * (y_pred - y_true) * x
grad_b = 2 * (y_pred - y_true)
w -= lr * grad_w
b -= lr * grad_b
```

网络一深、层数一多，手工推导会爆炸——这就是需要 PyTorch 自动微分（`loss.backward()`）的原因。

### 5.5 计算图与自动微分

- 前向传播时，框架记录每个运算的依赖关系，形成计算图。
- 反向传播时，从 loss 出发沿图反向应用链式法则，得到每个参数的梯度。
- 这也是"动态图"框架（PyTorch）灵活的原因：图是运行时建的，可以写任意 Python 控制流。

数据工程师不需要手推公式，但要能讲清"梯度是责任分摊、链式法则是分摊工具"。

## 六、优化器与学习率

### 6.1 分工

反向传播算出"每个参数该往哪调"，但**每次调多大、用什么策略**，由优化器决定。

类比：开车下山找最低点（损失最小处）。

| 优化器 | 类比 | 特点 |
|---|---|---|
| SGD（随机梯度下降） | 每步朝当前最陡方向走 | 简单、内存省；易绕路、震荡，对学习率敏感 |
| Momentum | 带惯性下坡 | 累积历史方向，抑制震荡、冲过小坑 |
| Adam | 记惯性 + 自适应步长 | 一阶矩（动量）+ 二阶矩（梯度平方）结合，每个参数有自己的步长；默认首选，又快又稳 |

补充两点：

- **Adam 并非永远最好**：在部分视觉任务上精调的 SGD + Momentum 泛化更好；Adam 的权重衰减实现有坑，现代做法用 AdamW（解耦权重衰减）。
- **优化器不改变模型表达能力**，只影响收敛速度和最终落点。

### 6.2 学习率：最重要的超参数

`W = W - 学习率 × 梯度`，学习率就是那个步长。

| 情况 | 后果 |
|---|---|
| 太小（如 1e-7） | 碎步，训练慢得吓人，可能停在半路 |
| 太大（如 10） | 步子乱跳，来回震荡甚至**发散（loss 变 nan）** |
| 合适（如 0.01 / 0.001） | 稳稳收敛 |

学习率是超参数，**由人设定**，定错训练直接废——新手最常见的坑。

### 6.3 学习率调度

流行做法是"先大步快走、后小步精调"：

- **Warmup**：训练初期从很小线性升到目标值，避免一开始梯度爆炸 / 参数被带偏（Transformer 训练标配）。
- **Decay**：后期按余弦、阶梯或指数衰减，帮助收敛到更平的极小值。
- **ReduceLROnPlateau**：验证集 loss 不降时自动降学习率。

### 6.4 调学习率的实操顺序

1. 先用 `1e-3`（Adam）或 `1e-2`（SGD）试跑几十个 step。
2. 看 loss：不降 → 调大 10 倍；变 `nan` / 剧烈震荡 → 调小 10 倍。
3. 找到能稳定下降的量级后，再在附近做对数网格搜索（`3e-4, 1e-3, 3e-3`）。
4. 数据量、batch size 变了要重新调：batch 变大通常可以适当调大学习率。

## 七、过拟合与正则化

### 7.1 过拟合是什么

训练数据考 99 分，新数据就垮——不是学会规律，而是**死记硬背训练数据**（把噪声也学进去了）。

类比：考前把答案背下来，换题就不会；真正理解规律，换题也会。

三种状态：

| 状态 | 表现 | 原因 |
|---|---|---|
| 欠拟合 | 训练集 loss 都下不去 | 模型太简单 / 特征不足 / 训练不够 |
| 刚好 | 训练集和验证集都好，差距小 | 容量与数据匹配 |
| 过拟合 | 训练集极好，验证集差 | 模型容量过大 / 数据太少 / 训练过久 |

判断依据永远是**训练集与验证集的表现差距**，不是单看训练 loss。

### 7.2 训练集 / 验证集 / 测试集

| 集合 | 用途 |
|---|---|
| 训练集 | 更新参数 |
| 验证集 | 选超参、决定何时早停 |
| 测试集 | 最终评估，只能看一次 |

用测试集调参等于偷看答案，最终指标会虚高。

### 7.3 防过拟合的武器

| 方法 | 一句话 | 类比 |
|---|---|---|
| L2 正则化 | 惩罚权重太大，别走极端 | 逼答案别走极端 |
| L1 正则化 | 惩罚权重绝对值，把无用特征权重压到 0 | 逼模型只保留重点 |
| Dropout | 训练时随机关掉一部分神经元 | 考试随机划掉一半知识点，逼学整体规律 |
| 早停 | 验证集损失不再降就停 | 复习到位就交卷 |
| 更多数据 / 数据增强 | 数据够大没法背，只能学规律 | 题库够大就没法背答案 |
| 减小模型 | 降低容量 | 别用大炮打蚊子 |

### 7.4 L1 与 L2

```
L1: loss_total = loss + λ * Σ|w|
L2: loss_total = loss + λ * Σw²
```

| | L1 | L2 |
|---|---|---|
| 惩罚对象 | 权重绝对值 | 权重平方 |
| 效果 | 稀疏解，很多权重变成 0 → 自带特征选择 | 权重整体变小、更平滑，不会精确为 0 |
| 别名 | Lasso | Ridge / 权重衰减（weight decay） |
| 适用 | 特征多、想要稀疏 | 默认首选，防过拟合 |

`λ` 是正则化强度：太大 → 欠拟合（权重被压得太狠）；太小 → 没效果。它也是超参数。

### 7.5 Dropout

- **训练时**：每个神经元以概率 `p` 被随机置零，强制网络不依赖某几个特定神经元。
- **推理时**：关闭 Dropout，所有神经元都参与。
- **缩放**：现代实现用 inverted dropout，训练时把保留的神经元乘 `1/(1-p)`，保证训练和推理的期望输出一致，推理时无需再缩放。
- 典型值 `p = 0.1 ~ 0.5`；放在全连接层后，卷积层较少用。

常考题："Dropout 是干嘛的？"——训练时随机丢弃一部分神经元，强制网络不依赖某几个特定神经元，提升泛化、防过拟合。它是**训练时的技巧，推理时不生效**。

### 7.6 早停

- 每个 epoch 在验证集上评估，记录最好的模型权重。
- 验证 loss 连续 `patience` 个 epoch 不下降就停止训练，回滚到最优 checkpoint。
- 本质是一种"用训练时间换正则化"的手段，零额外计算成本，性价比很高。

### 7.7 数据增强

- 图像：翻转、裁剪、旋转、颜色抖动、Mixup、CutMix。
- 文本：同义替换、回译、随机删除。
- 表格：SMOTE 过采样、加噪声、特征组合。

核心逻辑：**让模型见不到两张完全一样的样本，就没法靠背答案过关。**

### 7.8 偏差-方差权衡

泛化误差可以拆成三部分：

```
总误差 = 偏差² + 方差 + 不可约噪声
```

| | 偏差（Bias） | 方差（Variance） |
|---|---|---|
| 含义 | 模型假设与真实规律的偏离 | 模型对训练集扰动的敏感度 |
| 表现 | 训练集、验证集都差（欠拟合） | 训练集好、验证集差（过拟合） |
| 解法 | 加容量、加特征、减正则 | 加数据、加正则、减容量、集成 |

**权衡**：模型越复杂，偏差越低、方差越高。最优容量在两者交叉点附近。

这也解释了为什么"加深加宽"不是万能药：容量上去后偏差降了，方差可能涨得更快。

### 7.9 实战踩坑：量纲导致 loss 发散

用曝光 + 出价预测转化时：

1. **第一次跑 loss 直接爆炸成 `nan`**——曝光量数值上万、出价只有 1~10，特征量纲差太大，梯度巨大导致发散。
2. **解决：特征归一化**（把所有特征缩放到 0~1 或标准化到均值 0、方差 1）。归一化后 loss 从 1.13 稳稳降到 0.04。

结论：**学习率 / 量纲不对 → 发散**。归一化是 AI 工程每天做的基础操作，不是可选项。

## 八、梯度消失与梯度爆炸

### 8.1 原因

反向传播是"误差一层层往回乘"（链式法则连乘）：

- 每层乘一个小于 1 的数 → 传到前面几乎为 0 → **梯度消失**，浅层学不动。
- 每层乘一个大于 1 的数 → 指数放大 → **梯度爆炸**，参数乱跳、loss 变 `nan`。

类比：传话游戏，传 100 个人后要么面目全非（消失），要么无限放大（爆炸）。

### 8.2 为什么 Sigmoid 容易消失

Sigmoid 的导数最大值只有 0.25，且在两端饱和区接近 0。多层连乘 `0.25^n`，10 层就衰减到百万分之一。

### 8.3 解法

| 问题 | 解法 | 原理 |
|---|---|---|
| 梯度消失 | **ReLU** | 正区间导数恒为 1，连乘不衰减 |
| 梯度消失 | **残差连接（ResNet）** | `y = x + F(x)`，梯度有一条恒等通路直接回传 |
| 梯度消失 | **BatchNorm / LayerNorm** | 把每层输入归一化，避免落到饱和区 |
| 梯度消失 | **合理初始化**（Xavier / He） | 让每层方差稳定，不指数衰减 |
| 梯度消失 | **门控结构**（LSTM / GRU） | 用门控制信息保留长度 |
| 梯度爆炸 | **梯度裁剪** | `clip_grad_norm_(params, max_norm=1.0)`，超过阈值就等比缩小 |
| 梯度爆炸 | **归一化输入 + 调小学习率** | 从源头减小梯度量级 |

梯度裁剪代码：

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

注意裁剪要放在 `backward()` 之后、`step()` 之前。

## 九、权重初始化与 BatchNorm

### 9.1 权重初始化

**不能全设 0，也不能乱设。**

- **全 0**：同一层的所有神经元输出完全相同，梯度也相同，更新后仍然相同 → 对称性无法打破，等于只有一个神经元。
- **全设同一个常数**：同样对称失效。
- **太小**（如 0.01 倍标准正态）：信号逐层缩小 → 消失。
- **太大**：信号逐层放大 → 爆炸。

常用方案：

| 方法 | 适用激活 | 方差设置 |
|---|---|---|
| Xavier / Glorot | Tanh、Sigmoid | `2 / (fan_in + fan_out)` |
| He / Kaiming | ReLU 及其变体 | `2 / fan_in` |

框架默认已经处理好（`nn.Linear` 用 Kaiming 均匀初始化），一般不用手写，但要知道它在解决"信号稳定传递"。

### 9.2 BatchNorm

**把每层输出归一到标准范围（均值 0、方差 1），再做一次可学习的缩放和平移。**

作用：

- 训练更稳，缓解梯度消失 / 爆炸。
- 可用更大的学习率。
- 自带一点正则化效果（每个 batch 的统计量有噪声）。
- 对初始化不那么敏感。

两个易错点：

- **训练和推理行为不同**：训练用当前 batch 的均值和方差；推理用训练期累积的滑动平均。忘了切换 `model.eval()` 会导致结果不稳定。
- **batch 太小时统计量不准**：batch size 为 1 或 2 时 BN 效果差，此时改用 LayerNorm / GroupNorm。
- **位置**：通常在 `Linear` / `Conv` 之后、激活之前（也有放到激活之后的变体）。

BatchNorm 按特征维度统计（跨样本），LayerNorm 按单个样本的所有特征统计——后者不依赖 batch，所以 Transformer 用 LayerNorm。

### 9.3 优先级

| 优先级 | 知识点 | 为什么 |
|---|---|---|
| 高 | 过拟合 + 正则化 | 数据岗最高频，跟样本平衡经历挂钩 |
| 高 | 优化器 + 学习率 | 必考"怎么调学习率" |
| 中 | 梯度消失 / 爆炸 + ReLU | 常和激活函数一起问 |
| 低 | 权重初始化 / BatchNorm | 知道在解决什么即可 |

## 十、一开始怎么决定搭几层、几个单元

### 10.1 核心认知：不是算出来的

**一开始并不知道，也不靠"算"，靠"默认值 + 试"。**

没有人能从任务描述推导出"应该 3 层、每层 128"。业界做法是：从一个合理的小网络起步，根据训练曲线的信号调整。层数和宽度是**超参数**，不是设计出来的常量。

### 10.2 起手配置

| 任务 | 起手配置 |
|---|---|
| 表格数据（广告预测、流失预测） | 2~4 层全连接，单元 32 / 64 / 128 |
| 图像 | 不自己搭，直接拿 ResNet / EfficientNet 等预训练模型微调 |
| 文本 | 不自己搭，直接用 BERT / GPT 等，层数由论文定死 |

**能从零搭的只有表格数据**；图像和文本的成熟结构是多年搜索的结果，重新发明没有意义。

### 10.3 从简单 baseline 起步

正确的顺序：

```
规则 / 均值基线 → 逻辑回归 / 线性回归 → 树模型（XGBoost / LightGBM） → 神经网络
```

理由：

1. **先知道"及格线"在哪**。如果 XGBoost 已经做到 AUC 0.85，神经网络做到 0.86 才值得上；做到 0.80 说明方向错了。
2. **表格数据上树模型常常打赢神经网络**，尤其是样本量几万到几十万、特征异构的场景。
3. **baseline 提供错误分析的对象**：看哪些样本错，比盲调层数有用得多。

神经网络的优势在**高维、稠密、有空间 / 序列结构**的数据（图像、文本、音频），以及**数据量极大**时。

### 10.4 由数据规模和任务复杂度决定

| 信号 | 调整方向 |
|---|---|
| 样本量小（几千条以内） | 浅（1~2 层）、窄（16~64）、强正则，或干脆用树模型 |
| 样本量大（百万级以上） | 可以加深加宽，容量不足会成为瓶颈 |
| 任务简单（近似线性） | 1 层隐藏层足够，甚至不用隐藏层 |
| 任务复杂（强非线性、交互多） | 加深；但表格数据通常 3~4 层就到顶 |
| 输入维度高（几百上千特征） | 第一层宽度要够，或先做特征选择 / 降维 |
| 输出维度高（多分类几百类） | 最后一层宽度 = 类别数，前面的容量也要相应增加 |

第一层和最后一层的宽度是**被数据决定的**：

- 第一层输入维度 = 特征数。
- 最后一层输出维度 = 1（回归 / 二分类）或类别数（多分类）。

中间层才是自由的。

### 10.5 参数量怎么估

一层全连接的参数量 = `输入维度 × 输出维度 + 输出维度`（偏置）。

例：10 维输入 → 64 → 64 → 1

```
10*64 + 64 = 704
64*64 + 64 = 4160
64*1  + 1  = 65
合计 ≈ 4929 个参数
```

用途：判断模型相对样本量是否过大。经验上参数量接近或超过样本量时，过拟合风险很高，需要强正则或减容量。

### 10.6 判断信号比记数字更重要

- **欠拟合**（搭小了）：训练集 loss 都下不去 → 加大加深、加特征、训练更久。
- **过拟合**（搭大了）：训练集 loss 极低、验证集一遇新数据就崩 → 减小容量、加 Dropout / L2、加数据。

先看信号，再动结构。盲目加深是最常见的无效操作。

### 10.7 调参顺序（性价比从高到低）

1. **数据质量与特征**：量纲归一化、缺失处理、类别编码。收益最大。
2. **学习率**：唯一能让训练从"完全不收敛"变成"收敛"的参数。
3. **正则化强度**（Dropout、weight decay）：控制过拟合。
4. **batch size**：影响训练稳定性和速度。
5. **层数 / 宽度**：最后调，收益递减。

很多人反过来，一上来就堆层数，结果调了一周不如做一次归一化。

### 10.8 调参是写代码自动搜，不是手拧

红线认知：**"调参"不是人一个个试，是写循环让程序搜。**

人负责定义搜索空间和评估指标，机器负责跑组合。下一节展开。

## 十一、调参自动化

### 11.1 三种搜索策略

| 方法 | 做法 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 网格搜索（Grid Search） | 每个超参取固定几个值，做笛卡尔积全组合 | 简单、可复现、易并行 | 维度灾难：5 个参数各 5 个值 = 3125 次；很多组合在无效区域浪费 | 参数 ≤ 3 个、空间小 |
| 随机搜索（Random Search） | 从分布里随机采样若干组 | 同样预算下覆盖更广；高维时显著优于网格 | 不利用历史结果；可能重复采到差区域 | 默认首选，维度中等 |
| 贝叶斯优化（Bayesian Optimization） | 用已试结果建代理模型（高斯过程 / TPE），选"最有希望"的下一个点 | 样本效率高，适合单次训练很贵的场景 | 串行、实现复杂、高维效果下降 | 训练成本高、预算有限 |

**为什么随机搜索常打赢网格搜索**：真正起作用的往往只有 2~3 个超参，其余维度是"平坦"的。网格搜索在无关维度上浪费了大量组合；随机搜索让每个重要维度获得更多不同取值。

### 11.2 搜索空间怎么定

- 学习率：**对数均匀**采样（`1e-5 ~ 1e-1`），不是线性。
- 层数：`1 ~ 4` 的整数。
- 单元数：`{32, 64, 128, 256}`，按 2 的幂。
- Dropout：`0 ~ 0.5` 均匀。
- weight decay：对数均匀 `1e-6 ~ 1e-2`。
- batch size：`{32, 64, 128, 256}`，受显存限制。

### 11.3 早停剪枝：省预算的关键

不要等每个组合跑完才比较。用 Hyperband / ASHA 这类策略：先让所有组合跑少量 epoch，表现差的直接砍掉，只把预算留给有希望的。

Optuna 的 `MedianPruner` 就是这个思路。

### 11.4 最小可运行示例（Optuna）

```python
import optuna

def objective(trial):
    n_layers = trial.suggest_int("n_layers", 1, 4)
    lr = trial.suggest_float("lr", 1e-5, 1e-2, log=True)
    dropout = trial.suggest_float("dropout", 0.0, 0.5)

    dims = [trial.suggest_categorical(f"units_{i}", [32, 64, 128, 256])
            for i in range(n_layers)]

    model = build_model(dims, dropout)
    for epoch in range(50):
        train_one_epoch(model, lr)
        val_loss = evaluate(model)
        trial.report(val_loss, epoch)
        if trial.should_prune():          # 表现差就提前终止
            raise optuna.TrialPruned()
    return val_loss

study = optuna.create_study(direction="minimize")
study.optimize(objective, n_trials=50)
print(study.best_params)
```

sklearn 场景更简单：

```python
from sklearn.model_selection import RandomizedSearchCV
search = RandomizedSearchCV(model, param_distributions, n_iter=50, cv=3, n_jobs=-1)
search.fit(X, y)
```

### 11.5 自动化的边界

- **搜索空间决定上限**：人没想到的取值，机器也搜不到。
- **评估指标要选对**：类别不平衡时用 F1 / AUC，不要用 accuracy。
- **算力是硬约束**：50 次试验 × 每次 1 小时 = 两天，先想清楚值不值。
- **别在测试集上搜**：只能看验证集，测试集留到最后。

## 十二、什么任务适合用模型，什么任务规则就够了

### 12.1 两条判断轴

**能不能模型化，看两条：① 输出是不是"唯一确定的一个数"；② 数据量够不够大。**

```
                    数据量少 ←──────────→ 数据量大
输出单一 ↑          [规则 / 统计]        [✓ 训模型]
输出不唯一 ↓        [LLM + 工具 + 知识库] [LLM 生成式]
```

| 象限 | 做法 | 例子 |
|---|---|---|
| 输出单一 + 数据多 | 训模型 | 出价、CTR 预估、推荐排序、图像识别 |
| 输出不唯一 + 数据少 | LLM + 工具 + 知识库 | 广告优化决策 |
| 输出单一 + 数据少 | 传统统计 / 规则（阈值判断） | 小样本风控规则 |
| 输出不唯一 + 数据多 | LLM 生成式 | 写文案、对话、总结 |

### 12.2 为什么优化决策不适合训神经网络

理由里最本质的**不是"输入类型杂"，而是"输出不唯一 + 数据少"**：

- **输出不唯一**：同一个广告表现差，正确答案可能是"降价"、可能是"换素材"、可能是"换渠道"——**没有唯一标准答案**。模型要学的是"唯一的一个数"，学不了"决策"。
- **数据量少**：行业经验、业务突发只有几十到几百条样本，喂不饱神经网络。

注意："输入类型杂"其实不是障碍——图像识别输入是几百万像素照样训。真正死穴是**输出不唯一 + 数据少**。

### 12.3 广告实时出价（RTB）为什么适合模型、又为什么不用神经网络

场景：用户打开 App 要展示广告位，平台在**几十毫秒内**做一次拍卖，几十家广告主同时报价。模型要回答：

> "这个用户值不值得出 5 块钱买下这次展示？"

- **为什么适合模型化**：输出单一（预估收益 eCPM 一个数）+ 数据海量（每秒百万级请求）。
- **为什么不用神经网络**：要快（几十毫秒）、要便宜（每笔请求都算）。实际多用 XGBoost / 逻辑回归这类传统 ML，特征工程 + 树模型在这个场景性价比最高。

### 12.4 完整选型决策

| 数据量 | 做法 | 典型场景 |
|---|---|---|
| 极少（几十 ~ 几百条） | LLM + 工具 + 知识库 | 投放优化中台（Agent + 知识库） |
| 中间（万 ~ 十万） | 传统 ML（XGBoost / 逻辑回归） | 财务困境预测、流失预测 |
| 海量（百万以上） | 训 / 微调模型（树模型或神经网络） | 广告出价、CTR、推荐排序 |

### 12.5 LLM 的两个硬伤

1. **贵 + 慢**：每问一次调 API、要几秒；训练好的 XGBoost 预测一次是微秒级、几乎免费。广告出价每秒几万次，不可能每笔问 LLM。
2. **不精确**：LLM 是"预测下一个词"，不是"算精确到 0.001 的数"。

这两点决定了 LLM 不能替代训练模型，只能补它不擅长的部分（理解意图、组织语言、处理非结构化输入）。

### 12.6 什么时候规则就够了

规则 / 阈值系统并非落后，以下场景反而更优：

| 场景 | 为什么规则更好 |
|---|---|
| 逻辑明确可枚举（如"余额 < 0 则拒绝"） | 模型学不出比规则更准的东西，还增加成本 |
| 需要可解释、可审计（合规、风控） | 规则能逐条说明原因，模型只能给概率 |
| 样本极少或没有历史标签 | 无从训练 |
| 零容错（资损、安全） | 规则能保证边界，模型输出不可控 |
| 业务规则频繁变 | 改一行配置比重新训练快 |

工程上常见**规则兜底 + 模型排序**的混合架构：规则负责硬约束（黑名单、预算上限），模型负责在合法集合里做最优选择。

### 12.7 一句话结论

> **能不能训模型取决于数据量，要不要用 LLM 取决于任务形态。**
> 数据少用 LLM + 工具 + 知识库，数据多且要实时精确的用训模型，中间的用传统 ML。

### 12.8 三条红线

- 别把"训练神经网络"说成"需要几十万条才起步"——数据量小应该用传统 ML 或 LLM。
- 别把 PyTorch 说成"模型"——PyTorch 是框架，模型是 GPT / BERT 那些。
- 别以为"调参"是人手动拧——参数更新是 `backward()` + `step()` 自动完成的，人只定学习率等超参数。

## 十三、面试速查

**Q：神经网络本质是什么？**
A：一个带参数的函数 `f(x, W)`，结构固定、参数靠训练确定；它算的是数字，不是文字。

**Q：怎么判断模型训练好了？**
A：看 loss 是否稳定下降并收敛到接近 0；同时看训练集与验证集的差距判断是否过拟合。

**Q：训练的四步循环？**
A：前向传播算预测 → 算损失 → 反向传播求梯度 → 优化器更新参数，循环往复。

**Q：batch、iteration、epoch 的区别？**
A：batch 是一次喂的样本数；iteration 是喂一批并更新一次参数；epoch 是把全量数据完整过一遍。

**Q：为什么按 batch 训练？**
A：GPU 并行效率高、批平均梯度更稳、内存可控。

**Q：万能逼近定理怎么说？**
A：一层隐藏层 + 足够多神经元 + 非线性激活，就能以任意精度逼近任意连续函数。

**Q：为什么必须用非线性激活？**
A：线性套线性仍是线性，100 层等价于 1 层；非线性才能让深度带来表达能力。

**Q：万能逼近定理有什么局限？**
A：只保证存在性，不保证梯度下降能找到、不保证泛化好、也不给出需要多少神经元。

**Q：回归和分类分别用什么损失？**
A：回归用 MSE；分类用交叉熵（配 Softmax / Sigmoid）。

**Q：分类为什么不用 MSE？**
A：MSE 配合饱和激活会梯度消失、收敛慢；交叉熵梯度形式为 `y_pred - y_true`，错得越狠改得越狠。

**Q：反向传播是什么？**
A：从 loss 出发，用链式法则逐层回传，算出每个参数对损失的偏导（梯度），即"责任分摊"。

**Q：参数更新公式？**
A：`W = W - learning_rate * gradient`。

**Q：SGD、Momentum、Adam 的区别？**
A：SGD 每步沿当前梯度走；Momentum 累积历史方向抑制震荡；Adam 同时用一阶矩和二阶矩，为每个参数自适应调整步长。

**Q：学习率太大或太小会怎样？**
A：太大震荡甚至发散（loss 变 nan）；太小收敛极慢甚至训不动。合适值通常 1e-3 量级（Adam）。

**Q：什么是学习率调度？**
A：训练过程动态调整学习率，如 warmup 先升、后期余弦衰减，兼顾稳定与精细收敛。

**Q：过拟合的表现和本质？**
A：训练集表现极好、验证集明显变差；本质是记住了训练数据的噪声而非规律。

**Q：防过拟合有哪些手段？**
A：L1/L2 正则、Dropout、早停、更多数据 / 数据增强、减小模型容量。

**Q：L1 和 L2 的区别？**
A：L1 惩罚绝对值，产生稀疏解可做特征选择；L2 惩罚平方，让权重整体变小更平滑。

**Q：Dropout 的原理？**
A：训练时以概率 p 随机置零神经元并缩放，逼网络不依赖特定神经元；推理时关闭。

**Q：早停怎么做？**
A：监控验证集 loss，连续若干 epoch 不下降就停止，并回滚到最优 checkpoint。

**Q：偏差和方差分别对应什么？**
A：高偏差 = 欠拟合（训练验证都差）；高方差 = 过拟合（训练好验证差）。总误差 = 偏差² + 方差 + 噪声。

**Q：梯度消失的原因？**
A：反向传播是连乘，激活函数导数小于 1（Sigmoid 最大 0.25）时逐层衰减到接近 0。

**Q：梯度爆炸的原因和解法？**
A：连乘大于 1 导致指数放大；解法是梯度裁剪、归一化输入、调小学习率、合理初始化。

**Q：解决梯度消失有哪些方法？**
A：ReLU、残差连接、BatchNorm / LayerNorm、Xavier / He 初始化、门控结构（LSTM）。

**Q：为什么权重不能全初始化为 0？**
A：同层神经元输出和梯度完全相同，对称性无法打破，等价于只有一个神经元。

**Q：Xavier 和 He 初始化的区别？**
A：Xavier 方差按 `2/(fan_in+fan_out)`，适合 tanh / sigmoid；He 按 `2/fan_in`，适合 ReLU。

**Q：BatchNorm 的作用？**
A：把每层输出归一化到均值 0 方差 1，稳定训练、缓解梯度问题、允许更大学习率，并带一点正则化。

**Q：BatchNorm 训练和推理有什么区别？**
A：训练用当前 batch 统计量，推理用训练期累积的滑动平均；忘记 `model.eval()` 会导致结果不稳。

**Q：一开始怎么定几层几单元？**
A：算不出来，靠默认值加试：表格数据从 2~4 层、32/64/128 起步；图像文本直接用预训练模型；再根据欠拟合 / 过拟合信号调整。

**Q：为什么不要一上来就搭深层网络？**
A：应先有简单 baseline 作为及格线；表格数据上树模型常更强，深层网络收益低、过拟合风险高、调参成本大。

**Q：调参为什么要自动化？**
A：超参组合爆炸，人工试效率极低；写循环让程序按搜索策略跑，人只定义空间和指标。

**Q：网格搜索、随机搜索、贝叶斯优化的区别？**
A：网格是全组合、简单但维度灾难；随机采样覆盖更广、高维更优；贝叶斯用历史结果建代理模型选下一个点，样本效率最高但实现复杂。

**Q：学习率为什么用对数均匀采样？**
A：学习率的影响是数量级级别的（1e-4 与 1e-3 差异巨大），线性采样会集中在过大区间。

**Q：什么任务适合训模型？**
A：输出单一确定 + 数据量足够大，例如 CTR 预估、出价、推荐排序。

**Q：什么任务不适合训模型？**
A：输出不唯一（没有标准答案的决策）、数据量只有几十到几百条的场景。

**Q：广告优化决策为什么用 LLM + 工具而不是训模型？**
A：同一问题可能有降价 / 换素材 / 换渠道多个正确答案，且样本只有几十条，模型学不了"决策"。

**Q："输入类型杂"是不训模型的理由吗？**
A：不是。图像输入是几百万像素照样能训；真正理由是输出不唯一 + 数据少。

**Q：LLM 为什么不能替代训练模型？**
A：贵且慢（秒级 vs 微秒级）、不精确（概率续写不是精确计算），高并发实时场景扛不住。

**Q：什么时候规则比模型好？**
A：逻辑明确可枚举、需要可解释可审计、样本极少、零容错、规则频繁变更的场景。
