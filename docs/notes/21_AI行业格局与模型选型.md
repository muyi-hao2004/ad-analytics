## 一、先看格局：两条不同的路线

一句话概括 2026 年的中美模型竞争：

> **美国定义天花板，中国把天花板变便宜。**

| 维度 | 美国 | 中国 |
|---|---|---|
| 定位 | 前沿能力探索（最高分） | 效率与落地（同水平最低成本） |
| 代表 | GPT 系列、Claude 系列、Gemini 系列 | DeepSeek、Qwen、Kimi、GLM、混元 |
| 优势 | 算力、资本、人才、先发 | 算法效率、工程优化、开源、场景数据 |
| 开源意愿 | 头部以闭源为主（Meta 例外但节奏放缓） | **开源是主流策略** |
| 商业逻辑 | 卖能力溢价 | 卖性价比、抢生态位 |

**为什么头部几乎都在美国**：三个先发优势叠加——① Transformer 等基础架构由美国机构提出并有长期积累；② 高端算力供给（受出口管制影响，反而强化了先发者的存量优势）；③ 风险资本愿意为长期不确定的技术下注。

**为什么差距看起来很小**：因为「追赶」比「开创」便宜得多。架构是公开的、论文是公开的、开源权重是公开的，后来者不需要重新摸索方向，只需要在已知方向上做工程优化。**效率路线的边际收益，在追赶阶段远高于探索路线。**

## 二、DeepSeek V4.1-Flash 与「代际反超」

2026 年 10 月，DeepSeek 发布 V4.1-Flash-1017。

具体技术细节以官方为准，但**现象本身值得记住**：

> **Flash 是「廉价代际」，能力却超过了上一代的 Pro。**

这叫**代际反超**——不是同代内的性价比取舍，而是新一代的「低配版」打赢了老一代的「高配版」。

### 为什么会出现代际反超

| 原因 | 说明 |
|---|---|
| 架构效率进步快于参数堆叠 | 同样的能力，用更少的激活参数就能达到 |
| MoE 成熟 | 总参数大、激活参数小，推理成本大幅下降 |
| 训练数据质量提升 | 数据配比比单纯堆量更有效 |
| 推理优化（KV Cache 压缩等） | 单位 token 的显存和算力开销下降 |
| 蒸馏与后训练 | 用强模型产出高质量数据训小模型 |

**这个现象的行业含义**：参数规模不再是能力的主要解释变量。**「用了多少参数」正在让位于「每块钱能买到多少能力」。**

> 对使用者的直接影响：不要默认「贵的更强」。上一代旗舰往往在新一代中端发布后，性价比瞬间崩塌。

## 三、Kimi K3 与「蒸馏 Claude」争议

### 3.1 事件脉络

2026 年，Kimi K3 发布后，社区出现一种说法：K3 是通过**蒸馏 Anthropic 的 Claude** 训练出来的。争议中的「CC」指的就是 Claude。

流传的「证据」主要有两类：

1. **模型自称是 Claude**——被问到身份时，K3 偶尔回答自己是 Claude。
2. **输出分布的相似性**——有分析指出 K3 在某些任务上的输出分布与 Claude 高度接近（交叉熵异常低）。

### 3.2 这些证据成立吗

**不成立，或者说不构成实锤。**

| 证据 | 问题 |
|---|---|
| 自称 Claude | 训练数据里混入了 Claude 的对话语料，模型就会学到「我是 Claude」这个说法。这只说明**数据来源**，不说明**蒸馏** |
| 输出分布相似 | 蒸馏、共用训练数据、相同架构 + 相同对齐方法，都会导致分布接近。这是**必要不充分条件** |
| 权重水印 | 业界没有公认的、鲁棒的模型水印方案。没有水印就无法做所有权证明 |

**关键事实**：如果只用 API 输出做蒸馏，得到的是「行为模仿」，不是「权重复制」。前者在法律和技术的定性上都模糊得多。

### 3.3 蒸馏到底是什么

**定义**：用一个强模型（老师）的输出，去训练另一个模型（学生）。

#### 为什么蒸馏有效：软标签比硬标签信息量大

```
硬标签（人工标注）：这张图是「猫」        → 只有 1 bit：是/不是
软标签（老师输出）：猫 0.85 / 狗 0.10 / 豹 0.05 → 携带了「猫和狗、豹长得像」的信息
```

老师输出的**概率分布**里，包含了它学到的「类别之间的相似关系」，这部分叫**暗知识（dark knowledge）**。学生学分布，比学 one-hot 标签能获得更多信息，所以用更少的参数就能达到接近的效果。

#### 温度参数 T

```
softmax(z_i / T)
```

- `T = 1`：正常输出，分布尖锐
- `T > 1`：分布变平缓，**暗知识更明显**（小概率类别的差异被放大）

蒸馏时通常用较高的 T 让学生看到完整的分布结构，再用 T=1 做正常任务。

#### MOPD：多教师同策略蒸馏

多个老师模型，用统一的策略把它们的输出整合起来教一个学生。好处是可以融合不同老师的优势（比如一个擅长推理、一个擅长写作），代价是要处理老师之间的冲突。

### 3.4 怎么理性看待这类争议

- 蒸馏在业界是**公开且普遍**的做法，很多「小模型很强」的背后都有蒸馏
- 但「蒸馏」和「抄权重」是两件事，法律与技术的定性完全不同
- 社区证据（自称身份、分布相似）**只能提示，不能定案**
- 判断一家公司是否真有能力，看的是**它能否持续迭代**，而不是某一代模型像谁

> 面试如果被问到，标准答法是：「蒸馏是常规手段，软标签比硬标签信息量大；但用自称身份或分布相似来判断蒸馏，证据链是不完整的，因为共用数据、相同对齐方法也会导致分布接近。」

## 四、开源格局：谁在开源，为什么

### 4.1 现状

| 阵营 | 态度 | 代表 |
|---|---|---|
| 中国厂商 | 主力开源 | DeepSeek、Qwen、Kimi、GLM 等（多为开放权重） |
| 美国头部 | 闭源为主 | GPT / Claude / Gemini |
| 美国开源派 | 仍在但节奏放缓 | Meta Llama 系列 |

### 4.2 为什么中国厂商更愿意开源

1. **抢生态位**：闭源打不过先发者，开源可以把开发者拉到自己这边
2. **降低信任成本**：权重公开 = 可审计，企业客户更放心私有化部署
3. **商业化路径不同**：不靠卖 token，靠卖云服务、私有化部署、行业方案
4. **工程红利可复用**：开源带来社区反馈和优化，反哺下一代

### 4.3 开源有没有实质威胁到美国

**分层看，答案是「部分领域是，整体还不是」。**

| 层次 | 判断 |
|---|---|
| 能力天花板 | 尚未超越，前沿能力仍由美国定义 |
| 成本结构 | **已被显著冲击**——开源权重把「同水平能力」的价格锚点打下来了 |
| 生态话语权 | 部分侵蚀——开发者社区大量转向开放权重 |
| 商业模式 | 冲击闭源 API 的定价权，但不摧毁其高端市场 |

**一句话**：开源威胁的不是「美国能不能做出最强模型」，而是「美国能不能继续靠最强模型收高价」。

## 五、MoE 与推理成本：为什么便宜得下来

### 5.1 MoE（混合专家）

```
总参数 100B，但每个 token 只激活其中 10B
```

- 模型里有多组「专家」网络，加一个**路由器**决定每个 token 走哪几个专家
- 好处：**参数量大 = 知识容量大；激活参数小 = 推理便宜**
- 代价：显存占用仍按总参数算（所有专家都得加载）、训练时要做负载均衡（否则专家饿的饿死、撑的撑死）

**这解释了一个常见困惑**：为什么有些模型「参数很大但跑起来很便宜」——因为贵的是总参数的显存，便宜的是每 token 的算力。

### 5.2 KV Cache 压缩

推理时，已生成的 token 的 Key/Value 要缓存下来复用，否则每生成一个字都要重算前面所有内容。

- 代价：显存。序列越长，KV Cache 越大
- 压缩手段：量化（FP16 → FP8 → **FP4**）、MQA / GQA（多个 Query 头共享一组 KV 头）、PagedAttention（分页管理，减少碎片）

**FP4 级别的 KV Cache 压缩，是「长上下文 + 低成本」能同时成立的关键技术之一。**

### 5.3 量化

| 精度 | 显存 | 能力损失 |
|---|---|---|
| FP16 / BF16 | 基准 | 无 |
| FP8 | 约一半 | 很小 |
| FP4 | 约四分之一 | 需专门训练或校准 |

量化省的是显存和带宽，不是算力峰值——但在**显存带宽受限**的解码阶段，省带宽就是提速。

## 六、模型选型方法论

### 6.1 四个维度，不要只看「最强」

| 维度 | 要问的问题 |
|---|---|
| **能力** | 在我的任务类型上够不够（不是通用榜单排名） |
| **价格** | 输入 / 输出 / 缓存命中 分别多少钱 |
| **上下文** | 窗口多大，长文档能不能塞下 |
| **延迟与稳定性** | 首 token 多久、并发扛不扛得住、会不会挂起 |

### 6.2 选型顺序（实操）

```
1. 先用便宜且够用的，跑通链路
2. 用真实任务集做小规模 A/B，而不是看榜单
3. 只在「明确不达标」的环节升级到更贵的模型
4. 分级路由：简单判断用便宜模型，复杂推理用贵模型
```

### 6.3 一个常见误区

> **「贵的模型效果更好，所以直接上最贵的。」**

错在两处：① 同一代内，贵通常只对应「更强一点」，不是数量级的差异；② 跨代时，新一代的中端往往打赢老一代的旗舰（代际反超）。**所以选型必须按「当前可选项」比较，不能按「Pro/Flash」这种名字判断。**

### 6.4 成本优化的正确顺序

```
1. 减少无效输入（快照只给结论、精简工具描述）  ← 收益最大
2. 命中缓存（固定前缀放最前）                  ← 通常 10 倍级折扣
3. 减少往返轮次（合并工具调用）                ← 倍数级
4. 降低输出长度（约束格式）                    ← 一般
5. 换便宜模型                                  ← 最后考虑，可能影响质量
```

详见 18 篇《上下文工程与成本优化》。

## 七、WorkBuddy 内的模型选择经验

> 这一节是**具体工具的使用经验**，不是行业判断，换平台不适用。

| 场景 | 建议 |
|---|---|
| 复杂推理、代码审查、长文档分析 | 用旗舰（如 DeepSeek V4-Pro 一类） |
| 日常问答、格式整理、批量小任务 | 用 Flash 一类的中端，性价比高一个数量级 |
| 需要极强中文写作 | 看当时可用的国产模型表现 |

**踩过的坑**：长期用 Pro 做日常任务，成本是 Flash 的好几倍，而这类任务上质量差异几乎感知不到。

**判断规则**：如果你无法在一次回答里指出「贵模型比便宜模型好在哪」，那就应该用便宜的。

另外需要澄清一个常见误读：某个模型在**某个工具里**被称为「最强」，只代表在该工具的可用列表里最强，**不等于国内最强或全球最强**。

## 八、怎么持续跟踪

| 渠道 | 看什么 |
|---|---|
| 官方博客 / 发布说明 | 版本号、上下文长度、价格表 |
| 价格页 | 真正的成本结构（输入/输出/缓存是否分开计价） |
| 独立评测（LMArena 等） | 人类偏好排名，注意有刷榜可能 |
| 自己的任务集 | **最可靠**——固定 20 条真实任务，新模型出来就跑一遍 |

**最重要的一条**：建一个自己的小评测集。榜单衡量的是通用能力，你的任务只关心你的场景。

## 九、面试速查

- **为什么头部模型多在美国？** → 架构先发、算力存量、资本愿意为长周期下注。
- **为什么差距小？** → 追赶比开创便宜，架构/论文/权重公开，效率路线边际收益高。
- **中美竞争的本质区别？** → 美国定义天花板，中国把天花板变便宜。
- **什么是代际反超？** → 新一代中端打赢老一代旗舰，说明架构效率进步快于参数堆叠。
- **蒸馏为什么有效？** → 老师输出的概率分布携带类别相似性（暗知识），比 one-hot 标签信息量大。
- **温度 T 的作用？** → T 越大分布越平缓，暗知识越明显。
- **蒸馏和抄权重的区别？** → 蒸馏只模仿行为，抄权重是复制参数，法律定性完全不同。
- **K3 蒸馏 Claude 是实锤吗？** → 不是。自称身份只说明训练数据来源，分布相似也可能来自共用数据或相同对齐方法。
- **MoE 为什么便宜？** → 总参数决定容量，激活参数决定算力，每 token 只走少数专家。
- **KV Cache 压缩的意义？** → 长上下文与低成本能同时成立。
- **开源威胁到美国了吗？** → 没威胁到能力天花板，但冲击了价格锚点和生态话语权。
- **怎么选模型？** → 能力/价格/上下文/延迟四维，用自己的任务集测，不要看名字判断。
- **成本优化第一步是什么？** → 减少无效输入，不是换模型。
