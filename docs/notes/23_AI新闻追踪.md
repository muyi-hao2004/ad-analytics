## 〇、这一篇怎么用

### 0.1 与 21 篇的分工：一个数仓类比

| 层 | 对应文件 | 特点 | 生命周期 |
|---|---|---|---|
| **ODS / DWD（明细）** | **本篇** | 单条新闻、带日期、未聚合、会过期 | 月级，可删可改 |
| **ADS（结论）** | 21 篇《AI 行业格局与模型选型》 | 判断框架、去时间标记、长期有效 | 年级 |

**规则：新闻先进本篇，攒够了、验证过了，再把结构性判断搬进 21 篇。**

不要直接往 21 篇里写新闻，否则框架会被时效性污染——半年后那一篇就没人看了。反过来，也不要把判断留在本篇，否则每次都要翻一堆过期条目才能找到结论。

这也是为什么本篇的结构是「分桶 + 倒序」，而不是「按天流水账」：**按主题分桶，旧条目可以整行删掉，不影响结构。**

### 0.2 什么值得记：四问筛选

一条新闻要不要写进来，问四个问题，**一条都不中就跳过**：

1. 三个月后这条还成立吗？（价格、榜单排名 → 不记；结构性变化 → 记）
2. 它会改变我的技术选型吗？
3. 它会改变我项目的成本结构吗？
4. 我能在面试里用 30 秒把它说清吗？

用这个标准，10 月这半个月真正值得记的大概 20 条，而实际发生的事件有上百条。**信息不是越多越好，能形成判断的才叫信息。**

### 0.3 记录格式：一条一行

```
| 日期 | 事件 | 实质 | 影响 |
```

- **实质**：写「它到底是什么」，不写「它发布了」（「发布了 X 模型」没有任何信息量）
- **影响**：写「对我意味着什么」，不写「行业意义重大」（这是空话）
- 一条 30 秒能写完。写不完说明还没想清楚，先别记。

### 0.4 维护节奏

| 频率 | 动作 |
|---|---|
| 每周 15 分钟 | 扫官方 changelog，挑 1 条真正影响项目的写进来 |
| 每月 1 号 | 删掉已被后续事件覆盖的行（模型淘汰、价格作废） |
| 每季度 | 整篇压缩一次，只留还在影响判断的；结构性结论搬进 21 篇 |

### 2.2 两个容易误读的细节

**① Gemini 4 Argon 的「100 万」是输出上限，不是上下文窗口。**

这两件事经常被混为一谈：

- **上下文窗口**：一次能塞进去多少输入
- **输出上限**：一次能生成长度多长

Argon 的 100 万是后者。这确实是突破（上一代是 6.4 万），但它不解决「文档太长塞不进去」的问题。看到「100 万 token」先问是哪一种。

**② Haiku 5.5 换了新分词器，降价的收益被部分抵消。**

单价降 75%，但同一个任务消耗的 token 比上一代多。官方只说「降低运行成本约 75%」，没给统一的实际节省数字，也主动交代了这个技术变化。

**这就是为什么「单价降 X%」不能直接乘出账单降 X%。** 分词器、思考模式的默认开关、工具调用的轮数，任何一个变了，端到端成本都会跟你算的不一样。

### 3.2 单价降，但总账单在涨

这是 2026 年最反直觉的一条：

```
token 单价  ↓↓↓
token 消耗量 ↑↑↑↑↑     ← 涨得更快
────────────────
端到端账单  ↑
```

**为什么消耗量涨得更快**：

| 原因 | 机制 |
|---|---|
| Agent 是多轮的 | 一次任务 5-15 轮，每轮都要重发历史 |
| 上下文在变长 | 1M 窗口一开，很多人就把整份文档塞进去 |
| 缓存命中不等于免费 | 缓存价通常是输入价的 1/10，不是 0；命中率再高，量大也可观 |
| 思考模式默认打开 | DeepSeek 的 thinking 默认开，简单编辑任务也可能烧满输出上限 |

**实测例子**（2026-10-09，同一 prompt，1,024 输出上限）：

```
thinking off → 89 个输出 token，出结果
thinking on  → 1,024 个 token 全被推理吃掉，一个字都没输出
```

**对做项目的人的直接含义**：**成本优化的主战场永远是「减少无效 token」，不是「换便宜模型」。** 这个结论 18 篇《上下文工程与成本优化》里已经推过一遍，现在有了行业侧的预测数据支撑——不是我个人偏好，是趋势。

### 3.3 「任务成本」和「每百万 token 价格」是两回事

阶跃 Step 5 的宣传是「单任务成本是 Claude Opus 5 的八分之一」。

**注意，这不是「每百万 token 便宜八倍」，是「完成同一个任务的总花费是八分之一」。**

两者差别很大：

| 说法 | 含义 | 能不能直接比 |
|---|---|---|
| 每百万 token $0.15 | 价目表 | 只能比单价 |
| 单任务成本 1/8 | 端到端实测，含 token 数、轮数、重试 | 更接近真实账单，但依赖任务类型 |

同样的现象在 Sonnet 5.5（单价不变、任务成本 −30%）和 Haiku 5.5（降价被分词器抵消）上都出现过。

**结论：价目表已经不足以做选型了。** 唯一可靠的做法是自己固定 20 条真实任务，新模型出来跑一遍，比「完成任务的总成本 + 正确率」。这就是 21 篇说的 eval set，现在有更强的理由。

### 3.4 检索层被 API 化：$0.75 / 千次调用

10-17 DeepSeek 开放 Search / Fetch 两个 API，单价 $0.75 / 千次，10 月底前免费。

**换算一下才知道这个价意味着什么**：

```
$0.75 / 1000 次 = $0.00075 / 次
一个 Agent 每天 1 万次检索 → $7.5 / 天 ≈ $225 / 月
同量级的 token 成本        → 通常高一个数量级
```

**对 RAG 项目是一个真实的取舍**：

| 方案 | 成本 | 优点 | 缺点 |
|---|---|---|---|
| 自建（爬虫 + 向量库 + 清洗） | 人力成本为主，API 基本免费 | 数据源可控、可按垂类优化 | 索引会腐坏，要持续维护 |
| 直接调 Search API | 按次计费，量小几乎无感 | 免维护，覆盖全网 | 数据源不可控，垂类召回差 |

**这正好是他项目里「平台抽象层」那个设计的价值所在**：检索器做成可插拔的，自建和托管两条路都能接。**不是预判对了，是这个抽象本身就必须有**——因为这条线半年内变了两次（先向量库自建热，现在托管 API 打到这个价）。

**但也别急着换**。他的广告投放场景里，检索对象是**内部指标口径和历史报表**，本来就不在公网上。**自建仍然是对的选择**——托管检索解决的是「全网信息」，不是「我的私有数据」。

**这就是区分「新技术能不能用」和「我的场景需不需要」的典型例子。** 面试里能讲清这个区别，比会说十个数出来强。

### 4.3 三档推理强度正在变成标配

Kimi K3.1 的 Low / High / Max，Claude Haiku 5.5 的可调性能档位，DeepSeek 的 thinking on/off——三家独立做了同一件事。

**背后的逻辑**：长上下文「能处理」已经不是差异点，**「这件事值得花多少算力」才是**。以前是一个模型一个价，现在是同一个模型按任务难度分档计价。

**对 Agent 项目的直接用法**：

```
意图识别 / 参数抽取 / 格式整理  → 低档或关掉 thinking
多步规划 / 取舍判断             → 高档
```

这比「简单任务换便宜模型」更细一层——**同一个模型内部就能做成本路由**，不用维护两套 prompt。

### 5.2 昇腾这条线为什么重要

单看「开源几个编译工具」没什么感觉，放在一起才看得出意图：

```
CUDA 生态 = 编译器 + 计算库 + 通信库 + 大量调优经验
昇腾要能用 = 必须把这三层补齐，且开发者不用改代码
```

DeepSeek 把面向昇腾的**全套**组件开源，等于把「在国产卡上跑大模型」的开发体验对齐 CUDA。加上自购 16 万颗芯片，这是**软件栈层面的去单一依赖**，不是采购层面的。

**对求职者的含义**：国产算力生态的工程岗位会持续增加，而且这些岗位要的是「懂分布式训练 + 懂编译/通信」的人，不是「会调 API」的人。这是一个和他现在技能栈有距离、但方向明确的口子。

### 5.3 开源竞争的维度变了

以前比「能力差多少分」，现在比「同样任务省多少」。阶跃直接用「单任务成本 1/8」做宣传口径，这是个标志性变化——**开源不再只是「便宜的替代品」，而是拿成本当主武器。**

## 八、G 桶｜训练数据

> 这一桶和前六桶性质不同。前六桶回答「行业在发生什么」，这一桶回答**「我这类岗位的需求在怎么变」**。所以他看新闻的优先级也是反的：前六桶扫标题，这一桶逐条细看。

### 8.1 记录

| 10 月中 | 科技日报：高质量数据成硬通货 | 通用网页数据的增量红利基本吃完；专业领域数据供给不足；低质合成数据反复训练导致**模型坍缩** | 见 8.2 |
| 10-16 | NVIDIA × AI4Bharat：`Nemotron-pretraining-Indic-v1` | 2.8T token / 22 种印度语；2,601B 原生文字 + 224.6B 罗马化文本；**完整生成 pipeline 全开放**（NeMo Data Designer） | 见 8.3，目前能看到的最完整的公开训练数据工程案例 |

### 8.2 「模型坍缩」是这一桶的核心风险词

不筛选地把模型自己生成的内容喂回去训练，会发生什么：

```
第 1 代：训练集 = 真实数据 + 模型生成数据（比例 9:1）
第 2 代：训练集 = 上一代模型输出 → 罕见模式消失
第 3 代：分布收窄到「最安全的那些说法」→ 输出平均化
```

**表现不是「变傻」，是「变平庸」**——语法正确、逻辑通顺、但没有任何具体信息。这个现象有个更朴素的解释：模型输出的分布比真实数据的分布窄，反复自我喂养等于反复做「分布取交集」。

所以「可控合成」里的**可控**两个字是关键词。它至少要包含三件事：

| 要求 | 具体做法 |
|---|---|
| 真实数据锚定 | 合成数据只能占一定比例，且必须和真实数据混合训练 |
| 配比控制 | 每种任务类型、每种难度、每种语言各占多少，要显式设计 |
| 质量过滤 | 每条合成样本都要过一道评分闸门，不达标就丢或回炉 |

**对他的直接含义**：做训练数据这一行，核心技能不是「会写 Spark 清洗」，而是**能定义「什么叫一条好样本」，并且能证明这个定义是对的**。前者靠业务理解，后者靠评估方法论。

这一点上他其实有真实资产：ML 论文做的就是「四个模型对比 + SMOTE 重采样 + SHAP 解释 + AUC 评估」。**那套流程搬到数据质量评估上是同构的**——只是把「评估模型」换成「评估数据集」。

### 8.3 Indic pipeline 拆解：一个完整可复现的案例

这条新闻的价值不在「2.8 万亿 token」这个数字，在于**它把整个 pipeline 公开了**，是少数能看清每一步在干什么的训练数据工程。

```
原始语料
├── 原生文字 2,601B token    ← 22 种语言直接从网页/书籍采集
└── 罗马化文本 224.6B token  ← 用拉丁字母拼写的印度语（网络口语常见）
        ↓
翻译增强
  用 Gemma-4-31B-it 把高质量英语内容翻成目标语言
  （低资源语言的主要扩量手段：拿强模型造数据）
        ↓
质量闸门
  MQM 评分（Multidimensional Quality Metrics，多维质量指标）
  ≥ 75 / 100 才保留，低于直接淘汰
        ↓
修复循环
  不合格样本回炉重做，回收 438.4B token
        ↓
最终 2.8T token 训练集
```

**三个可以直接拿去讲的点**：

1. **MQM ≥ 75 这个门槛，就是「什么叫好样本」的可操作定义。** 不是「我觉得这条还行」，是一个 100 分制、有明确维度的评分，且设了阈值。任何数据质量项目都需要这么一条线。
2. **修复循环回收了 438.4B token，约占总量的 15%。** 这说明「一次性过滤 + 丢弃」是浪费的——二次加工比直接扔划算。**15% 这个回收率在面试里可以直接当数字用**，比说「我们做了数据清洗」有力得多。
3. **pipeline 是开源的（NeMo Data Designer）。** 意味着他不用看别人的 PPT，可以自己跑一个小规模版本。

**建议动作**：把这个思路套到中文场景做一个小 demo——比如「广告投放客服对话」或「商品评论文本」，做「规则初筛 → LLM 打分 → 阈值过滤 → 低分样本修复 → 配比采样」五步，产出前后两版数据集，用一个小模型训练对比下游指标。

这比再加一个 RAG 项目的价值高得多，因为**它就是他目标岗位的工作内容本身**，而 RAG 项目已经是红海。

### 8.4 六条数据渠道：个人只能切进两条

| 渠道 | 2026 年的状态 | 门槛 |
|---|---|---|
| 网页爬取 | 增量红利消失；11.4% 顶级站点已屏蔽 | 法务 + 反爬对抗，小团队做不了 |
| 授权采购 | Reddit / Stack Overflow / 出版社多已签独家 | 资本密集 |
| **专家众包** | 81 亿美元市场，$55–101 / 小时 | **对个人开放的唯一入口** |
| 企业档案购买 | 医疗、法律、金融 | 需行业关系 |
| **合成数据 + 评估** | 增长最快，但有坍缩风险 | **需要评估方法论** |
| 自有用户数据 | 大厂专属 | 无 |

**结论**：个人和小团队能切进去的只有「专家众包」和「合成数据 + 评估」两条。

第一条要**领域权威**（医学博士、执业律师），他切不进去。第二条要**评估能力**——而这正好是他有证据的部分。

所以他的定位应该说得更窄更准：**不是「我会做数据清洗」，而是「我能给数据定质量标准，并用下游指标证明它有效」。**

### 8.5 岗位能力要求在换口径

```
旧口径（数据开发）：会 SQL、会 Spark、能把表建对、任务不挂
新口径（训练数据工程）：能定义样本标准、能设计过滤与配比策略、
                        能用下游指标证明这套策略让模型变好了
```

差别全在最后半句：**证明**。

- 前者交付的是**表和任务**
- 后者交付的是**一个可复现的、指标更好的数据集**

这也解释了为什么这个岗位薪资高于普通数据开发——它不是执行岗，是**带决策的工程岗**：决定哪些数据进、哪些不进，直接影响模型能力上限。

## 九、五条正在发生的主线

单条新闻会过期，主线不会。**面试要说的也是这五条，不是报菜名。**

### 9.1 前沿模型从「发布即全量」变成「分阶段开门」

Argon 只给安全防御者，Astra 被撤下，输出加水印。

**含义**：能力不再是唯一变量，**可用性也是**。选型要问「我能不能稳定拿到」，不只问「它强不强」。

### 9.2 单价在降，总账单在涨

Gartner 预测 agent 成本 5 年内 5 倍以上。

**含义**：成本优化的顺序不能反——先减无效 token，再谈换模型。换模型是最后一步，也是最容易做错的一步。

### 9.3 开源出现分叉，且竞争维度从「能力」转向「任务成本」

中国：开源 + 场景 + 国产算力栈（昇腾）
美国：闭源前沿 + 分阶段发放
Meta：双线（闭源 Wonder + 开放 Spark）

**含义**：开源不再是「便宜替代品」。Muse Spark Open 816B 已摸到前沿参数规模，阶跃直接用「任务成本 1/8」当卖点。

### 9.4 「任务成本」正在取代「token 单价」成为计价单位

三个证据拼在一起：

```
Sonnet 5.5   单价不变，任务成本 −30%   → 省在 token 数
Haiku 5.5    单价 −75%，但换分词器     → token 数变多，抵消一部分
Step 5       直接说"单任务成本 1/8"    → 不用单价做口径
```

**含义**：价目表已经不能用来比较模型。**必须跑自己的任务集。** 这一条是 21 篇「建 eval set」的行业级证据。

### 9.5 训练数据从「清洗」升级为「构造 + 评估」

三个证据：

```
科技日报    通用网页数据红利吃完，专业数据不足，低质合成 → 模型坍缩
NVIDIA      2.8T token 语料，MQM 评分卡 75 分，修复循环回收 15%
Scale AI    10 亿美元做医疗垂类数据
```

**含义**：数据供给从「找得到就行」变成「要设计、要评分、要证明」。**这条主线直接决定他该补什么技能。** 前面四条是行业观察，这一条是行动指令。

## 十二、被问「最近 AI 有什么变化」怎么答

这道题在 AI 相关岗位面试里出现频率很高，而且**是送分题也是送命题**——答得好显得你真在跟；答成报菜名，立刻暴露「只看标题」。

### 12.1 30 秒版（结论 + 数字 + 对岗位的含义）

> 「这半年最大的变化不是模型变强，是变便宜。OpenAI 的 GPT-6.1 Sol 用旗舰五分之一的价格拿到了接近旗舰的能力，DeepSeek V4.1-Flash 输入价已经到每百万 token 0.15 美元。
>
> 对数据工程的意义是：以前因为成本不敢做的批量调用——比如每天全量打标、逐条生成解释——现在可以放进日常链路了。但另一面是，Agent 类应用的总成本反而在涨，Gartner 预测到 2028 年单个 agent 工作流的推理成本会涨 5 倍以上，因为多轮和长上下文把 token 消耗量拉上去了。所以成本优化的重点在减少无效 token，不在换便宜模型。」

**为什么这个答法有效**：有结论（变便宜）、有数字（1/5、$0.15、5 倍）、有转折（但总账单在涨）、落到自己的岗位（数据工程的批量调用）。

### 12.2 追问「你还关注哪些方向」→ 说三条，且三条要同源

不要说「我还关注多模态、具身智能、AI4S」——这是报兴趣，不是有观点。**三条要指向同一个判断**，才有说服力：

1. **前沿模型的发布策略从「全量」变成「分阶段开门」**——Argon 只给审核过的安全防御者，说明可用性也是选型维度
2. **开源和闭源的分叉**——中国走开源 + 场景 + 国产算力栈，美国走闭源前沿，Meta 用双线
3. **计价单位从「token 单价」变成「任务成本」**——三家做法不同但指向一致，说明价目表已经不能用来比较模型了

**这三条的共同点**：都在说「以前能用的判断标准，现在不能用了」。这才是观点。如果换成「关注多模态、具身智能、AI4S」，那是三个并列的名词，没有判断。

> 如果面的是训练数据岗，别用这三条，用 12.5 里那条数据主线。

### 12.3 三个陷阱

| 陷阱 | 为什么错 | 改成 |
|---|---|---|
| 「XX 是最强模型」 | 榜单随时变，且和你的任务无关 | 「在我的任务上 XX 够用，且比 YY 便宜一个数量级」 |
| 说传闻（融资、上市、内部消息） | 说错一次，可信度全没 | 只说能追溯到官方发布页的 |
| 只讲模型不讲业务 | 显得只会看新闻 | 每条都落到「对我的项目/成本/选型意味着什么」 |

### 12.4 一个能加分的反问

> 「贵司现在的模型调用成本，是按 token 单价核算，还是按单任务成本核算？」

这个问题能直接暴露你有没有真做过——**只有真算过账的人才知道这两者会差很多**。

### 12.5 如果岗位是训练数据方向，答这一版

上面 12.1 那版是从「成本」切入的，通用。但他要投的是训练数据工程，**应该从「数据」切入**，成本那段降为佐证。

> 「我这半年最关注的是数据侧的变化。
>
> 第一，免费数据在关窗。Common Crawl 最新快照 21.7 亿页里，已经有 11.4% 的顶级站点屏蔽了 AI 爬虫，通用网页数据的增量红利基本吃完。
>
> 第二，合成数据不是随便造。如果不筛选地自我喂养，几代之后模型会坍缩——不是变傻，是变平庸。所以现在真正在做的事是「可控合成」：真实数据锚定、配比控制、逐条评分过滤。
>
> 第三，这块已经有可复现的工程范例了。NVIDIA 和 AI4Bharat 十月开放的 Indic 语料，2.8 万亿 token、22 种语言，pipeline 是全开的：用 Gemma 做翻译增强，用 MQM 多维质量评分卡 75 分门槛，不合格的回炉重做，最后回收了 438 亿 token，大概占总量的 15%。
>
> 我的理解是，这个岗位的关键不是会不会洗数据，是能不能定义「什么叫一条好样本」，并且用下游指标证明这个定义是对的。我自己论文里做的就是多模型对比加 SHAP 解释加 AUC 评估，方法论是相通的，只是从评估模型换成评估数据集。」

**为什么这版更强**：

| 特征 | 效果 |
|---|---|
| 三个数字（11.4% / 75 分 / 438 亿） | 三个不同层级：行业趋势、质量门槛、工程回收率 |
| 有具体机构名（AI4Bharat、MQM、Gemma） | 证明不是看标题，是真读过 pipeline |
| 落在方法论而不是工具 | 工具会换，方法论不会 |
| 主动连到自己的论文 | 把「没做过数据工程」这个短板，转成「有评估方法论」这个长板 |

**注意不要说**：「我做过训练数据工程」。他没做过。说「我论文里做的评估方法论和这个是同构的」——这是真的，也经得起追问。

## 十三、维护备忘

| 什么时候 | 做什么 |
|---|---|
| 每次聊到新东西 | 先判断四问，中了就写进对应桶，一条 30 秒 |
| 每月初 | 删掉被覆盖的行（模型淘汰、价格作废）；把「待核实」里已确认的移进正文 |
| 每季度 | 整篇压缩；把结构性判断搬进 21 篇，搬完在这里留一行「已沉淀」 |
| 21 篇 | **不轻易动**。只有当主线判断本身变了（比如「美国定义天花板」不再成立）才改 |

**这一篇的价值不在「记了多少条」，在于三个月后你还能一眼看出「现在该用什么、为什么」。** 如果做不到这一点，说明记的方式不对——多半是把新闻稿搬进来了，而不是提炼出了实质。
