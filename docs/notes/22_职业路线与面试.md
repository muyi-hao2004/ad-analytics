# 职业路线与面试

> **本篇覆盖**：模型/AI 岗位的分类与边界、MLOps 的职责、训练与推理的本质区别、三个对口方向的对比与路线图、求职话术与红线、港城莞 Data Science AI 面试的完整准备（形式解读、60 秒结构、自我介绍、16 题素材、实战技巧）、**求职线与申请线的口径差异**。
>
> 最后一条最关键：中文简历和英文 CV/PS 是两套口径，答面试题时**不能混用**。

## 一、先把「模型」这个词拆开

**模型 = 一切从数据学规律、做预测的东西。** 豆包 / ChatGPT 只是其中一类。

```
模型
├── 传统机器学习：LR / 随机森林 / XGBoost
├── 深度学习：CNN / LSTM / Transformer
└── 大语言模型（LLM）：GPT / DeepSeek / Qwen / Kimi
```

| | 中小型模型（XGBoost 等） | 大语言模型 |
|---|---|---|
| 谁训练 | 自己 / 公司训练 | 大厂训好，你调 API |
| 需要 MLOps 吗 | ✅ 需要 | ❌ 基本不用 |
| 对应方向 | **MLOps** | **RAG / AI 工程化** |

## 二、AI 团队里的三种角色

```
① 数据工程师     → 造数据管道、建数仓、出特征（管「数据从哪来、怎么存」）
        ↓ 产出特征
② 算法/ML 工程师 → 训练模型、调效果（管「模型准不准」）
        ↓ 产出模型
③ MLOps 工程师   → 部署、上线、监控（管「模型稳不稳定」）
```

**关键区分：「包含」≠「负责」。**

- MLOps 流水线里**有**「训练」环节，但 MLOps 工程师**不做**训练（那是算法工程师的活）。
- 类比：Airflow 管「清洗函数何时跑」，但 Airflow 不写清洗逻辑。

---

## 三、MLOps 是什么

**MLOps = ML + Ops，把「模型开发 → 训练 → 部署 → 监控」做成自动化、可复现、可追踪的流水线。**

### 3.1 解决的四个痛点

| 痛点 | 现象 | 解法 |
|---|---|---|
| 环境不一致 | 我电脑能跑，线上崩 | 容器化（Docker） |
| 模型版本混乱 | 不知道线上是哪个版本 | 模型注册表 |
| 效果退化没人知道 | 模型慢慢变差 | 模型监控 |
| 训练/推理特征不一致 | 线上线下口径不同 | 特征存储 |

### 3.2 完整职责

```
【训练侧】搭训练流水线（Airflow）、管数据特征、管模型版本、管实验
【上线侧】部署（打包 API + Docker）、上线（灰度 / A-B / 回滚）、推理服务、监控
【闭环】  效果变差 → 重新训练 → 重新部署 → 再监控
```

**上线侧是 MLOps 最核心、最体现价值的部分**——把模型从「实验室」变成「产品」。

### 3.3 训练 vs 推理

| | 训练（Training） | 推理（Inference） |
|---|---|---|
| 做什么 | 拿历史数据让模型「学一次」 | 用训练好的模型对新数据预测 |
| 频率 | 偶尔、离线 | 持续、在线 |
| 关注点 | 效果、收敛 | 延迟、吞吐、成本 |

**「模型上线后仍要持续喂数据」是在做推理，不是继续学习。** 模型推理时不会变聪明，变聪明只能靠重训。

### 3.4 特征必须一致

模型只认得「训练时那套规则」下的数据。推理时若口径不同（单位、缺失处理、公式变了），模型看到的是陌生输入，会**静默地变差**——不报错，只是效果下降，这是最难排查的故障之一。

**解法：特征存储（Feature Store）** ——定义一次，训练和推理共用同一套口径。数据工程师「造特征」，MLOps「管特征」。

## 四、三个对口方向

| | 数据工程师（大模型方向） | MLOps / 训练平台 | AI 应用 / 推理服务 |
|---|---|---|---|
| 干什么 | 把原始数据变成高质量训练数据：清洗、去重、构造数据集、质量评估、搭管道 | 搭「让算法一键训练/部署」的平台 | 用大模型做产品：RAG、Agent、推理优化 |
| 技能 | Spark/Flink + Python/SQL + 清洗 + Airflow | Python + Web 后端 + Docker/K8s + 分布式 + 懂模型 | Python/FastAPI + RAG + 向量库 + Prompt |
| 门槛 | 中 | **中高** | 低 |
| 竞争 | 中 | 中（稀缺） | **大** |
| 定位 | **现在** | **读研后** | 副线 |

**MLOps 不必从零造轮子**，主要是用 Kubeflow / MLflow / K8s 组装定制。门槛最高、最稀缺、最值钱。

**AI 应用门槛最低、上手最快，但竞争最激烈**，不适合当唯一主线。

## 五、职业路线图

```
现在（求职）：数据工程师              ← 已经够得着
   ↓ 工作 10 个月 + 读研
升级：MLOps / 训练平台                ← 补 Docker/K8s/云平台 + 训练平台经验
   ↓ 并行
副线：AI 应用 / RAG                   ← 有一个能讲透的最小 demo
   ↓ 毕业后
定位：AI 数据工程 / MLOps 工程师      ← 数据工程底子 + AI 深度
```

**一句话：数据工程师是「现在时」，MLOps 是「将来时」，是一条路上的两个阶段，不是二选一。**

### 心态校准：关于「进大模型厂」

- **「训练大模型」（算法研究）**：博士起步、顶会论文，机会极小——**不是这条赛道**
- **「支撑大模型」（数据 / 工程 / 平台 / 应用）**：岗位数量是前者的几十倍，硕士完全够
- 趋势：**模型越成熟，越缺「工程化和落地」的人**，纯算法的稀缺性反而在下降

## 六、求职线：话术与红线

### 6.1 简历口径（中文，投数据工程/数据开发岗）

| 项 | 处理 |
|---|---|
| GPA | **不写**（3.1/4.5 偏弱，会先被筛掉） |
| 雅思 | **不写**（会被怀疑要出国） |
| 身份 | 已毕业（2026.07），投正式全职岗，不写「大四/实习」 |
| 项目 | 标注「个人项目」+ GitHub 地址 |
| 技术栈 | 不写「熟悉/了解/会用」等程度词，只列名词 |

### 6.2 实习表述的边界

| 经历 | 能说的 | 不能说的 |
|---|---|---|
| 哇哇鱼（IAA 投放数据） | 参与分析、评估 Agent、为 AI 团队准备训练数据 | 「主导开发 Agent」 |
| 金舟（数据清洗） | 用 Python + SQL 做清洗、出日报 | 夸大业务复杂度 |

**原则**：写「参与」不写「负责」，写具体动作不写抽象成果。

### 6.3 给 HR 的开场话术结构

```
① 身份：深大数学 2026 届，数据工程方向
② 一句话能力：Python/SQL/数仓建模 + 一个可讲的完整项目
③ 一个硬证据：GitHub 项目 / 论文 / 实习
④ 明确诉求：想找数据开发/数据工程岗，附简历
```

不写技术细节堆砌，HR 看不懂；但也不能完全不写，否则像群发。

### 6.4 招聘渠道识别（重要）

| 现象 | 判断 |
|---|---|
| 猎头说「华为 OD」 | OD 是外包岗位，与华为正编不同体系，考核和晋升独立 |
| 要求先刷算法题 | 正常，OD/外包常考算法；正编数据岗更看重 SQL + 项目 |
| 面试前索要身份证 | **警惕**。正规流程在发 offer 后才做背调 |

### 6.5 求职线红线

- ❌ 说「完全自己写的代码」
- ❌ 把学过的技术说成项目用过的（Parquet、Kafka、Flink）
- ❌ 虚构实习内容
- ✅ 说「AI 辅助，但设计和口径是我定的，每个模块能讲清」

### 7.1 面试形式

- 线上 AI 面试：机器出题 → 摄像头录像作答，**全英文**
- 两周内自选时间完成，**整个申请季最多 3 次机会**
- 题型：1 分钟自我介绍 + 行为题，每题 60 秒

### 7.2 评分看三点

1. **英语流利度与清晰度**（比内容完美更重要）
2. **逻辑结构**（有没有框架）
3. **与申请材料的一致性**（要和 CV/PS 对得上）

**核心策略：不求惊艳，求稳。** 每题用固定结构答满 40-50 秒，语速中等，别背得太僵。

### 7.3 60 秒万能结构

```
[0-8s]   Direct answer  — 直接给结论
[8-40s]  Story/Reason   — 一个具体例子（STAR 简版）
[40-55s] Result/Lesson  — 结果 + 学到什么
[55-60s] Tie back       — 拉回「为什么适合这个项目」（可选）
```

**宁可少说，不要超时；宁可简单句，不要复杂句卡壳。**

### 7.5 16 题素材库

> 每题按「题目 → 素材 → 核心表达」组织。素材全部来自真实经历，不要临时编。

#### A 类：团队 / 领导力 / 冲突（最高频）

**Q1 团队合作遇到困难怎么解决？**
素材：CUMCM 省二，动态规划 vs 启发式算法的分歧。
> We had a disagreement: I wanted dynamic programming, a teammate suggested a simpler heuristic because of the deadline. Instead of arguing, I proposed we test both on sample data. Mine gave higher profit but took longer; his was faster but less accurate. So we combined them — his method for quick screening, mine for the final solution. We won the Second Prize.
> **Lesson**：the goal is not to win the argument, but to let data decide.

**Q2 怎么做好团队领导？**
素材：建模队里按优势分工。
> Leadership is about making everyone's strength visible. I was responsible for model building, but I noticed a teammate was good at writing, so I asked her to lead the paper while I focused on models. When someone is stuck, I ask questions instead of giving answers — "what if we simplify the assumption first?"
> **Lesson**：clear division, trust, help people grow.

**Q3 怎么对待批评？**
素材：实习时导师指出渠道流量结构差异。
> My supervisor pointed out that my metric comparison ignored the traffic composition difference between channels — my conclusion looked right but was actually misleading. At first I felt defensive, but I checked the data and he was right. I redid the analysis with proper segmentation.
> **Lesson**：separate emotion from content, verify facts. Criticism on data work is quality control.

#### B 类：压力 / 困难 / 突发（第二高频）

**Q4 压力下怎么开展工作？**
素材：毕业论文 + 论文投稿 + 实习申请三线并行。
> I was writing my graduation thesis on Riemann sum convergence while preparing my ML paper submission at the same time. My method: list all tasks and rank by deadline and importance; break big tasks into daily goals; protect fixed working hours and avoid multitasking. Both finished on time.
> **Lesson**：pressure is manageable when it is converted into a schedule.

**Q5 项目中遇到的困难？**
素材：破产预测数据极度不平衡（<4%）。
> The dataset was extremely imbalanced — bankrupt firms were less than 4%. A naive model could reach high accuracy but was useless, because it just predicted "no bankruptcy" for everyone. I changed the evaluation system to AUC, precision, recall and F1 instead of accuracy, applied SMOTE, and used a stratified split to keep the test set honest. Final XGBoost reached AUC 0.97.
> **Lesson**：defining the right evaluation is often more important than the model itself.

**Q6 突发情况怎么处理？**
素材：数模比赛前一天发现适应度函数写错。
> One day before the deadline, we found our genetic algorithm had an incorrect fitness function and results were wrong. I stayed calm and did three things: isolate the problem quickly, fix the core while keeping the correct parts, and simplify some extended scenarios to protect the deadline. We submitted on time.
> **Lesson**：stabilize first, then fix, never let panic consume remaining time.

#### C 类：学术 / 专业兴趣

**Q7 常用的数学方法或工具？**
> Most used: Python and SQL. In Python, Pandas for cleaning, scikit-learn and XGBoost for modeling. For statistics, hypothesis testing and regression — in my paper I used stratified sampling and compared models with AUC and F1. For interpretation, SHAP. My math foundation in probability, statistics and modeling helps me understand **why** a method works, not just how to call a library.

> Three things. A solid math foundation supporting quantitative courses. Real experience — industry data analysis plus a published ML paper, contributing practical perspectives to group projects. An AI-application perspective — I built a RAG-based analytics agent and would like to exchange ideas on how LLMs change data workflows.

**Q10 过去学术经历怎么安排的？**
> A clear logic: build the math foundation first (analysis, probability, statistics), then apply it (math modeling contests in 2024), then go deeper (two papers — one in pure math on Newton-Leibniz formula in split complex numbers, one in ML on financial distress prediction), finally connect to practice (internship and the analytics platform).

### 7.6 AI 面试实战技巧

1. **设备与环境**：摄像头平视（电脑垫高）、安静房间、浅色背景、面光在脸前方
2. **开口前 2 秒**：深呼吸、微笑，第一句最影响印象
3. **语速**：比平时慢 10%，卡壳时说 "well, let me put it this way" 过渡
4. **眼神**：看**摄像头**，不是看屏幕里的自己
5. **听到题先在心里定好例子**，别边说边想
6. **没听懂**：礼貌说 "Sorry, could you please repeat the question?"，比答偏强一百倍
7. **练法**：每题每天朗读 2 遍，再手机录像自答（不看稿），回放查语速和填充词
8. **正式作答时间**：安排在面辅后 3-5 天（状态最熟时），别拖到截止前

## 八、两条线不能混（最容易出错的地方）

| 项 | 求职线（中文简历） | 申请线（英文 CV / PS） |
|---|---|---|
| GPA | **不写** | **写 3.1/4.5** |
| 雅思 6.5 | **不写** | 写 |
| 身份 | 已毕业，投全职 | 应届申请人 |
| 项目定位 | 「个人项目」+ GitHub | "personal learning project, simulated data, AI-assisted" |
| 实习表述 | 「参与分析」 | 可写 "supported AI team with training data preparation" |
| 出口 | 数据工程 / 数据开发岗 | MSc Data Science |

**为什么必须分开**：求职时 GPA 和雅思是减分项且暗示「要出国」；申请时 GPA 是必填项且低分要靠其他材料补。同一份材料不可能同时服务两个目标。

## 九、面试速查

- **模型和 LLM 什么关系？** → LLM 只是模型家族的一个分支，模型是泛指一切从数据学规律的东西。
- **MLOps 和算法工程师的分界？** → MLOps 管平台和上线，不管训练效果。
- **训练和推理的区别？** → 训练学一次，推理每次用；上线后喂数据是推理，不是学习。
- **特征为什么要一致？** → 口径变了模型看到陌生输入，会静默变差。
- **三个方向怎么选？** → 数据工程是现在，MLOps 是读研后，AI 应用是副线。
- **进大模型厂做什么？** → 做数据和工程，不做训练模型。
- **AI 面试评分看什么？** → 流利度 > 逻辑 > 材料一致性，内容完美排最后。
- **60 秒怎么组织？** → 结论 8 秒 + 例子 32 秒 + 收获 15 秒。
- **被问「项目是 AI 写的吗」？** → 承认 AI 辅助，强调设计、口径、流程是自己定的。
- **求职和申请材料能共用吗？** → 不能，GPA/雅思/项目表述三处口径相反。
